# v5.6E.2 — Smart Buyer Lead Text Understanding

**Status:** Staging MVP (deterministic parser; AI fallback prepared but OFF)

## Problem (manual smoke)

User reply after lead CTA:

> ชื่อ ดล จัดไฟแนนซ์ เสนอราคา 4 แสน ติดต่อได้ตลอดเวลา

Legacy parser often:
- Captured **entire tail** as display name after `ชื่อ`
- Missed contact phrases like **ติดต่อได้ตลอดเวลา** (required `ช่วง/เวลา` in pattern)
- Felt like “fill by label only” chatbot UX

## Solution

### 1. Deterministic natural-language parser

File: `src/services/leads/buyerLeadTextParser.ts`

- Single-line Thai messages
- Name: `ชื่อ ดล`, `ชื่อเอ`, leading name before finance/cash verbs
- Purchase method: เงินสด / จัดไฟแนนซ์ / ผ่อนไฟแนนซ์ / ไฟแนนซ์ / ยังไม่แน่ใจ
- Prices: `4 แสน`, `480,000`, `1.2 ล้าน`, `3 แสนห้า` → 350000
- Contact window phrases: ติดต่อได้ตลอดเวลา, หลังห้าโมง, ช่วงเย็น, เวลาทำงาน, เสาร์อาทิตย์

Structured output (`BuyerLeadTextParseResult`):

- `displayName`, `purchaseMethod`, `budgetMin/Max`, `offeredPrice`, `preferredContactWindow`
- `missingFields[]`
- `confidence` (0–1, 4 core fields × 0.25)

Integrated via `mergeNaturalBuyerLeadText()` inside `mergeBuyerLeadFieldsFromMessage()`.

### 2. UX: ask only what’s missing

- `buildBuyerLeadCollectingPrompt(missing, { compact: true })` when partial fields already parsed
- Active lead capture still routed before search/orchestrator (`shouldRunBuyerLeadCaptureTurn`)

### 3. AI fallback (prepared, default OFF)

File: `src/services/leads/buyerLeadAiParseFallback.ts`

- `BUYER_LEAD_AI_TEXT_PARSE_ENABLED = false`
- `tryAiParseBuyerLeadText()` returns `null` — **no Gemini/API calls** in this release
- Future guard: only if enabled AND confidence < 0.75 AND fields still missing

## Unchanged guardrails

- Phone **not** collected in chat; modal + consent still required every submit
- No payment / admin settlement / full seller reveal
- No Firestore rules / migration / env changes
