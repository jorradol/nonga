## 3) Root cause of `ai_first_disabled`

### 3.1 Where the gate is produced

Root cause is generated in `src/services/ai/salesBrainUserVisibleGate.ts`:

- `evaluateUserVisibleGate()` -> `checkUserVisiblePrerequisites()`
- when `NONGA_AI_FIRST_ENABLED` is not truthy, function returns `blockedReason = "ai_first_disabled"`
- this happens before provider dispatch

### 3.2 How it propagates into v13.15 output

Path that produced v13.15 evidence:

1. `/api/ai/chat-user-visible-orchestrate` enters `handleChatUserVisibleOrchestratePost()`
2. bridge runs `maybeApplyUserVisibleRealProvider()`
3. eligibility calls `evaluateUserVisibleRealProviderEligibility()`
4. this calls `evaluateUserVisibleGate()`
5. blocked reason `ai_first_disabled` is mapped as `realProviderGateReason`
6. function returns no dispatch:
   - `realProviderNetwork=false`
   - `skipGemini=true`
   - `fallbackToLegacy=true`

### 3.3 Expected behavior or bug

Conclusion: expected behavior, not a bug.

- owner-only v13.12 gate can be open
- but user-visible prerequisite gate still fail-closed if AI-first is off
- therefore provider dispatch is intentionally blocked and fallback path is used
