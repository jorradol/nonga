## 1. Prompt architecture (v6.8E patch)

| Component | File | Role |
|-----------|------|------|
| Combined prompt | `salesBrainUserVisibleRealProvider.ts` → `buildUserVisibleGeminiCombinedPrompt` | system instruction + listing context + user message |
| Listing context | `formatListingContextForPrompt` | brand, model, year, price, mileage, fuel, body class, description |
| Quality slice | `USER_VISIBLE_BUYER_PROMPT_QUALITY_SLICE_ID` = `v6.8E.3` | prompt quality marker |
| Vehicle English allowlist | `extractVehicleEnglishAllowlistFromPilotOrchestration`, `stripAllowedVehicleEnglishForThaiCheck` | allow brand/model/tech tokens |
| Persona guard | prompt + `hasGuessedCustomerAddressTerm`, `hasForbiddenBrandVoiceTerm` | น้องเอ Thai voice, no guessed ลุง/ป้า |
| Two-layer knowledge | prompt markers + general insight disclaimer | listing facts vs model knowledge |
| Output recovery | compact prompt contract + `buildUserVisibleGeminiRetryPrompt` (max 1 retry) | too_short / non_thai_output only |
| Unsafe diagnostics | `logUserVisibleOutputUnsafeDiagnostics` — server log only, redacted | `outputUnsafeReason` enum + `retryAttempt` |
| Follow-up intent | `isPilotBuyerCardInsightFollowUp` in `chatPilotBuyerFollowUp.ts` | summarize/fit with session cards |
| Bridge routing | `preferPilotSessionFirst` in orchestration bridge | skip legacy BUYER_ASK_SELECT when session cards exist |
| Generation | `USER_VISIBLE_REAL_PROVIDER_MAX_OUTPUT_TOKENS` = `768` | user-visible real provider only |
| Mock fallback | `salesBrainUserVisibleChatPath.ts` | unchanged when real provider blocked/fails |

**Car card fields sent to Gemini:** `index`, `brand`, `model`, `year`, `price`, `mileage`, `fuelType`, `bodyClassLabel`, `description` (from `PilotGroundedCarCard`).

## 2. Quality rules added (v6.8E)

### Grounding
- อ้างอิงได้เฉพาะข้อมูล listing ที่ส่งใน prompt
- ถ้าข้อมูลไม่มี → ตอบว่า "ยังไม่มีข้อมูลนี้ในระบบ"
- ห้ามแต่งราคา/ปี/รุ่น/ไมล์/โปรโมชัน/สภาพที่ไม่มีใน listing

### Multi-card variety
- แต่ละคันต้องมีคำอธิบายต่างกันตามข้อมูลจริง
- ห้ามใช้ประโยคซ้ำแข็งทุกคัน

### Finance safety
- ห้าม: อนุมัติแน่นอน, การันตี, ผ่อนได้แน่นอน, ผ่านชัวร์, รับประกันอนุมัติ
- ใช้: ประเมินเบื้องต้น, ขึ้นอยู่กับเงื่อนไขไฟแนนซ์, ทีมงานช่วยประสานรายละเอียด

### CTA
- ชวนฝากชื่อ/เบอร์ให้ทีมงานติดต่อกลับแบบนุ่มนวล
- ห้ามรับปากแทน dealer

## 4. Manual quality smoke scenarios (allowlisted buyer)

### 4.1 Budget search
**Input:** `งบ 4 แสน มีรถอะไรน่าเล่น`

| Check | Pass criteria |
|-------|---------------|
| Grounding | แนะนำเฉพาะรถจาก car cards ที่แสดง |
| No hallucination | ไม่แต่งราคา/ปี/รุ่น/ไมล์/โปรโมชัน |
| Variety | แต่ละคันมีคำอธิบายต่างกัน |
| CTA | มีชวนฝากชื่อ/เบอร์แบบนุ่มนวล |
| Diagnostics | `realProviderNetwork=true`, `realProviderGateReason=real_provider_call_ok` |

### 4.2 Finance question
**Input:** `ผ่อนประมาณเท่าไหร่ได้ไหม` (หลังมี car cards)

| Check | Pass criteria |
|-------|---------------|
| No guarantee words | ไม่มี อนุมัติแน่นอน / การันตี / ผ่อนได้แน่นอน / ผ่านชัวร์ |
| Safe language | ใช้ ประเมินเบื้องต้น / ขึ้นอยู่กับเงื่อนไขไฟแนนซ์ |
| No dealer promise | ไม่รับปากแทน dealer |

### 4.3 Compare two cars
**Input:** `เทียบคันที่ 1 กับ 2`

| Check | Pass criteria |
|-------|---------------|
| Data-only compare | เทียบจากข้อมูลที่มีในการ์ด |
| Missing data | บอกไม่มีข้อมูลพอถ้าช่องว่าง |
| No overclaim | ไม่สรุปเหนือข้อมูลจริง |

### 4.4 Summarize card
**Input:** `สรุปจุดดึงของคันนี้` (หลังเลือกคัน)

| Check | Pass criteria |
|-------|---------------|
| Listing-grounded | อ้างอิงข้อมูลจากการ์ด |
| Natural tone | น้ำเสียงสุภาพ เป็นผู้ช่วยขาย |
| No exaggeration | ไม่พูดเกินจริง |

### 4.5 เหมาะกับใคร
**Input:** `คันนี้เหมาะกับใคร`

| Check | Pass criteria |
|-------|---------------|
| Grounded inference | อิงประเภทรถ/ปี/ไมล์/ราคาที่มี |
| Missing fields | บอก "ยังไม่มีข้อมูลนี้ในระบบ" เมื่อจำเป็น |
| Disclaimer tone | ไม่ฟันธงแทน dealer |
