**Branch:** `feature/chat-image-attachment-v1`

**Test harness:** `npm run test:sim-dealer-import-dry-run`

## 1. Vision & scope

พิสูจน์ว่า simulated Thor partitions (`sim-1thor`, `sim-2thor`, `sim-3thor`) สามารถไหลผ่าน import pipeline เดิมและแยก dealer partition ได้ โดย:

- reuse inventory import / marketplace / draft / access เดิม
- ใช้ fake rows เท่านั้น (masked plate, fake VIN placeholder)
- dry-run แบบ in-memory — **ไม่ persist**, **ไม่ publish**

## 2. Import path audit — dealerId entry points

| Stage | File | รับ dealerId จาก | เรียก `normalizeDealerId` |

| Smart prep | `prepareSmartImport.ts` | `ImportOwnerContext.dealerId` | ไม่โดยตรง — ส่งต่อ owner ไป payload |
| Payload mapping | `mapToMarketplace.ts` | `owner.ownerId/Name/Phone` | ไม่ set `dealerId` ใน payload |
| **Commit partition** | `inventoryImportCommit.ts` | `resolveDealerIdForImport(owner, row)` | **ใช่ — partition boundary หลัก** |
| Published car record | `buildCarRecord()` | `dealerId: resolveDealerIdForImport(...)` | ใช่ |
| Draft record | `buildDraftRecord()` | `dealerId: resolveDealerIdForImport(...)` | ใช่ |

## 3. Flow หลัง v6.6L — sim owner context

```
ImportOwnerContext { dealerId: 'sim-1thor', ownerId: 'owner-sim-1thor', ... }
        │
        ▼
prepareSmartInventoryImport(cleanedRows, owner, rawMap)
        │  payload.ownerId = owner.ownerId (ไม่มี dealerId ใน payload)
        ▼
processSmartInventoryImport({ published, drafts }, owner)
        │
        ▼
resolveDealerIdForImport(owner, row)
        │  owner.dealerId มีค่า → normalizeDealerId('sim-1thor') → 'sim-1thor'
        ▼
buildCarRecord / buildDraftRecord
        │  record.dealerId = 'sim-1thor'
        ▼
bulkAddMarketplaceCars / bulkAddDealerDrafts  (runtime — ยังไม่อนุมัติใน v6.6M)
        │
        ▼
getDealerInventoryCars('sim-1thor') / getDealerDraftsSorted('sim-1thor')
        │  filter: normalizeDealerId(record.dealerId) === normalizeDealerId(query)
        ▼
resolveParentDealerGroup('sim-1thor') → 'Thor Auto'  (business truth — metadata layer)
```

## 4. Partition boundaries

| Boundary | Mechanism |
|----------|-----------|
| **Primary write** | `resolveDealerIdForImport()` → `MarketplaceCarRecord.dealerId` / `DealerDraftRecord.dealerId` |
| **Read filter (cars)** | `getDealerInventoryCars()` → `resolveCarDealerId(c) === dealerId` |
| **Read filter (drafts)** | `getDealerDraftsSorted()` → `normalizeDealerId(d.dealerId) === normalizeDealerId(query)` |
| **API scope** | `dealerAccess.parseDealerRequestScope()` → `normalizeDealerId(x-dealer-id)` |
| **Parent group (metadata)** | `resolveParentDealerGroup()` — ไม่ใช้ partition filter |

## 5. Collapse risk assessment (post v6.6L)

| Input | `normalizeDealerId` output | Collapse risk |
|-------|---------------------------|---------------|
| `sim-1thor` | `sim-1thor` | ✅ ปลอดภัย — early return ก่อน thor collapse |
| `dealer-sim-1thor` | `sim-1thor` | ✅ ปลอดภัย |
| `owner-sim-1thor` | `sim-1thor` | ✅ ปลอดภัย |
| `dealer-thor-auto` | `thor-auto` | ✅ intended |
| `dealer-thor-other` | `thor-auto` | ⚠️ legacy collapse — ไม่กระทบ sim-* |
| `sim-1thor` via `startsWith('dealer-thor')` | N/A | ✅ `dealer-sim-*` ไม่ match prefix `dealer-thor` |

**จุดเสี่ยงที่เหลือ (ไม่ต้องแก้ใน v6.6M):**

- UI default owner ใน `InventoryImportView` ยังใช้ `buildThorAutoOwnerContext()` → `thor-auto` จนกว่า admin จะ override `dealerId` เป็น sim-* (runtime import round)
- `dealerProfile.ts` ยังไม่มี sim profile records (optional ก่อน import จริง)

**สรุป:** ไม่จำเป็นต้องแก้ code เพิ่มใน v6.6M — identity layer v6.6L เพียงพอสำหรับ dry-run
