# v5.6E.5 — Seller Queue Empty State & Target Lead Debug

**Status:** Local fix (awaiting review — no deploy)

## Problems (manual smoke after v5.6E.4)

1. Queue panel box appeared on **every** My Listings card (loading/error chrome).
2. Some cars showed **"ไม่มีสิทธิ์ดูคิวนี้"** for legitimate owners.
3. Buyer lead submitted but not visible on target car after Cloud Run redeploy.

## Root causes

### Panel on every listing

- `MyListingsView` rendered `SellerMaskedLeadQueuePanel` for all owned cars.
- Panel always mounted → loading spinner / error box even when `interestCount = 0`.

### False "ไม่มีสิทธิ์"

- Queue API checked `listing.ownerId === auth.uid` only.
- My Listings access uses `canManageListingWithScope` (dealerId **or** ownerId).
- Dealer / synthetic `owner-{dealerId}` listings got 403 while still visible in My Listings.

### Lead not on target car after submit

- Lead capture binds `listingId = car.id` correctly (verified in tests).
- **In-memory** `buyerLeadRepository` resets on Cloud Run redeploy → leads vanish; `interestCount` on stats may briefly desync.

## Fixes

| Area | Change |
|------|--------|
| `sellerLeadQueueApi` | Stats-first: skip auth queue call when `interestCount = 0` |
| `sellerLeadQueuePanelMessages` | Map owner 403 / empty / sync mismatch copy |
| `SellerMaskedLeadQueuePanel` | Hidden when no leads; small notice for sync mismatch only |
| `buyerLeadQueueRoutes` | Queue GET auth via `canManageListingWithScope` |
| `buyerLeadTargetDebug` | Test helper for listingId/sellerId/queuePosition/interestCount |
