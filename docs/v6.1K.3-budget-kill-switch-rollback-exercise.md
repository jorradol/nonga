## 5. Important Finding — Global Kill Switch Gap

### Summary

หลังตั้ง **`NONGA_AI_EMERGENCY_KILL_SWITCH=true`** บน Cloud Run, **CP-02 ยังเรียก real Gemini** (`providerNetwork:true`, `real_provider_call_ok`) แทนที่จะ block เป็น `providerNetwork:false`

### Root cause (observed in code)

Chat shadow sink scenarios **CP-01** และ **CP-02** ใช้ `stagingStyleShadowEnv()` สำหรับ scenario evaluation ซึ่ง **hardcode**:

```ts
[NONGA_AI_EMERGENCY_KILL_SWITCH_ENV]: "false"
```

ใน `src/services/ai/salesBrainServerShadowSmoke.ts` — function `stagingStyleShadowEnv()`.

`resolveChatShadowSinkHandlerContext` gates real provider on `evaluation.runtimeFlags.shadowEvaluationAllowed` จาก **scenario env** ไม่ใช่ global Cloud Run `process.env` kill switch ดังนั้น global kill switch **ยังไม่ไหลเข้า** CP-02 real provider gate

### What still works

- **CP-03** scenario-local kill (`env` override `EMERGENCY_KILL_SWITCH=true`) — blocks shadow evaluation and real provider
- **Public chat** — unaffected; legacy orchestrator unchanged
- **Rollback flag** (Exercise B) — stops CP-02 real provider immediately

### Risk note

Global emergency kill switch **must be fixed** (recommended slice: **v6.1K.4 Global Kill Switch Fix for Chat Shadow Sink**) before any **v6.1L** user-visible pilot.
