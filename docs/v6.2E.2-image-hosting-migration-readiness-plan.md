## 1. Problem Statement

### 1.1 Current state (post v6.2E.1 / v6.2E.1A)

| Item | Status |
|------|--------|
| Controlled staging pilot | ✅ GO — **10** listings (`pilotBatchId: v62b-real-pilot-001`) |
| Sidebar label | ✅ **รถมาใหม่** |
| Preview area | ✅ ไม่ว่าง/ไม่แตก — **placeholder fallback** |
| Real car photos in browser | ❌ **not displaying** |

### 1.2 Root cause (confirmed v6.2E.1)

| Issue | Detail |
|-------|--------|
| Source | Listing `images[]` stores **external share links** (Google Drive share page format) |
| Browser `<img>` | Share/hotlink URLs **not reliable** — CORS/access/HTML response |
| Client normalize | `uc?export=view` helps format but **still fails** in browser for pilot images |
| Fallback | `onError` → `LISTING_PLACEHOLDER_IMAGE` — UX safe but **not real photos** |

### 1.3 Why this blocks pilot

| Blocker | Impact |
|---------|--------|
| Placeholder ≠ real car | ลุง/allowlisted tester cannot visually verify inventory |
| Compare/search cards | Image grounding UX degraded |
| Pilot feedback loop | Image issue taxonomy stays open (v6.2E) |

**Conclusion:** Controlled pilot **continues** but **image hosting migration** needed before meaningful visual pilot sign-off.

## 2. Candidate Solutions

### 2.1 Option matrix

| Option ID | Approach | Pros | Cons / Risks |
|-----------|----------|------|----------------|
| **OPT-A** | **Firebase Storage migration** | Aligns with existing `listing-images/` + `firebasestorage.googleapis.com` path; stable `<img>` URLs; staging bucket already exists | Requires ops upload script + Firestore field update (separate approval); storage rules review |
| **OPT-B** | **Image proxy / thumbnail endpoint** | Hides Drive from browser; server-side fetch | Needs **backend deploy** + auth/rate limits; secret/env risk; more moving parts |
| **OPT-C** | **Import-time download + upload** | One-time at import; clean public URLs | Retouches import pipeline; re-run on **10** pilot rows needs approval; Drive access from server |
| **OPT-D** | **Manual curated upload** | Lowest automation risk for pilot | Slow; human error; not scalable |
| **OPT-E** | **Keep Drive + client normalize only** | Already tried (v6.2E.1) | ❌ **proven insufficient** for pilot |

### 2.2 Risk comparison (summary)

| Risk | OPT-A Storage | OPT-B Proxy | OPT-C Import-time | OPT-D Manual |
|------|---------------|-------------|-------------------|--------------|
| Production touch | ❌ if staging only | ❌ if staging only | ❌ if staging only | ❌ |
| Secret / env | Low | **High** | Medium | Low |
| Firestore rules change | Maybe read-only public URLs | Maybe | Yes (images[] update) | Yes |
| PII in public URL | Low if path convention | Medium | Low | Low |
| Rollback | ✅ revert `images[]` | ✅ disable proxy | ✅ keep Drive copy ops-only | ✅ |

## 3. Recommended Approach

### 3.1 Primary recommendation: **Firebase Storage (OPT-A)** for pilot images

| Decision | Value |
|----------|-------|
| **Recommended** | Migrate pilot listing images to **Firebase Storage** (`nonga-ce93c` bucket) |
| Scope | **staging only** — `pilotBatchId: v62b-real-pilot-001` — **10** listings |
| Method | Ops-controlled upload script (future slice) — **not in v6.2E.2** |
| Public display | `firebasestorage.googleapis.com` download URLs or approved CDN path |

### 3.2 Storage path convention (proposed)

```
listing-images/{pilotBatchId}/{listingId}/{slotIndex}-{hash}.webp
```

| Segment | Rule |
|---------|------|
| `pilotBatchId` | e.g. `v62b-real-pilot-001` — batch isolation |
| `listingId` | Firestore listing id — **no plate/PII in path** |
| filename | ordinal + content hash — **no plate/phone/LINE** |

Alternate compatible with existing codebase:

```
listing-images/{listingId}/{slotIndex}.webp
```

### 3.3 Original Drive URL handling

| Field | Visibility |
|-------|------------|
| Original Drive share URL | **ops-only** — secure ops channel / migration manifest — **not in git** |
| Public `images[]` after migration | Storage URLs only |
| Public API DTO | **no** raw Drive URLs if avoidable |

### 3.4 Why not proxy (OPT-B) for pilot

- Requires **backend deploy** — out of scope for minimal pilot fix
- Higher secret/env/rules surface
- Storage migration reuses existing `imageStorageRepository` patterns

### 3.5 Execution phasing (future — not v6.2E.2)

| Phase | Action |
|-------|--------|
| E.2.1 | Dry-run manifest — count slots, redacted validation |
| E.2.2 | Staging upload — **10** listings, ops approval |
| E.2.3 | Firestore `images[]` update — separate write approval |
| E.2.4 | Post-migration smoke + optional hosting redeploy if needed |

## 5. Data Model / Readiness

### 5.1 Public image fields (frontend)

| Field | Used by | After migration |
|-------|---------|-----------------|
| `images[]` | API, marketplace, sidebar, chat cards | Storage HTTPS URLs (primary) |
| `imageUrl` / `coverImage` (legacy) | Some mappers | Avoid — prefer `images[]` |
| Display normalization | `normalizeListingImageDisplayUrl` | Pass-through for Storage URLs; Drive normalize fallback until migrated |

### 5.2 Mapping: Drive slots → Storage slots

| Step | Rule |
|------|------|
| M-01 | 1:1 slot order preserved — `images[0]` stays hero |
| M-02 | Max **12** slots per listing (existing sanitize cap) |
| M-03 | Invalid/unmigratable slot → skip or placeholder — **no cross-listing paths** |
| M-04 | Ops manifest maps `listingId` → slot count — **outside repo** |

### 5.3 Fallback behavior

| Condition | Behavior |
|-----------|----------|
| Storage URL valid | Display real image |
| Storage URL broken | `onError` → placeholder (existing) |
| Pre-migration Drive URL | Placeholder (current production behavior) |
| No images | `LISTING_PLACEHOLDER_IMAGE` |

### 5.4 Rollback plan

| Trigger | Rollback |
|---------|----------|
| Bad upload / wrong car image | Restore previous `images[]` from ops backup manifest |
| Privacy leak in image | Hide listing + ops review — **no git** |
| Full rollback | Revert Firestore `images[]` to pre-migration snapshot (ops) — sidebar shows placeholder again |
