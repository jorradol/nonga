## 3) Root cause of `/storage/listings/car-import-...` 404

1. Thor CSV import downloaded Google Drive / remote image URLs via `downloadListingImagesForCar()`.
2. That helper wrote bytes only to local `data/listing-images/` and stored `/storage/listings/{carId}/...` paths in Firestore.
3. Staging Cloud Run health reported `imageBackend: file` because `NONGA_IMAGE_BACKEND` was unset (defaults to file).
4. Cloud Run filesystem is ephemeral and instance-local — after scale/redeploy/cold start on another instance, static `/storage/listings/**` returns **404**.
5. Listing metadata remained durable in Firestore (marketplace/chat PASS), but image bytes did not.

`imageBackend:file` is expected only for local/dev disposable smoke. For Cloud Run staging it is **wrong for durable pilot images**.

## 5) Plate-in-image privacy decision

| Item | Decision |
|------|----------|
| Text/API masking | Remains PASS — public DTO keeps `licensePlateMasked`, strips full plate/VIN/phone |
| Image content | Source photos may still show a full plate visually |
| Policy | `vehicleImagePlatePrivacy` — text masking does **not** cover plates inside images |
| Owner/dealer requirement | Use plate-blurred / plate-safe images before any public-facing or revenue pilot use |
| Import warning | Added on import when images are present without plate-safe attestation |
| Docs/UI | Pilot listing policy, dealer import guide, and import help section updated |

Automated pixel blur is **not** implemented in this slice (would be a larger vision pipeline). Policy + checklist + import warning are the staging-safe gate.
