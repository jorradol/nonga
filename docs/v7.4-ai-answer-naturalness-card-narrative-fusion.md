# v7.4 — AI Answer Naturalness + Car Card Narrative Fusion

Round goal: ทำให้คำตอบของน้องเอ **เป็นธรรมชาติ** แบบผู้ช่วยขายรถมือสองสไตล์ไทย และ
**ผสานคำตอบเข้ากับ car cards** ให้ต่อเนื่อง (ไม่แยกเป็นข้อความก้อนแข็ง ๆ กับการ์ด)
โดยอธิบายเหตุผลว่ารถแต่ละคันเหมาะกับโจทย์อย่างไร — **อิงข้อมูลจริงในระบบเท่านั้น**

Status: local-safe เท่านั้น — ไม่ deploy production/staging, ไม่เปิด public signup,
ไม่เปิด user-visible AI จริง, **ไม่เรียก Gemini จริง** (deterministic ล้วน),
ไม่ส่ง lead เอง, ไม่แตะ lead payload / consent / dealer isolation / privacy / data model

## ขอบเขตที่ลุงเด่นอนุมัติ (default ที่เสนอ)

1. **Fusion:** แนบ `fitReason` ต่อการ์ด + **ตัด pitch ซ้ำออกจาก text wall** (ฟิวชันเต็มที่)
2. **Memory:** ใช้ v7.2 ทำได้แค่ **soft opener (display)** ไม่ผูกเป็น fact ของการ์ดคันใด
3. **Type:** เพิ่ม optional `fitReason` (display-only) ใน `ChatCarCardData` (ไม่ persist, ไม่เข้า payload)

## flow คำตอบ + car cards ปัจจุบัน (ฐานที่ใช้ต่อ — ปลอดภัยอยู่แล้ว)

1. ค้นหา → `chatSearchOrchestrator.ts` → `tryBuyerScoredMarketplaceReply` (`buyerScoredMarketplaceSearch.ts`)
2. narrative (grounded, deterministic) → `buyerCarPitchCopy.ts` (`buildWarmAngle` ฯลฯ)
   มี guard กัน hallucination: `assertBuyerPitchSafe` + `BUYER_PITCH_FORBIDDEN_CLAIM`
   และใน scored search มี `FORBIDDEN_REPLY_CLAIM`
3. ตอบกลับ `{ text, carCards, ... }` แล้ว render: `ChatMessageBubble.tsx` → grid ของ `ChatCarCard.tsx`

ปัญหา UX เดิม: pitch ต่อคันถูกยัดรวมเป็น text ก้อนเดียว **แยกจากการ์ด** → "แข็ง"

## ป้องกัน hallucination / invented car facts

- `fitReason` มาจาก field จริง (ราคา/ปี/ประเภทตัวถัง/reasons) + intent — ไม่แตะ field ที่ไม่มี
- ทุก `fitReason` ผ่าน `assertBuyerPitchSafe` (กัน km/l, ไม่เคยชน/น้ำท่วม, การันตี ฯลฯ)
- soft opener recall เฉพาะคำพูดลูกค้า ไม่ผูกเป็น fact ของการ์ดคันใด
- test ตรวจ `INVENTED_FACT_RE` (เลขไมล์/อัตราสิ้นเปลือง/ประวัติซ่อม/เคลม) ทั้ง text + ทุก fitReason

## memory ไม่กลายเป็น consent

- opener เป็น **display-only** — ไม่เข้า payload, ไม่ตั้ง consent, ไม่ส่ง lead
- `conversationalLeadMemoryHasNoContactOrConsent()` ยังผ่าน
- การส่ง lead ยังต้องผ่าน flow v7.1–v7.3: modal + เบอร์ที่ลูกค้ากรอกเอง + `consentConfirmed`

## ไม่กระทบ lead flow v7.1–v7.3

- ไม่แตะ `buyerLeadCaptureFlow` / `buyerLeadFlowEscape` / `buyerLeadCaptureHandler` /
  preview / consent / queue หลังบ้าน
- v7.4 อยู่ในชั้น search reply + card display เท่านั้น
