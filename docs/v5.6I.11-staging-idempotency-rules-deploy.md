git checkout HEAD -- firestore.rules
rm firestore.rules.rollback-tmp

## 8) Firestore persistence — ยังไม่เปิด

| Flag | ค่า |
|------|-----|
| `NONGA_SUCCESS_FEE_RECORD_ENABLED` | **off** |
| `NONGA_SETTLEMENT_DATA_BACKEND` | **`memory`** |
| `NONGA_SETTLEMENT_FIRESTORE_WRITES_ENABLED` | **off** |

Runtime settlement repo = **in-memory** — revenue API ไม่พึ่ง client Firestore

Rules deploy รอบนี้ **ไม่สร้าง** idempotency docs ใน Firestore และ **ไม่เปิด** Admin SDK writes สำหรับ settlement

## 9) Production hold statement

**ห้าม production deploy** จนกว่า:

- Wire durable idempotency ใน Firestore transaction + multi-instance smoke ผ่าน
- Authenticated admin/seller staging smoke ผ่านครบ
- Finance/admin sign-off
- Payment gateway / invoice ยังไม่เปิด

## 10) Risk ที่เหลือ

| Risk | สถานะ |
|------|--------|
| Firestore repo ยังใช้ in-process `idempotencyCache` | ต้อง wire durable idempotency ใน transaction ก่อน multi-instance ปลอดภัย |
| ยังไม่ wire `settlementIdempotencyRecords` ใน repo | phase ถัดไป (หลัง v5.6I.11) |
| Rules `settlementIdempotencyRecords` บน staging | **deploy แล้ว** (v5.6I.11) |
| Legacy clients ไม่ส่ง `requestId` | server generate `srv-...` ใหม่ทุก request → retry ไม่ idempotent |
| `processing` record cleanup/alert | ต้องทำ scheduled cleanup + ops alert ก่อนเปิด writes จริง |
| Authenticated admin/seller smoke | **pending manual โดยลุง** |
