## 4. Lead intake workflow (admin-assisted, safe flow)

> flow นี้เป็น **admin-assisted**: operator/dealer ที่มีสิทธิ์เป็นผู้ปฏิบัติ agent ไม่ login และไม่อ่าน credential

**Safe flow (ลำดับ):**

1. **Lead เข้ามา** → เข้าสู่ queue ของ dealer ที่มีสิทธิ์ (scoped)
2. **Operator ตรวจ queue** → ดูเฉพาะ queue ที่อยู่ใน scope ของตน
3. **ตรวจ masking** → ยืนยันว่า contact fields ถูก mask ก่อน reveal ที่ถูกสิทธิ์
4. **Dealer scoped access** → dealer เห็นเฉพาะ listing/lead ใน scope ของตนเท่านั้น
5. **บันทึก count/status เท่านั้น** → operator บันทึกลง monitor เป็น count/status แบบ non-PII

**ข้อห้ามใน flow:**

- **ห้ามบันทึก** ชื่อจริงลูกค้า เบอร์โทร อีเมล plate VIN หรือ raw contact ลง repo / docs / tests
- ถ้าจำเป็นต้อง **reveal contact จริง** ต้องเป็น **operator/dealer action ตามสิทธิ์เท่านั้น** และ **ไม่** นำข้อมูลนั้นมาบันทึกในเอกสาร/repo
- **agent ห้าม login** หรืออ่าน credential / session / password / token
- **agent ห้ามสร้าง/แก้ lead จริง** ใน Firestore
- **agent ห้าม reveal** ข้อมูล contact จริง

| Actor | ทำได้ | ทำไม่ได้ |
|-------|-------|----------|
| Operator/admin (มีสิทธิ์) | ตรวจ queue ใน scope, ตรวจ masking, บันทึก count/status | บันทึก PII ลง repo/docs |
| Dealer (มีสิทธิ์) | เห็น listing/lead ใน scope, reveal contact ตามสิทธิ์ | เห็นนอก scope |
| Agent (ผู้ช่วย) | เขียน SOP/skeleton, static validation | login, reveal contact, เขียน Firestore, import Thor |

## 5. Lead monitor fields (non-PII skeleton)

> skeleton สำหรับบันทึกแบบ **count/status เท่านั้น** ทุก field ต้อง **ไม่มี PII** ตัวอย่างด้านล่างใช้ placeholder เท่านั้น ไม่ใช่ข้อมูลจริง

| Field | ชนิด | คำอธิบาย (non-PII) | ตัวอย่าง placeholder |
|-------|------|---------------------|----------------------|
| `date` | date | วันที่ตรวจ | `YYYY-MM-DD` |
| `environment` | label | สภาพแวดล้อม (เช่น staging) | `staging` |
| `dealer_scope_label` | label | label scope แบบไม่ใช่ข้อมูลลับ ไม่ระบุชื่อจริง/ที่อยู่ | `scope-A` |
| `listing_count_checked` | count | จำนวน listing ที่ตรวจ | `0` |
| `lead_rows_observed_count` | count | จำนวน lead rows ที่เห็นใน queue | `0` |
| `masked_rows_count` | count | จำนวน rows ที่ contact ถูก mask | `0` |
| `reveal_attempts_count` | count | จำนวนครั้ง reveal ที่ถูกสิทธิ์ (count เท่านั้น) | `0` |
| `skip_outcome_attempts_count` | count | จำนวน skip/outcome action | `0` |
| `anomalies_count` | count | จำนวน anomaly ที่พบ | `0` |
| `incident_flag` | boolean | พบ incident หรือไม่ | `false` |
| `operator_initials_role` | label | initials/role แบบไม่ระบุตัวตนละเอียด | `op-1 / dealer-role` |
| `notes` | text (no PII) | หมายเหตุแบบไม่มี PII | `no anomaly observed` |

**กฎ field:**

- ทุก field เป็น **count / status / label** เท่านั้น
- `dealer_scope_label` และ `operator_initials_role` ต้อง **ไม่** ระบุชื่อจริง เบอร์ อีเมล หรือข้อมูลลับ
- `notes` ต้อง **ไม่มี** PII / raw contact / plate / VIN / token / secret

| ID | Trigger (no-go) | การกระทำ |
|----|------------------|----------|
| NG-01 | พบ **cross-dealer lead leak** (เห็น lead ของ dealer อื่น) | STOP + escalate |
| NG-02 | พบ **raw PII ก่อน reveal ที่ถูกสิทธิ์** | STOP + escalate |
| NG-03 | พบ **plate / VIN leak** | STOP + escalate |

## 9. Evidence format (non-PII)

operator บันทึก **เฉพาะ** รูปแบบเหล่านี้ — ไม่มี identifier ไม่มี contact data:

| Allowed | Example placeholder |
|---------|---------------------|

| Count (non-identifying) | `lead_rows_observed_count = 0` |
| Boolean observation | `masking = yes` |
| Generic scope label | `dealer_scope_label = scope-A` |

| Forbidden | Reason |
|-----------|--------|
| Buyer phone / email / name | PII |
| License plate / VIN | sensitive vehicle ID |
| Session token / cookie / password | credential |
| Dealer account email/password | credential/PII |
| Raw lead contact text | PII |
