# v5.6C — Buyer Consent Lead Capture MVP

**สถานะ:** MVP — consent + บันทึก buyer lead ใน server memory; ยังไม่ payment / seller inbox เต็ม / reveal เบอร์  
**อ้างอิง:** [v5.6A](./v5.6A-ai-sales-lead-engine-blueprint.md), [v5.6B](./v5.6B-lead-engine-data-model.md)

---

## สิ่งที่ทำในรอบนี้

| รายการ | รายละเอียด |
|--------|-------------|
| Chat flow | ผู้ซื้อพิมพ์ “ขอให้ผู้ขายติดต่อกลับ” → เก็บข้อมูลขั้นต่ำ → consent → บันทึก (ต้อง login) |
| API | `POST /api/buyer-leads`, `GET /api/buyer-leads/:id` |
| Storage | In-memory repository (ไม่แตะ Firestore rules) |
| Masking | ผู้ขาย/คนอื่นไม่เห็นเบอร์เต็ม; ผู้ซื้อและ admin เห็นเต็ม |

---

## ข้อจำกัดการเก็บข้อมูล (staging MVP)

รอบ v5.6C **ยังไม่ใช่ระบบ production-ready** สำหรับลีดจริง:

| ข้อจำกัด | รายละเอียด |
|----------|-------------|
| **Server memory เท่านั้น** | `buyerLeadRepository` เก็บ buyer lead ใน RAM ของ process (in-memory `Map`) — ไม่มีไฟล์หรือ Firestore ในรอบนี้ |
| **Restart / redeploy หาย** | เมื่อ Cloud Run (หรือ `node server`) **restart หรือ redeploy** ข้อมูล lead และ contact log ที่บันทึกไว้ **จะหายทั้งหมด** |
| **หลาย instance** | ถ้า Cloud Run รันหลาย instance พร้อมกัน ลีดที่สร้างอาจอยู่ **คนละ instance** — `GET /api/buyer-leads/:id` อาจได้ 404 ถ้า request ไป pod อื่น |
| **รอบถัดไป** | ต้องทำ **durable persistence** (เช่น Firestore + rules ที่ออกแบบแล้ว) ในเฟสหลัง v5.6C **ก่อน** เปิดใช้งาน lead จริงกับผู้ขาย/production |

สถานะ capture ในแชท (`buyerLeadCaptureFlow`) ก็อยู่ใน memory ของ session — refresh หน้ากลาง flow อาจต้องเริ่มใหม่

## Consent wording

ข้อความหลัก (ก่อนบันทึก):

> ถ้าคุณยืนยัน น้องเอจะส่งข้อมูลติดต่อและความสนใจของคุณให้ผู้ขายรถคันนี้ เพื่อให้ผู้ขายติดต่อกลับเรื่องการซื้อขายรถคันนี้เท่านั้น

ยืนยัน: **“ยืนยันให้ส่งข้อมูล”** (ต้องเข้าสู่ระบบ)

`consentVersion`: `v5.6C-1`

## ข้อมูลที่เก็บ / ห้ามเก็บ

เก็บได้: ชื่อ/ชื่อเล่น, เบอร์, รถที่สนใจ (`listingId` จากรถที่เลือกในแชท), งบ/ราคาเสนอ, วิธีซื้อ, เวลาสะดวก, สรุปจากน้องเอ

## API

### `POST /api/buyer-leads`

- **Auth:** Firebase Bearer บังคับ (guest → 401)
- **Body:** `listingId`, `displayName`, `contactPhone`, `purchaseMethod`, `preferredContactWindow`, `consentConfirmed: true`, `consentVersion: "v5.6C-1"`, optional budget/offer
- **Response:** `PublicBuyerLead` (ผู้ซื้อเห็นเบอร์ตัวเอง; ยังไม่ส่งให้ seller inbox แบบเต็มใน v5.6D)

### `GET /api/buyer-leads/:id`

- Buyer self / admin / listing seller (seller เห็น **masked**)
