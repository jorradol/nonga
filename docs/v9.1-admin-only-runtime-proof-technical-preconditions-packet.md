# v9.1 Admin-Only Runtime Proof Technical Preconditions Packet

> **TECHNICAL PRECONDITIONS PACKET ONLY / DOCS-ONLY / STATIC VALIDATION ONLY**
> เอกสารนี้ระบุเงื่อนไขเชิงเทคนิคก่อนอนุญาตให้แตะ runtime จริงแบบ admin-only ในอนาคตเท่านั้น
> ไม่ใช่ runtime implementation และไม่ใช่การเปิดใช้งานจริง

---

## 1. Purpose

v9.1 จัดทำเพื่อบันทึก **Technical Preconditions Packet** ก่อนจะอนุญาตงานที่แตะ runtime จริงแบบ admin-only ในอนาคต

- ยังไม่เปิด runtime proof จริง
- ยังไม่เปิด Gemini จริง
- ยังไม่แตะ `src/`
- ยังไม่ deploy
- ยังไม่เปิดให้ buyer/user เห็น AI
- no src changes
- no deploy
- no production
- no runtime activation
- no Gemini activation
- no buyer-facing AI
- no user-visible AI
- no real lead sending

## 2. Current Source of Truth

- deterministic flow remains source of truth
- buyer path ต้องใช้ deterministic flow เท่านั้นจนกว่าจะมี owner approval รอบใหม่ในอนาคต
- admin-only runtime proof path (ถ้ามีในอนาคต) ต้องไม่กระทบ buyer/public path

## 3. Admin-Only Boundary Preconditions

ก่อนจะอนุญาตให้ทำ admin-only runtime proof จริงในอนาคต ต้องมี preconditions ดังนี้:

- ต้องมี admin-only route boundary ที่แยกจาก buyer/public path
- ต้องไม่มี public route ที่เรียก AI ได้
- ต้องไม่มี buyer-facing/user-visible AI path
- ต้องมี owner-approved access boundary
- ต้องมี proof-only usage scope
- runtime proof path ในอนาคตต้องเป็น admin-only เท่านั้น

หมายเหตุ: v9.1 เป็นเอกสารเท่านั้น ห้ามสร้าง route จริงในรอบนี้

## 4. Environment Variable Preconditions

ระบุเฉพาะ env var names only (ไม่ใส่ค่าจริง):

- `GEMINI_API_KEY`
- `AI_RUNTIME_PROOF_ENABLED`
- `AI_ADMIN_RUNTIME_PROOF_ONLY`
- `AI_RUNTIME_PROOF_QUOTA_LIMIT`
- `AI_LOG_REDACTION_ENABLED`

ข้อกำหนดยืนยัน:

- env var names only
- no real values
- no secrets in repo
- no API key in repo
- no real secret/API key in repo
- secret ต้องอยู่ใน secure environment เท่านั้น หากมี owner approval ในอนาคต

## 5. Kill Switch Preconditions

- default ต้องเป็น OFF
- ถ้า env ไม่ครบ ต้อง fallback
- ถ้า provider error ต้อง fallback
- ถ้า quota exceed ต้อง fallback
- ถ้าไม่ใช่ admin-only context ต้อง block/fallback
- deterministic fallback ต้องปลอดภัยเสมอ

## 6. Fallback Preconditions

- deterministic fallback ต้องพร้อมก่อน runtime proof จริง
- buyer path ต้องไม่พึ่ง AI
- AI failure ห้ามทำให้ lead/search/chat หลักพัง
- ไม่มีการส่ง lead จริงจาก proof path

## 7. Logging Redaction Preconditions

logging สำหรับ proof ต้องเป็น sanitized/redacted เท่านั้น และต้องไม่เก็บหรือปล่อยข้อมูลต่อไปนี้:

- real secret/API key
- phone number
- plate
- VIN
- buyer PII
- raw prompt ที่มี PII
- raw Gemini response ที่มี PII หรือข้อมูลหลุด
- lead payload จริง

## 8. Quota Cap Preconditions

- runtime proof ต้องมี quota cap ต่ำ
- ต้องเป็น proof-only
- ต้องมี fail-closed หรือ fallback เมื่อเกิน quota
- ห้ามเปิดใช้งานแบบ unlimited
- ห้ามให้ buyer/public path ใช้ quota

## 9. Forbidden Actions in v9.1

- ห้ามแตะ `src/`
- ห้าม deploy
- ห้าม production
- ห้าม runtime activation จริง
- ห้าม Gemini activation จริง
- ห้ามใส่ secret/API key จริงใน repo
- ห้ามเปิด public route
- ห้าม buyer-facing/user-visible AI
- ห้าม real lead sending
- ห้ามเปลี่ยน deterministic flow
- ห้ามเปลี่ยน buyer/dealer/admin runtime behavior
- ห้ามเชื่อมต่อ provider จริง
- ห้ามแก้ Cloud Run / Firebase config เพื่อเปิดใช้งานจริง

## 10. Exit Criteria Before Any Runtime-Touching Work

ก่อนจะเริ่มงานที่แตะ runtime จริงในอนาคต ต้องครบทุกข้อ:

- v9.1 docs approved
- static validation PASS
- owner explicit approval สำหรับ runtime-touching work
- scope แยกชัดว่าแตะไฟล์ไหนได้บ้าง
- rollback/disable plan
- no-secret policy confirmed
- admin-only boundary confirmed
- deterministic fallback confirmed
- logging redaction confirmed
- quota cap confirmed
- no buyer-visible path confirmed
