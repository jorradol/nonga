## 1. Vision & ขอบเขต v6.0A

### เป้าหมาย

วางแผนให้ **น้องเอคุยฉลาดขึ้นและช่วยขายได้จริง** ในทุก flow (buyer / seller / dealer) โดย:

- ใช้ **AI First Evaluation Mode** บน staging/closed pilot — ดูศักยภาพสูงสุดก่อน แล้วค่อย optimize
- ใช้ **Sales Brain** — ช่วยต่อรองในกรอบ, แนะนำทางเลือก, ถามกลับเมื่อข้อมูลไม่พอ, อธิบายไฟแนนซ์เบื้องต้น
- **Monitor cost** — ไม่ optimize cost เป็นเป้าหมายแรก แต่ต้องวัดและมี brake ให้ SuperAdmin ลดทีหลัง
- **Hard safety guard** — privacy, consent, revenue write path, settlement, payment, invoice
- **ไม่กระทบระบบเดิม** — buyer lead / seller reveal / outcome / payment / settlement ที่ใช้งานแล้ว **ห้ามแตะ**

### หลักคิด v6.0A (AI First — ไม่ใช่ Cost-Control First)

| แนวเดิม (เลิกใช้เป็น default design) | แนว v6.0A |
|--------------------------------------|-----------|
| orchestrator/template เป็นหลัก, AI optional | **AI high** เป็น design default บน staging/closed pilot |
| ประหยัด API ก่อน | **พิสูจน์ product value ก่อน** — ดูว่าน้องเอช่วยขายได้จริงแค่ไหน |
| เปิด AI ทีละน้อย | เปิดเต็มใน evaluation → **measure** → **downshift/cost optimize** |
| economy = default ทุกที่ | economy/off = **production default**; **high = staging/closed pilot default** |

### v6.0A ทำอะไร / ไม่ทำอะไร

| ทำ (รอบนี้) | ไม่ทำ (รอบนี้) |
|-------------|----------------|
| เอกสาร blueprint นี้ | Deploy Cloud Run / Hosting / Firestore rules |
| Test script static validation | เปิด env/secrets ใหม่ |
| ออกแบบ AI First Evaluation Mode + SuperAdmin brake | เรียก paid AI API จริง |
| Evaluation metrics + rollout plan | เปลี่ยน runtime chat behavior |
| Hard no-go zones matrix | ไม่แตะ production |
| Thai tone guide | แก้ payment / invoice / settlement |
| | แก้ buyer lead / seller reveal / outcome flow |
| | เปิด public signup |

### ความสัมพันธ์กับของเดิม (AI First evaluation path)

```
[User message]
      │
      ▼
[chatSearchOrchestrator] ── inventory facts / templates (baseline — ยังมีเมื่อ AI off)
      │
      │ (staging/closed pilot: AI First Evaluation Mode — tier **high**)
      ▼
[Sales Brain layer] ──► Gemini proxy (server-only, full conversation AI)
      │

      │

```

## 2. AI First Evaluation Mode

### คืออะไร

**AI First Evaluation Mode** คือโหมดออกแบบสำหรับ staging และ closed pilot ที่ตั้งใจให้น้องเอใช้ AI **เต็มศักยภาพ** เพื่อวัดว่า:

- คุยฉลาดแค่ไหน — ถามเป็น แนะนำเป็น ปิดการขายช่วยได้จริงไหม
- ช่วย buyer/seller/dealer แต่ละ flow ได้ดีแค่ไหน
- มี hallucination / safety incident บ่อยแค่ไหน
- cost ต่อบทสนทนาที่มีประโยชน์ (useful conversation) เป็นเท่าไหร่

### Design default

| Environment | AI tier default (v6.0A design) | เป้าหมาย |
|-------------|-------------------------------|----------|
| **Production** | `off` / `low` (ยังไม่เปิด AI First) | ความเสถียร — ไม่แตะใน v6.0A |
| **Staging** | **`high`** | ดูศักยภาพสูงสุด + monitor |
| **Closed pilot** | **`high`** | พิสูจน์ product value กับ cohort จำกัด |

> staging/closed pilot default = **AI high** — ใช้ AI เต็มขึ้นใน buyer/seller/dealer conversation เพื่อ evaluation

### สิ่งที่เปิดใน AI high (evaluation)

| Flow | AI First (high) | หมายเหตุ |
|------|-----------------|----------|
| Buyer chat / search summary | ✅ AI สรุป + ถามกลับ + แนะนำ | inventory-bound |
| Buyer negotiation hint | ✅ | ห้ามรับปากราคา |
| Buyer finance explanation | ✅ AI อธิบาย (ตัวเลขจาก calculator) | disclaimer บังคับ |
| Seller draft / copy assist | ✅ | human review ก่อน publish |
| Seller lead reply suggestion | ✅ | masked context only |
| Dealer suggested reply | ✅ | draft only |
| Troubleshooting | ✅ optional | guard output |
| Lead text parse | ✅ | fallback parser ยังมี |

### สิ่งที่ **ไม่** optimize เป็นเป้าหมายแรก

- ไม่จำกัด AI ให้ต่ำสุดตั้งแต่แรก
- ไม่บังคับ cache hit ก่อนทุก call ใน evaluation phase
- ไม่ปิด flow เพื่อประหยัด — **เปิดก่อน วัดก่อน แล้วค่อย downshift**

### สิ่งที่ยังต้องทำควบคู่ (monitor ไม่ใช่ block ตั้งแต่ต้น)

- **Monitor cost** — daily/monthly spend, cost per useful conversation
- **Log guard events** — hallucination reports, downgrade events
- **Hard no-go zones** — ดู [§12](#12-hard-no-go-zones-ai-first-แต่ห้ามแตะ) — ไม่มีข้อยกเว้น

## 3. Buyer Flow — น้องเอคุยฉลาดขึ้นอย่างไร

### บริบทปัจจุบัน (ไม่แก้ใน v6.0A)

- `chatSearchOrchestrator` จัดการ marketplace search, compare, buyer facts Q&A, finance calculator, troubleshooting — ส่วนใหญ่ `skipGemini: true`
- Buyer lead capture ผ่าน `BuyerLeadConsentModal` + consent ก่อนส่งข้อมูลให้ผู้ขาย (v5.6C+)
- `tryBuyerIntentGateReply`, `tryBuyerScoredMarketplaceReply` — deterministic

### เป้าหมาย Smart Conversation — AI First (evaluation tier **high**)

| จังหวะ | พฤติกรรมที่ต้องการ | AI First (high) | Fallback (เมื่อ brake/off) |
|--------|---------------------|-----------------|----------------------------|
| ค้นหารถ / เปรียบเทียบ | สรุปจาก inventory + ถามงบ/การใช้งาน | **high** — AI สรุปและถามกลับ | orchestrator search |
| ถามสเปกรถที่เลือก | ตอบจาก listing fields + อธิบายเป็นภาษาคน | **high** (facts-bound) | `chatBuyerFactsQa` |
| สนใจรถ / อยากต่อรอง | ถามงบ, วิธีซื้อ, ราคาเสนอ — ทีละขั้น | **high** | buyer advisor templates |
| อธิบายไฟแนนซ์เบื้องต้น | ประเมินค่างวด + AI อธิบาย + disclaimer | **high** | `chatBuyerFinanceCalculator` |
| ก่อนส่ง lead | สรุป + **consent modal** | **off** — ห้าม AI แทน consent | modal เดิม |
| Lead text parse | ดึงงบ/ราคาเสนอจากข้อความอิสระ | **high** | `buyerLeadAiParseFallback` |

### กฎ Buyer Flow

1. **ห้าม** AI สร้างรถ/ราคา/สเปกที่ไม่มีใน inventory
2. **ห้าม** AI ส่งเบอร์/ชื่อ buyer ให้ seller โดยไม่ผ่าน consent
3. **ห้าม** AI รับปากราคาแทนผู้ขาย — แค่ช่วยสรุปข้อเสนอของ buyer
4. **ห้าม** AI แทน `BuyerLeadConsentModal` หรือเปลี่ยน submit path
5. ถามกลับเมื่อไม่ชัด — ใน AI First ใช้ AI ClarificationEngine; เมื่อ brake ใช้ template

## 4. Seller Flow — น้องเอคุยฉลาดขึ้นอย่างไร

### บริบทปัจจุบัน (ไม่แก้ใน v6.0A)

- Seller masked lead queue (v5.6E) — ดู lead แบบ masked
- Contact reveal + outcome flow (v5.6G, v5.6H) — **ห้ามแตะ**
- `sellIntentParser` + draft preview — deterministic, `skipGemini: true`
- `listingDescriptionHelper` — ช่วยเขียนประกาศจากสเปก

### เป้าหมาย Smart Conversation — AI First (evaluation tier **high**)

| จังหวะ | พฤติกรรมที่ต้องการ | AI First (high) | Fallback |
|--------|---------------------|-----------------|----------|
| สร้างประกาศจากแชท | ดึง fields + AI ช่วย copy | **high** | `sellIntentParser` |
| ช่วยเขียนคำอธิบาย | copy จาก fields จริง + seller ตรวจ | **high** | template listing description |
| ตอบคำถาม lead ใน inbox | สรุป lead (masked) + แนะนำคำถามถามกลับ | **high** | seller queue UI |
| ต่อรองในกรอบ | ร่างข้อความตอบ — ไม่รับปากราคา | **high** | negotiation guard templates |
| ปิดดีล / outcome | **ห้าม AI แทน** | **off** | outcome UI |

### กฎ Seller Flow

1. AI ช่วย **ร่างข้อความ** — seller กดส่งเอง (human-in-the-loop)
2. **ห้าม** AI เปิดเผย buyer contact — reveal ผ่าน route เดิมเท่านั้น
3. **ห้าม** AI รับปากว่าขายได้ / รับประกันราคา
4. ข้อมูล lead ที่ AI เห็น = **masked snapshot** เท่านั้น
5. ใน evaluation: `sellerCopyAssist` default **on** (high) — SuperAdmin downshift ได้ภายหลัง

## 6. Sales Brain — ต่อรอง / แนะนำ / ถามกลับ / ไฟแนนซ์เบื้องต้น

### Sales Brain Modules (v6.0B+ implement — เปิดเต็มใน AI First)

| Module | หน้าที่ | AI First | Output guard |
|--------|---------|----------|--------------|
| **NegotiationHelper** | ร่างข้อความต่อรองในกรอบราคา | ✅ high | ห้ามรับปากราคา |
| **RecommendationEngine** | แนะนำรถจาก inventory | ✅ high | carId จริงทุกคัน |
| **ClarificationEngine** | ถามกลับเมื่อ intent ไม่ชัด | ✅ high | ไม่ถาม PII ก่อนจำเป็น |
| **FinanceExplainer** | อธิบายค่างวด/ดาวน์ | ✅ high | disclaimer + ตัวเลขจาก calculator |
| **TroubleshootingAdvisor** | ปัญหารถเบื้องต้น | ✅ high | ไม่วินิจฉัยชัวร์ |

### หลักการต่อรอง (Negotiation Guard)

- น้องเอ **ส่งต่อ** ข้อเสนอของ buyer — ไม่ใช่คู่ต่อรองที่มี authority
- **ห้าม:** “รับเลย”, “ได้ราคานี้แน่นอน”, “ลดให้แล้ว”

### ไฟแนนซ์เบื้องต้น

- ตัวเลขจาก `chatBuyerFinanceCalculator` — AI อธิบายเป็นภาษาคนใน evaluation
- Disclaimer บังคับทุกครั้ง
- **ห้าม** คำแนะนำการเงินแบบฟันธง / รับประกันอนุมัติ

## 7. No-Hallucination Guard — ห้ามมั่วข้อมูลรถ

> **ทุกข้อมูลรถที่น้องเอพูด ต้อง trace กลับไป listing/inventory record ได้** — ใช้ใน AI First ด้วย ไม่มีข้อยกเว้น

| Guard | รายละเอียด |
|-------|------------|
| **Facts-only prompt** | `CHAT_FACTS_ONLY_PROMPT` + listing fields inject |
| **Inventory binding** | AI reply อ้าง `carId` ใน session |
| **Post-output validator** | ตรวจ brand/model/year/price ตรง source |
| **Empty inventory** | “ไม่พบในระบบ” — **ห้าม AI แต่งข้อมูลรถที่ไม่มีใน listing** |
| **Hallucination reports** | user/admin report → metric → trigger downshift review |

## 8. Consent & Privacy Guard

| Rule | รายละเอียด |
|------|------------|
| **No pre-consent contact** | **ห้าม AI reveal buyer phone/contact โดยไม่มี consent** |
| **Modal is source of truth** | `BuyerLeadConsentModal` เท่านั้น |
| **AI ไม่ bypass consent** | แม้ user พิมพ์เบอร์ในแชท — ไม่ forward จนกว่า consent |
| **PDPA** | สรุปก่อนยินยอม |
| **Masked until reveal** | seller/dealer เห็น masked snapshot |

## 9. Credit-Risk & Financial/Legal Copy Guard

**ห้าม** น้องเอใช้คำหรือนัยที่ตีตราผู้ซื้อ — รวมถึง **ห้ามพูด “ติดบูโร”**, ห้ามใช้ **credit-risk label**, ห้ามตีตรา **เครดิต** ของผู้ซื้อ

**ห้าม AI ให้คำแนะนำการเงิน/กฎหมายแบบฟันธง** — ใช้ภาษา “โดยทั่วไป”, “แนะนำตรวจสอบกับผู้เชี่ยวชาญ”, “ขึ้นกับไฟแนนซ์”

Post-output filter: `containsCreditRiskLabel`, `containsBuyerCommissionLanguage`, finance guarantee patterns

## 10. Deterministic Fallback

Fallback ยังจำเป็นเมื่อ SuperAdmin **brake/downshift/off**, emergency kill switch, budget stop, หรือ AI error

| Trigger | Fallback action |
|---------|-----------------|
| Tier → `off` (brake/kill switch) | 100% template / orchestrator |
| AI API error / timeout | template + “ขออภัย ลองใหม่นะครับ” |
| Budget stop | template + log `budget_stop` |
| Output guard fail | ทิ้ง AI output → template |
| Downshift high → standard → low | ลด AI coverage ตาม tier |

```
1. chatSearchOrchestrator (skipGemini paths)
2. Role-specific templates (buyer/seller/dealer)
3. Generic help template
4. Static error copy
```

## 11. SuperAdmin AI Brake / Downshift

### แนวคิด

SuperAdmin **ไม่ต้องเปิด AI ทีละน้อย** — ใน evaluation เปิด **high** ก่อน แล้ว **ค่อย ๆ ลด (downshift/brake)** เมื่อเห็นข้อมูล cost/safety/quality

### Tier ladder (downshift path)

```
high  →  standard  →  low  →  off
 ▲                              │
 └──────── rollback / brake ────┘
```

| Tier | ความหมาย | ใช้เมื่อ |
|------|----------|----------|
| **high** | AI เต็ม — evaluation default (staging/closed pilot) | พิสูจน์ product value |
| **standard** | ลดบาง flow — ยังมี AI หลัก | cost สูง / quality ลดลงเล็กน้อย |
| **low** | AI เฉพาะ high-value flow | cost optimize ขั้นแรก |
| **off** | template/orchestrator เท่านั้น | emergency / production safe |

### Per-flow downshift (ลดแยก flow ได้)

| Flow toggle | downshift ได้ | ตัวอย่าง |
|-------------|---------------|----------|
| `buyerChat` / buyer search summary | ✅ | high → standard: ปิด AI summary |
| `sellerDraft` / seller copy assist | ✅ | high → low: template copy only |
| `dealerSuggestedReply` | ✅ | ลด generate quota |
| `priceNegotiation` | ✅ | template hint only |
| `financeExplanation` | ✅ | calculator only ไม่มี AI explain |
| `troubleshooting` | ✅ | template only |
| `buyerLeadCapture` | ❌ always modal | ห้าม AI แทน |
| revenue / settlement / payment | ❌ always off | hard no-go |

### Emergency kill switch

- ปุ่ม **Emergency AI Off** ใน SuperAdmin — ตั้ง tier → `off` ทันทีทุก flow
- ทุก Gemini path หยุด — fallback template 100%
- Log event: `emergency_kill_switch` + `updatedBy`
- **ไม่กระทบ** lead submit / reveal / outcome / settlement routes

### SuperAdmin UI concept (read-only ใน v6.0A)

- ต่อจาก `SmartSalesAiControlPreview`
- แสดง: current tier, per-flow toggles, downshift history, kill switch (mock)
- **ยังไม่ persist / ยังไม่เปลี่ยน runtime** ใน v6.0A

## 12. Hard No-Go Zones (AI First แต่ห้ามแตะ)

> AI First เปิด AI กว้างใน **conversation** — แต่มี **hard no-go zones** ที่ห้าม AI เข้าไม่ว่า tier ใด

| Zone | ห้าม AI | เหตุผล |
|------|---------|--------|
| **Revenue write path** | ❌ ห้าม AI ใน revenue write path | lead submit, fee record creation |
| **Settlement adjustment write** | ❌ ห้าม AI ใน settlement adjustment write | admin settlement mutations |
| **Payment** | ❌ ห้าม AI ใน payment | ไม่แตะ payment logic |
| **Invoice** | ❌ ห้าม AI ใน invoice | ไม่แตะ invoice logic |
| **Buyer contact reveal** | ❌ ห้าม AI reveal buyer phone/contact โดยไม่มี consent | PDPA + consent modal |
| **Listing facts** | ❌ ห้าม AI แต่งข้อมูลรถที่ไม่มีใน listing | hallucination guard |
| **Finance/legal definitive** | ❌ ห้าม AI ให้คำแนะนำการเงิน/กฎหมายแบบฟันธง | regulatory/trust |
| **Seller reveal / outcome routes** | ❌ ห้ามแตะ | flow ที่ใช้งานแล้ว |
| **Production default** | ❌ AI First high เฉพาะ staging/closed pilot | production ยัง off/low |

## 13. Evaluation Metrics

ใช้วัดว่า AI First คุ้มค่าหรือควร downshift — เก็บ aggregate ไม่เก็บ PII เกินจำเป็น

| Metric | วัดอะไร | ใช้ตัดสิน |
|--------|---------|----------|
| **buyer engagement** | ข้อความ/เซสชัน, ความยาวบทสนทนา, กลับมาคุยต่อ | AI มีประโยชน์ไหม |
| **lead conversion** | chat → consent → lead submitted | ช่วยขายได้จริงไหม |
| **seller satisfaction** | feedback / ใช้ copy assist ซ้ำ | seller flow คุ้มไหม |
| **dealer usefulness** | generate ใช้/แก้/ส่ง, time-to-reply | dealer flow คุ้มไหม |
| **hallucination reports** | guard fail + user report | ต้อง downshift ไหม |
| **cost per useful conversation** | spend / conversations with positive outcome | cost vs value |
| **SuperAdmin downgrade events** | tier changes, flow toggles, kill switch | audit trail |

### Decision framework (หลัง measure)

```
IF hallucination_rate > threshold OR safety_incident
  → downshift + review
ELSE IF cost_per_useful_conversation > target BUT value metrics good
  → downshift เฉพาะ flow ที่ ROI ต่ำ (e.g. troubleshooting)
ELSE IF value metrics strong
  → คง high ต่อ หรือขยาย closed pilot
```

## 14. Budget Monitor / Warning / Stop

ใน AI First **ไม่ block cost ตั้งแต่ต้น** — แต่ **monitor + warning + stop** เพื่อให้ SuperAdmin brake ได้

| Level | พฤติกรรม | SuperAdmin action |
|-------|----------|-------------------|
| **Monitor** | log spend, tokens, calls — ทุก request | dashboard ดู realtime |
| **Daily budget warning** | ถึง 80% ของ daily cap | แจ้ง SuperAdmin — ยังทำงานต่อ |
| **Monthly budget warning** | ถึง 80% ของ monthly cap | แจ้ง + แนะนำ downshift |
| **Budget stop** | ถึง 100% cap | หยุด AI calls → fallback template |
| **Emergency kill switch** | manual | tier → off ทันที |

### Rate limits ใน evaluation (ผ่อนปรนกว่า economy — ยังมี ceiling)

| Limit | AI First (high) eval | หมายเหตุ |
|-------|---------------------|----------|
| `maxAiCallsPerSession` | 20 | สูงกว่า economy |
| `maxAiCallsPerUserPerDay` | 100 | pilot cohort |
| `maxTokensPerReply` | 1024 | อนุญาตคำตอบยาวขึ้นใน evaluation |
| Dealer generate | 10/session | monitor แล้ว downshift |

Cache ใช้ลด cost **หลัง measure** — ไม่ใช่เป้าหมายแรกของ evaluation phase

| Stage | ชื่อ | สิ่งที่ทำ | AI API | Runtime change |
|-------|------|-----------|--------|----------------|

| **4** | **closed pilot high mode** | cohort จำกัด, tier **high** | ✅ eval | ⚠️ pilot only |

### Rollback / brake ทุก stage

4. **ไม่กระทบ** lead submit / reveal / outcome / settlement

- [ ] Evaluation metrics ผ่านเกณฑ์ value
- [ ] hallucination_rate ต่ำกว่า threshold
- [ ] SuperAdmin brake ทดสอบแล้ว
- [ ] Cost model ยอมรับได้หลัง downshift plan
- [ ] ลุง review + closed pilot report

## 17. Thai Tone Guide — น้องเอ v6.0A

### บุคลิก (คงไว้ + เน้น AI First)

| ด้าน | แนวทาง |
|------|--------|
| **อบอุ่น** | “ครับ/ค่ะ”, เรียก “คุณ/คุณพี่” เป็นกันเอง |
| **ฉลาด** | ตอบตรงประเด็น, อ้างข้อมูลจริง, **ถามเป็น** เมื่อไม่ชัด |
| **มืออาชีพ** | **เป็นผู้ช่วยขายรถที่คุยเก่ง แนะนำเป็น** — ไม่ hard sell |
| **ไม่เว่อร์** | “ปังปุริเย่!” เฉพาะจังหวะสำเร็จ — **ไม่ใส่ทุกประโยค** |
| **ไม่มั่ว** | ไม่รู้ → บอกไม่รู้ + ถามเพิ่ม |
| **ไม่กดดันเกินไป** | ชวนตัดสินใจอ่อน ๆ — ไม่เร่ง ไม่ guilt-trip |

### ตัวอย่าง DO / DON'T

| ✅ DO | ❌ DON'T |
|-------|----------|
| “งบ 8 แสน อยากใช้รถแบบไหนเป็นหลักครับ ครอบครัวหรือทำงาน?” | “รีบเลยครับ คันนี้จะหมด!” |
| “ช่วยเปรียบเทียบ 2 คันนี้ให้ไหมครับ ออกทางสเปกหรืองบ?” | “คันนี้ดีที่สุด ไม่ซื้อเสียใจ!” |
| “ถ้าสนใจจริง ๆ สรุปให้ผู้ขายติดต่อกลับได้ — กดยินยอมก่อนนะครับ” | ส่งเบอร์ buyer ให้ seller |
| “ผ่อนคร่าว ๆ X บ./เดือน — เช็คกับไฟแนนซ์จริงนะครับ” | “ผ่อนได้แน่นอน สบาย ๆ” |
