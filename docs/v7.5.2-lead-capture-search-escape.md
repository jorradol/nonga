# v7.5.2 — Lead Capture Search Escape Patch

Round goal: เมื่อลูกค้าอยู่ใน lead capture flow (กดปุ่ม "ให้ผู้ขายติดต่อกลับ" แล้ว)
ถ้าพิมพ์ขอ **ค้นหารถใหม่ / ขอรถถูกกว่า / ขอรุ่นอื่น** ระบบต้อง detect เป็น search intent ใหม่
แล้วพัก lead draft เดิม (ไม่ส่ง) ไม่ใช่ถาม lead prompt ซ้ำ ตามกลไก escape ของ v7.1

Status: staging-safe / local-safe เท่านั้น — ไม่ deploy, ไม่เปิด user-visible AI จริง,
ไม่เปิด Gemini จริง, ไม่แก้ lead payload / consent / final confirmation / privacy / queue เดิม

## ปัญหาที่พบจาก staging

ลุงเด่น: หา "รถในเมือง ไม่เกิน 5 แสน" → น้องเอเสนอ Vios/Yaris/HR-V → กด "ให้ผู้ขายติดต่อกลับ"
บน Toyota Yaris → เข้า lead capture แล้วน้องเอเริ่มถามข้อมูล lead จากนั้นพิมพ์
**"ช่วยหารถที่ราคาถูกกว่า 400,000 มานำเสนอเพิ่มให้ด้วยครับ"** → น้องเอ **ยังถาม lead prompt ซ้ำ**
ไม่กลับไปค้นหารถราคาต่ำกว่า 400,000

## Root cause

`detectBuyerLeadFlowEscapeIntent` (v7.1) ในเส้น soft-search พึ่งผลของ
`parseBuyerSearchIntent().isVehicleSearch` แต่:

1. `parseBuyerSearchBudgetMax` ไม่รู้จักคำว่า **"ถูกกว่า / ถูกลง / น้อยกว่า"** เป็น price-under
   signal → "ราคาถูกกว่า 400,000" ได้ `budgetMax = undefined`
2. เมื่อไม่มี budget และไม่มี usage/bodyType ⇒ `isVehicleSearch = false`
3. soft-search escape branch ไม่ทำงาน, strongRedirect ก็ไม่ match (ไม่มี replace/compare/finance
   /gas/fuel signal) ⇒ คืน `none`
4. `useChat` จึงไม่ escape แล้ว `processBuyerLeadCaptureTurn` merge ข้อความเป็น field ต่อ →
   ถาม lead prompt ซ้ำ

เคสเสริมที่หลุดเหมือนกัน: **"หา Yaris รุ่นอื่นให้ดูหน่อย"** (ไม่มี budget, ไม่ match signal เดิม)

หมายเหตุ: ไม่ใช่เพราะยังไม่เปิด Gemini — เป็นช่องว่างของ deterministic flow guard ล้วน ๆ

## การแก้ (minimal patch — intent detection / escape gate เท่านั้น)

1. `src/services/leads/buyerLeadFlowEscape.ts` (escape gate)
   - เพิ่ม signal: `CHEAPER_PRICE_SIGNAL` (ถูกกว่า/ถูกลง/ราคาถูก/ราคาต่ำกว่า/น้อยกว่านี้/ประหยัดกว่า/งบน้อย-ลด),
     `OTHER_VARIANT_SIGNAL` (รุ่นอื่น/รุ่นใหม่/แบบอื่น/ตัวอื่น/สีอื่น/คันอื่น), `CAR_DOMAIN_NOUN_SIGNAL`
   - ขยาย `SEARCH_VERB_SIGNAL` ให้รับ "หา " (เว้นวรรค เช่น "หา Yaris") และ "นำเสนอ"
   - เพิ่ม redirect branch ใหม่: ถ้าเป็น cheaper/variant + (search verb / replace / compare /
     car noun) **และไม่ใช่การกรอก lead field จริง** (`looksLikeLeadFieldContinuation` guard เดิม)
     → `redirect`
   - ไม่แตะ hold / control-action / lead-field guard เดิม → none cases ของ v7.1 ไม่เปลี่ยน

2. `src/services/ai/chat/buyerSearchIntentParser.ts` (budget parser — additive)
   - เพิ่ม "ถูกกว่า|ถูกลง|น้อยกว่า" เข้า price-under alternation ใน priceUnder / implicitUnder /
     plainBaht → "ราคาถูกกว่า 400,000" parse เป็น `budgetMax = 400000` ทำให้ search ใหม่ใช้เงื่อนไข
     ราคาได้จริง (เติมแบบเพิ่มเท่านั้น ไม่ลบ/แก้ของเดิม)

พฤติกรรมเดิมของ `useChat` (v7.1) ไม่เปลี่ยน: `redirect` → `pauseBuyerLeadCapture` + ตอบ ack ว่าพัก
คันก่อนหน้า (ยังไม่ส่ง) แล้วไหลต่อไป orchestrate search ใหม่ในเทิร์นเดียวกัน

## Flow ก่อนแก้ / หลังแก้

- ก่อน: lead capture active → พิมพ์ "หารถถูกกว่า 400,000" → escape = `none` → merge เป็น field →
  ถาม lead prompt ซ้ำ (lead draft ค้าง, ผู้ใช้หลุดไม่ได้นอกจากพิมพ์ "ยกเลิก")
- หลัง: escape = `redirect` (budget=400000) → pause lead draft (ไม่ส่ง) → ตอบว่าเข้าใจ ขอดูรถต่อ →
  ไหลไป search ใหม่ ; lead draft เดิมไม่ถูกส่ง, ไม่มี consent/phone/createdLeadId เกิดขึ้น
