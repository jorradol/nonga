## 3. Feedback Capture Fields

Feedback records เก็บ **นอก repo** (ops channel / secure sheet) — template ด้านล่างเป็น **schema only**

| Field | Type | Rule |
|-------|------|------|
| **testerRole** | enum | `owner` / `allowlisted buyer` / `dealer reviewer` |
| **testDate** | date | ISO date — no timezone PII |
| **scenario** | string | task ID เช่น T-01, T-05, G-02 |
| **userPrompt** | string | **redacted** — ห้าม phone/LINE/address/plate |
| **resultCategory** | enum | `pass` / `bug` / `data issue` / `AI wording issue` / `UX issue` / `legal/compliance issue` / `image issue` |
| **severity** | enum | `low` / `medium` / `high` / `blocker` |
| **expectedBehavior** | string | จาก task list §2 |
| **actualBehavior** | string | **no PII** — redacted observation |
| **screenshotAllowed** | yes/no | if yes → **must redact** plate/phone/LINE/address before store |
| **recommendedFix** | string | actionable — owner assignment |
| **owner** | enum | `product` / `data` / `frontend` / `backend` / `legal` |

### Forbidden in feedback records

| Forbidden | Rule |
|-----------|------|
| Full plate | ❌ |
| UID / allowlist tester identity raw | ❌ |
| Phone / LINE / address | ❌ |
| Raw image URL | ❌ |
| Per-car make/model/price in git | ❌ |
| Secret / env dump | ❌ |

## 4. Issue Taxonomy

### 4.1 Bug

ระบบพังหรือ logic ผิด — ไม่ใช่ข้อมูล listing อย่างเดียว

| Example | Severity guide |
|---------|----------------|
| การ์ดไม่ขึ้น / API error | medium–blocker |
| compare ใช้ context ผิด / stale cards | high |
| session scope ผิดข้ามแชท | high |
| orchestrate 401 สำหรับ allowlisted | blocker |

### 4.2 Data issue

ข้อมูลรถใน staging inventory ไม่ถูกต้องหรือไม่ครบ

| Example | Severity guide |
|---------|----------------|
| ราคา/ปี/ไมล์ผิด | medium–high |
| รูปผิดคัน | high |
| ข้อมูลไม่ครบที่ควรมี | low–medium |
| wholesale หลุด public | **blocker** |

### 4.3 AI wording issue

น้องเอตอบไม่ตรงหลัก grounding

| Example | Severity guide |
|---------|----------------|
| แต่งข้อมูลนอกประกาศ | high–blocker |
| ฟันธงสภาพรถ / ชนหนัก / น้ำท่วม | high–blocker |
| overpromise — “คุ้มค่าแน่นอน”, “ดีที่สุดแน่นอน” | medium–high |
| tone ไม่เหมาะ / ขายเกินจริง | low–medium |
| ไม่ตอบ **"ข้อมูลประกาศยังไม่พอ"** เมื่อข้อมูลไม่พอ | medium |

### 4.4 UX issue

ผู้ใช้ใช้งานยากหรือเข้าใจผิด

| Example | Severity guide |
|---------|----------------|
| ปุ่ม/flow สับสน | low–medium |
| รูปดูยาก / การ์ดอ่านยาก | low–medium |
| compare/refine ไม่รู้ว่าต้อง search ก่อน | low |

### 4.5 Legal/compliance issue

เสี่ยงต่อ สคบ. / PDPA / กรมขนส่ง (ดู v6.2D)

| Example | Severity guide |
|---------|----------------|
| แสดงทะเบียนเต็ม public | **blocker** |
| PII / เอกสาร / หลักฐานการเงิน public | **blocker** |
| claim รับประกันจากน้องเอ | high–blocker |
| สนับสนุนโอนลอย | **blocker** |

### 4.6 Image issue

| Example | Severity guide |
|---------|----------------|
| รูปไม่โหลด / hotlink fail | medium |
| รูปผิดคัน | high |
| รูปเห็นป้ายเต็ม / phone / LINE ในรูป | high–blocker |

## 5. AI Grounding Checks

### 5.1 Grounding rules (monitor during pilot)

| Rule ID | Rule |
|---------|------|
| GR-01 | น้องเอต้องตอบจาก **ข้อมูลประกาศจริง** ใน staging inventory ก่อน |
| GR-02 | **ห้ามแต่งข้อมูล** นอกประกาศ |
| GR-03 | ถ้าข้อมูลไม่พอ → **"ข้อมูลประกาศยังไม่พอ"** |
| GR-04 | **ห้ามรับประกัน** สภาพรถ / ชนหนัก / น้ำท่วม / เลขไมล์แทนผู้ขาย |
| GR-05 | **ห้าม overpromise** — เช่น “คุ้มค่าแน่นอน”, “ดีที่สุดแน่นอน” |
| GR-06 | Tone **น้องเอ** — อบอุ่น น่าเชื่อถือ ไม่ขายเกินจริง |
| GR-07 | Inventory count **10** — ห้ามอ้างจำนวนรถนอก inventory |

### 5.2 Monitor prompts (spot-check)

ใช้ร่วมกับ §2 — บันทึก resultCategory ถ้า fail:

- `งบ 4 แสน มีรถอะไรน่าเล่น`
- `เทียบคันที่ 1 กับ 2`
- `เอาประหยัดน้ำมันกว่า`
- คำถามสภาพรถที่ listing ไม่มี → ต้องได้ insufficient-data response
