## 1. Objective ของ admin-only Gemini shadow smoke

เป้าหมายของ admin-only Gemini shadow smoke (รอบอนาคต ที่ v7.7 นี้แค่ "วางแผน") คือ:

1. เตรียม **test design + readiness** เพื่อในอนาคตจะรัน Gemini แบบ **shadow** (เงา) เทียบกับ deterministic output โดย **admin เห็นเพื่อเปรียบเทียบเท่านั้น**
2. ตรวจว่า AI draft จะ "ตอบเป็นภาษา/น้ำเสียง" ได้ปลอดภัยแค่ไหน โดย **ไม่กระทบ flow จริง** และ **ไม่ถึงมือผู้ใช้จริง/buyer**
3. ยืนยันว่า guardrail ทั้งหมด (PII redaction, deterministic authority, fallback, kill switch) พร้อมก่อนพิจารณา go/no-go รอบถัดไป
4. เก็บหลักฐานแบบ **sanitized** เพื่อใช้ตัดสิน go/no-go สำหรับ admin-only shadow รอบจริง

v7.7 นี้ **ไม่ใช่ activation** — เป็นการออกแบบการทดสอบ + เกณฑ์ความพร้อมเท่านั้น

## 5. Admin-only Shadow Principle

หลักการ shadow ที่บังคับใช้ (no buyer-facing exposure):

- ผลลัพธ์ AI (Gemini draft) ให้ **admin เห็นเพื่อเทียบกับ deterministic output เท่านั้น**
- **ผู้ใช้จริง / buyer / public ห้ามเห็น** AI output ในรอบ shadow (admin-only / shadow-only)
- AI **ไม่มี write path** เข้า flow จริง — ไม่เปลี่ยนผลการค้นหา, ไม่เปลี่ยน card, ไม่ส่ง lead, ไม่สร้าง consent
- shadow output ถูกเก็บแบบ sanitized เพื่อเปรียบเทียบ — ไม่มีการแสดงต่อ buyer ไม่ว่ากรณีใด
- ถ้า shadow path มีความเสี่ยง buyer จะเห็น ⇒ ถือเป็น **NO-GO** ทันที

## 7. Input Policy

ส่งให้ AI ได้เฉพาะข้อมูลที่ปลอดภัยต่อสาธารณะ (allowed context):

- **sanitized inventory summary** (สรุป listing ที่ตัด PII แล้ว)
- **public car facts** (brand / model / year / bodyType / fuelType / price / mileage / sanitizedPublicDescription / normalizedPublicFeatures)
- **deterministic intent** (ผลของ intent parser, ไม่ใช่ raw user secret)
- **allowed context** อื่นที่ผ่าน sanitization แล้วเท่านั้น

ทุก input ต้องผ่าน sanitization ก่อนเสมอ — ห้ามส่ง raw payload ที่มี PII เข้า prompt

## 8. Forbidden Input Fields

ฟิลด์ที่ **ห้ามส่งเข้า AI prompt เด็ดขาด** (forbidden input fields):

- `phone` (เบอร์โทร)
- `full license plate` (ทะเบียนเต็ม)
- `VIN`
- `full UID` (Firebase UID เต็ม)
- `secret`
- `API key`
- `internal price` (ราคาภายใน)
- `wholesale price` (ราคาขายส่ง)
- `raw owner/dealer private data` (ข้อมูลส่วนตัว owner/dealer ดิบ)
- `raw lead/contact data` (ข้อมูล lead/contact ดิบ)

> หมายเหตุ: รายการข้างบนเป็น **ชื่อ policy field** ที่ห้ามใช้ ไม่ใช่ค่าจริง — เอกสารนี้ไม่บรรจุค่า PII / phone / plate / VIN / secret / API key จริงใดๆ

## 9. Output Policy

นโยบายผลลัพธ์ AI (shadow draft) — admin-only:

- AI ช่วยได้เฉพาะ **ภาษา / น้ำเสียง / คำอธิบาย** บนผลลัพธ์ deterministic เท่านั้น
- ❌ ห้ามแต่งข้อมูลรถเอง (ราคา / รุ่น / ปี / เลขไมล์ / สภาพ / ไฟแนนซ์ / โปรโมชั่น / availability)
- ❌ ห้ามการันตีไฟแนนซ์ ("อนุมัติแน่นอน" / "ผ่อนได้แน่นอน" / "การันตี")
- ❌ ห้ามบอกว่ารถ "ปลอดภัย" / "สภาพดีแน่นอน"
- ❌ ห้ามข้าม consent / final confirmation
- ❌ ห้ามชวนส่ง lead เองโดยไม่มี user action
- ❌ ห้ามแสดง queue count ฝั่ง buyer
- ✅ ต้องมีคำเตือน / ข้อจำกัดที่เหมาะสม (disclaimer ว่าไม่ใช่การยืนยันสภาพรถ/การอนุมัติไฟแนนซ์)
- ในรอบ shadow: output ไม่ถูกแสดงต่อ buyer ไม่ว่ากรณีใด

## 10. Deterministic Authority Map

จุดที่ deterministic เป็น authority และ AI **ห้ามแทนที่** (shadow draft ไม่มีสิทธิ์ override):

| Authority | Source (deterministic) | AI ในรอบ shadow |
|---|---|---|
| search result source | `buyerSearchIntentParser` + `useSearch` + inventory จริง | shadow draft เท่านั้น ไม่เปลี่ยนผล |
| car cards | deterministic card rendering จาก inventory จริง | ไม่แตะ — wording เทียบเงาเท่านั้น |
| lead capture | `buyerLeadCaptureFlow.ts` state machine (no Gemini) | ไม่มีสิทธิ์ |
| phone capture | user input เท่านั้น (`updateBuyerLeadDraftPhone`) | ไม่มีสิทธิ์ / ไม่เดา |
| consent preview | `buildLeadPreviewContextFromMemory` (display-only) | ไม่มีสิทธิ์ |
| final confirmation | consent modal + `draftToCreateInput` (`consentConfirmed`) | ไม่มีสิทธิ์ |
| queue policy | v7.3 no buyer-facing queue count | ไม่มีสิทธิ์ |
| dealer/owner isolation | public-safe fields เท่านั้น, ไม่มี identity/internal price | ไม่มีสิทธิ์ |
| public DTO redaction | public DTO ตัด PII / plate / VIN / UID | ไม่มีสิทธิ์ |

หลักการ: **AI เป็นชั้นภาษา/น้ำเสียงบน deterministic เท่านั้น — ไม่ใช่ผู้ตัดสินใจ flow และไม่ใช่ source of truth**

## 11. Fallback Policy (ทั้งหมดต้อง fallback deterministic)

เงื่อนไขที่ต้อง **fallback deterministic** เสมอ (fail-closed):

- AI fail (error / exception)
- timeout
- unsafe output (ละเมิด output policy)
- hallucination risk (แต่งข้อมูลรถ / สเปกที่ไม่มี source)
- policy block (เนื้อหาผิด policy)
- prompt injection (พยายามดึง PII / secret / ทะเบียน / VIN)

ทุกกรณีข้างบน ⇒ ระบบใช้ **deterministic output** เป็นผลจริง และ shadow draft ที่ unsafe จะถูกทำเครื่องหมาย fail แบบ sanitized — **fallback deterministic** ไม่กระทบ flow / lead / consent / phone

## 12. Shadow Comparison Method

วิธีเปรียบเทียบแบบเงา (admin-only):

- admin เห็น **deterministic output** วางคู่กับ **AI draft** เพื่อเปรียบเทียบคุณภาพภาษา/น้ำเสียง
- **AI output ต้องไม่ถูกส่งให้ buyer** — buyer เห็นเฉพาะ deterministic เท่านั้น (no buyer-facing exposure)
- บันทึกผลแบบ **sanitized** เท่านั้น: scenario id (S1..S9), pass/fail, reason code — ไม่มี raw content/PII
- การเปรียบเทียบเป็น **read-only / offline-style review** — ไม่เขียนกลับเข้า flow จริง

## 13. Logging / Redaction Policy

นโยบาย log สำหรับ shadow smoke (no raw PII):

- ❌ ห้าม log raw PII
- ❌ ห้าม log full plate / VIN / phone
- ❌ ห้าม log secret / API key
- ✅ ใช้เฉพาะ **sanitized scenario id / reason code / pass-fail** เท่านั้น
- masked identifier เท่านั้น (เช่น `Xxxx...xx`) หากจำเป็น
- error log ต้องผ่าน redaction (ลบ key / Bearer / PII) ก่อนเสมอ
- evidence เก็บแบบ sanitized ตาม pattern รอบก่อน (v7.5.2B / v7.6A)

## 14. Kill Switch Drill

วิธีทดสอบ kill switch (สำหรับรอบอนาคตเมื่อเปิด shadow — v7.7 แค่ออกแบบ drill):

1. ตั้งสถานะ shadow เปิด (ในรอบจริงเท่านั้น ไม่ใช่รอบนี้)
2. สั่ง `NONGA_AI_EMERGENCY_KILL_SWITCH=true`
3. ยืนยันว่า flag reader คืน `offFlags(...)` ⇒ ระบบ **ตัดกลับ deterministic ทันที**
4. ยืนยันว่า shadow path หยุดเรียก Gemini ทั้งหมด (ไม่มี network ออก)
5. ยืนยันว่า admin ไม่เห็น AI draft ใหม่ และ buyer ยังเห็น deterministic ตามปกติ
6. บันทึกผล drill แบบ sanitized (pass/fail + reason code)

หลักการ: kill switch ต้อง **ตัดกลับ deterministic ได้เสมอ** — ถ้า drill ไม่ผ่าน ⇒ NO-GO
รอบ v7.7 นี้ **ไม่รัน** drill จริง (ไม่มี runtime / ไม่เปิด flag) — เป็นการออกแบบขั้นตอนเท่านั้น

## 16. Known Blockers / Open Risks

- **B1:** ยังไม่มี owner sign-off สำหรับเปิด admin-only shadow จริง — **blocker**
- **B2:** secret wiring (Gemini API key ผ่าน Secret Manager) ยังไม่ยืนยันสำหรับ shadow rollout
- **B3:** budget caps ยังไม่ตั้งจริงใน staging runtime
- **B4:** output safety ส่วนใหญ่ทดสอบ offline — shadow smoke จริงยังไม่ได้รัน
- **B5:** ยังไม่มี cost/quota baseline จาก shadow traffic จริง
- **O1 (open risk):** hallucination เชิงคุณภาพภาษาไทย — ต้องเก็บตัวอย่าง shadow เพิ่ม
- **O2 (open risk):** prompt injection (S9) — มี redaction แต่ต้องเฝ้าใน shadow run
- **O3 (open risk):** admin-only boundary — ต้องยืนยันว่า shadow UI ไม่หลุดถึง buyer (no buyer-facing exposure)

v7.7 **ไม่ปิด** blocker เหล่านี้ — เป็นเพียงการ record เพื่อ go/no-go รอบถัดไป
