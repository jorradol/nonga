## Summary

Owner-browser v22.55 found one remaining defect: after an exact Corolla 2020 search and family-use follow-up, asking `ไมล์ 88,000 เยอะไปไหม` returned “ช่วยกดดูรายละเอียดรถ…” even though the grounded Corolla (mileage 88,000) was already the active conversation vehicle.

## Root cause

1. Mileage evaluation was **not** classified as a pilot follow-up (unlike family/`ครอบครัว`), so the server bridge re-ran the client orchestrator.
2. `/ไมล์/` matched bare **facts Q&A** (`specField`) which required an explicit pronoun / card click for session fallback → `BUYER_ASK_SELECT_CAR_FIRST`.
3. Gemini zone regex required `ไมล์` immediately followed by `เยอะ|…`, so `ไมล์ 88,000 เยอะไปไหม` never opened `car_fit_reason`.
4. Exact single-result search saved card context but did **not** set `lastSelectedCarId` without a card click.

## Fix (reuse existing mechanisms)

| Area | Change |
|------|--------|
| Pilot follow-up | `isPilotBuyerMileageFollowUp` → same session-first path as family |
| Gemini zone | Allow digits/punctuation between `ไมล์` and judgment words |
| Facts / orchestrator | Grounded mileage evaluation before select-car trap; mileage fact match; ambiguity clarification |
| Active vehicle | Exact single-result search + single-card assistant message sets `lastSelectedCarId` |
| Deterministic fallback | `buildMileageEvaluationReply` / pilot copy with annual estimate + condition caveats |
| Advisor | Grounded mileageGeneral uses listing mileage when a target car exists |

No new AI architecture, no Lead create, Pilot controls unchanged, Production untouched.
