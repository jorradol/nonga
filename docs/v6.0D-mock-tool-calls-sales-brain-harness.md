## 2. Mock Tool Call Contract

### Input (`SalesBrainMockInput`)

| Field | Type | รายละเอียด |
|-------|------|------------|
| `userMessage` | string | ข้อความผู้ใช้ (UTF-8) |
| `userRole` | `"buyer"` \| `"seller"` \| `"dealer"` \| `"admin"` | บทบาท |
| `flowContext` | object? | `{ sessionIdHash, selectedListingId?, attachedImageCount? }` |
| `listingContext` | object? | `{ listingId?, price?, brand?, model?, fieldsPresent: string[] }` — **facts from system only** |
| `aiMode` | `"off"` \| `"low"` \| `"standard"` \| `"high"` | จาก v6.0B `NONGA_AI_MODE` design |
| `aiProvider` | `"mock"` \| `"none"` | v6.0D อนุญาต **`mock` only** |

### Output (`SalesBrainMockOutput`)

| Field | Type | รายละเอียด |
|-------|------|------------|
| `intent` | string | e.g. `buyer.search`, `buyer.finance_negotiate`, `seller.image_draft` |
| `selectedCapabilities` | string[] | CAP IDs เช่น `CAP-04`, `CAP-05` |
| `mockToolCalls` | `MockToolCall[]` | `{ toolId, capId, mock: true, paramsHash }` |
| `responsePlan` | string | สรุปแผนตอบ (ไม่ใช่ข้อความจริงจาก API) |
| `safetyDecision` | `"allow"` \| `"no_go"` \| `"askFollowUp"` | guard result |
| `fallback` | boolean | true เมื่อ aiMode=off หรือ no_go → orchestrator |
| `askFollowUp` | string? | คำถามถามกลับเมื่อ facts ไม่พอ — **ห้าม hallucinate** |
| `logRecord` | object | `{ intent, caps, safety, latencyMs: 0 }` — **no PII raw phone/contact** |

### MockToolCall shape

```typescript
interface MockToolCall {
  toolId: string;       // e.g. "buyerSearchIntentParser.parse"
  capId: string;        // e.g. "CAP-04"
  mock: true;           // always true in v6.0D
  paramsHash: string;   // stable hash — no raw PII in params
}
```

### Contract rules

1. **ห้ามมี PII raw phone/contact ใน logs** — ใช้ `paramsHash` / redact
2. **ถ้า facts ไม่พอ** → `safetyDecision: "askFollowUp"` + `askFollowUp` text — **ไม่เดา listing fields**
3. **no-go intent** → `safetyDecision: "no_go"`, `fallback: true`, empty `mockToolCalls` สำหรับ write paths
4. **aiMode=off** → `fallback: true`, route to CAP-15 orchestrator plan only
5. **Deterministic** — same input → same output (including `paramsHash`)

## 3. Harness Architecture (offline)

```
scripts/test-v60d-mock-tool-calls-sales-brain-harness.mts
      │
      ├── routeSalesBrainMock(input) → SalesBrainMockOutput
      │        ├── intent classifier (keyword/rules — deterministic)
      │        ├── capability selector (maps to CAP-XX)
      │        ├── no-go zone guard
      │        └── PII redact in logRecord
      │
      ├── SCENARIO_FIXTURES (8 scenarios from §4)
      └── assert expected caps / safety / no network
```

**ไม่ import** `src/` runtime modules ใน v6.0D — harness เป็น **spec implementation** สำหรับ regression ก่อน wire จริงใน v6.0E+

## 5. No-Go Zone Handling in Harness

| Trigger pattern | safetyDecision | fallback | Blocked caps |
|-----------------|----------------|----------|--------------|
| `settlement adjust`, `adjust settlement write` | `no_go` | true | CAP-13 write |
| `record success fee`, `revenue write` | `no_go` | true | revenue write path |
| `process payment`, `charge card` | `no_go` | true | payment |
| `generate invoice`, `issue invoice` | `no_go` | true | invoice |
| `reveal phone`, `send buyer number to seller` | `no_go` | true | CAP-09/10 contact reveal |
| `submit lead without consent` | `no_go` | true | CAP-09 bypass |

Harness **ไม่สร้าง mockToolCalls** สำหรับ write paths — `responsePlan` = "fallback to existing deterministic route"

## 6. Deterministic Fallback & Safety

| Condition | Behavior |
|-----------|----------|
| `aiMode === "off"` | `fallback: true`, CAP-15 only, `mockToolCalls: []` |
| `aiProvider === "none"` | same as off |
| `safetyDecision === "no_go"` | `fallback: true`, log `no_go_blocked` |
| `safetyDecision === "askFollowUp"` | no inventory hallucination; partial caps only if safe |
| AI provider blocked (gemini in v6.0D) | harness never calls — spec only |

Fallback chain (unchanged from v6.0C):

```
chatSearchOrchestrator → role templates → chatMockFallback → static error
```

## 7. Logging & PII Rules

### เก็บได้ใน `logRecord`

- `intent`, `selectedCapabilities`, `safetyDecision`, `fallback`, `scenarioId`
- `paramsHash` (SHA256 prefix of redacted params)
- `latencyMs` (mock = 0)

### ห้ามเก็บ (no PII logging)

- Raw phone numbers (`081…`, `+66…`)
- Raw email
- Buyer full name
- `contactPhone` / `buyerPhone` fields
- Full `userMessage` in production logs (harness test may use message for routing only — log uses intent hash)

Redaction: phone patterns → `[phone-redacted]` before hash
