## Admin Auth Mode Alignment

Admin auth helper now supports explicit modes:

- `adminApiTokenMode` -> `Authorization: Bearer <NONGA_ADMIN_API_TOKEN>`
- `firebaseIdTokenMode` -> `Authorization: Bearer <Firebase ID token>`
- `legacyXApiTokenMode` -> `x-api-token: <token>`

For admin shadow smoke/gate path, the call site is now explicit with `admin_api_token` mode and explicit fallback policy. This prevents silent mode-mixing.

## Server Token Env Alignment

Primary server-compatible token source is now explicit:

1. `NONGA_ADMIN_API_TOKEN` (primary)
2. `VITE_NONGA_ADMIN_API_TOKEN` only when fallback is explicitly allowed

If token is missing or invalid, helper throws immediately before header construction.

## Script/Gate Token Env Alignment

The admin smoke/gate header builder now resolves token path with server-first logic:

- primary: `NONGA_ADMIN_API_TOKEN`
- fallback: `VITE_NONGA_ADMIN_API_TOKEN` only when explicitly intended

This aligns script/gate behavior with what `adminApiAuth` verifies on the server and reduces staging-boundary mismatch risk that surfaced in v12.8/v12.9.

## Token Validation

Validation now enforces:

- token must be present and non-empty
- token cannot be literal env reference (e.g. `$NONGA_ADMIN_API_TOKEN`, `${NONGA_ADMIN_API_TOKEN}`, `undefined`, `null`)
- token cannot have leading/trailing whitespace
- token cannot contain newline
- token cannot be quoted literal
- token cannot already contain `Bearer ` prefix when helper adds `Bearer`

Invalid values fail fast before any request dispatch.

## Sanitized Header Preview

Sanitized preview helper is explicit and always masked:

- `Authorization: Bearer ***MASKED***`
- `x-api-token: ***MASKED***`

No token value is printed in docs/tests/log assertions for this patch.
