## 3. Admin — provision ผู้ทดลอง

### 3.1 สร้างบัญชี Firebase Auth (ทีละคน)

1. Firebase Console → โปรเจกต์ `nonga-ce93c` → **Authentication** → **Add user**
2. ใส่อีเมลที่ login ได้จริง
3. ส่ง **Password reset** หรือรหัสชั่วคราวทางช่องทางส่วนตัว (ห้ามโพสต์ในกลุ่ม)
4. **คัดลอก UID** เก็บในตาราง pilot

### 3.2 เปิดสิทธิใน Admin Portal

1. Login เป็น **admin** หรือ **superadmin**
2. ไปที่ https://nonga-ce93c.web.app/admin/pilot-users  
   (หรือ Admin Dashboard → **ผู้ใช้งานทดลอง (Closed Pilot)**)
3. กรอก **Firebase UID** + อีเมล/ชื่ออ้างอิง
4. เลือกบทบาท:
   - **member** — ผู้ซื้อ / ผู้ขายรถบ้าน
   - **dealer** — ต้องใส่ **dealerId** (เช่น `thor-auto`) + ชื่อเต็นท์ (ถ้ามี)
5. สถานะ **active** ก่อนให้ใช้งานจริง
6. กด **บันทึกสิทธิผู้ใช้ทดลอง** → ตรวจในรายการ “ผู้ใช้ล่าสุด”

> **Closed Pilot:** เพิ่มเฉพาะผู้ที่ได้รับเชิญ — **public signup ยังปิด** ระบบไม่สร้างรหัสผ่านจากหน้านี้

### 3.3 Checklist ต่อ UID

| ☐ | รายการ |
|---|--------|
| ☐ | Auth user สร้างแล้ว |
| ☐ | Provision ใน `/admin/pilot-users` แล้ว (role + status ถูก) |
| ☐ | dealer: มี `dealerId` ตรงกับขอบเขตคลังรถ |
| ☐ | ทดสอบ login + เมนูที่ควรเห็นตาม role |
| ☐ | ส่งลิงก์ staging + คู่มือผู้ทดลองแล้ว |

## 4. Buyer test checklist

ผู้ทดลอง: **guest หรือ member** (ไม่จำเป็นต้อง login เพื่อค้นหาเบื้องต้น — login เมื่อต้องการฟีเจอร์ที่ล็อก)

| ☐ | ขั้นตอน | ผลที่คาดหวัง |
|---|--------|----------------|
| ☐ | เปิด https://nonga-ce93c.web.app → หน้าแชท | คุยกับน้องเอได้ |
| ☐ | ถามหารถ (งบ / ยี่ห้อ / จังหวัด) | ได้การ์ดรถหรือคำแนะนำในแชท |
| ☐ | กดขยาย **ดูรายละเอียดในแชท** บนการ์ดรถ | เห็นรายละเอียด + บทวิเคราะห์แบบคัดสรร (ไม่เด้ง full page หลุดจากแชท) |
| ☐ | ลอง “สนใจรถ” / รายงานประกาศ (ถ้ามี) | ทำงานแบบทดลอง — **ยังไม่ใช่ lead จริง** |
| ☐ | อ่าน Pilot Safety (ข้อ 8) กับผู้ทดลอง | เข้าใจว่าน้องเอไม่รับประกันสภาพรถ |

## 5. Seller (รถบ้าน / member) test checklist

| ☐ | ขั้นตอน | ผลที่คาดหวัง |
|---|--------|----------------|
| ☐ | Login ด้วยบัญชี member ที่ provision แล้ว | เข้าระบบได้ |

## 8. Pilot Safety Notes

แจกให้ผู้ทดลองทุกกลุ่ม (สรุปเต็มอยู่ในคู่มือผู้ใช้):

| หัวข้อ | ข้อความ |
|--------|---------|
| **น้องเอ** | เป็นผู้ช่วยแนะนำค้นหา/สรุปข้อมูล — **ไม่ใช่การรับประกันสภาพรถหรือเอกสาร** |
| **ผู้ซื้อ** | ควรตรวจรถจริง ทดลองขับ ตรวจเล่มทะเบียน/สัญญา ก่อนตัดสินใจ |
| **ผู้ขาย** | รับผิดชอบความถูกต้องของข้อมูลและรูปที่ลง |
| **ความเป็นส่วนตัว** | หลีกเลี่ยงส่งบัตร ทะเบียน สัญญาไฟแนนซ์ หรือข้อมูลอ่อนไหวในแชท |
| **การติดต่อ** | แชร์เบอร์/LINE เมื่อจำเป็นและทั้งสองฝ่ายยินยอมเท่านั้น |

## 9. Feedback plan

รอบ v5.5A **ยังไม่สร้างระบบ feedback ในแอป** — ใช้ช่องทางภายนอกก่อน:

| ช่องทาง | ใช้เมื่อ |
|---------|----------|
| **Google Form** | เก็บคะแนน/ข้อความเป็นระบบ |
| **LINE กับลุง** | ปัญหาเร่งด่วน / ส่งรูปหน้าจอ |
| **Manual note** | สรุปหลังคุยโทร |

**คำถามแนะนำใน Form / แบบสอบถาม:**

1. ใช้งานง่ายไหม (1–5)?
2. ตรงไหนงงหรือติดขั้นตอน?
3. รูปขึ้นถูกและครบไหม?
4. น้องเอแนะนำ/สรุปรถช่วยได้แค่ไหน?
5. อยากให้เพิ่มอะไรในรอบถัดไป?

เก็บ **วันที่, role, หน้าที่ใช้, อุปกรณ์ (มือถือ/เดสก์ท็อป)** ในชีตติดตาม pilot

## 10. Rollback & safety

| สถานการณ์ | แนวทาง |
|-----------|--------|
| ผู้ทดลองใช้งานผิดสิทธิ์ | ตั้ง `status: suspended` ใน `/admin/pilot-users` |
| ประกาดผิด/รุนแรง | Admin ซ่อน/ลบผ่าน dashboard หรือ dealer unpublish ตาม flow ที่มี |
| ต้องหยุดรับคนใหม่ชั่วคราว | หยุดเชิญ + ไม่ provision เพิ่ม — **ไม่ต้อง** เปิด public signup |
| Deploy ผิด | **รอบนี้ห้าม deploy production** — rollback staging ผ่าน Firebase Hosting release ก่อนหน้า (ลุงเท่านั้น) |
| ข้อมูลรั่วในแชท | แจ้งผู้ใช้ลบข้อความ/รูป — บันทึก incident ใน note |

**ห้ามในรอบแก้ปัญหาเร่ง:**

- แก้ `firestore.rules` / `storage.rules`
- รัน migration write
- เปลี่ยน `NONGA_*` backend flags หรือ secrets บน Cloud Run

## 11. Known limitations

| หัวข้อ | สถานะรอบ closed pilot |
|--------|------------------------|
| **Public signup** | ปิด — สมัครเองไม่ได้ |
| **Lead / สนใจรถ** | ทดลอง — ยังไม่ส่ง lead จริงถึงผู้ขาย |
| **เบอร์ผู้ขายบนตลาด** | ไม่แสดงใน public API (ติดต่อผ่านช่องทางที่ทีมกำหนด) |
| **Payment / subscription** | ยังไม่มีระบบจริง |
| **น้องเอ / Gemini** | คำแนะนำไม่แทนการตรวจสอบรถจริง; ควบคุม cost — ไม่เปิดฟีเจอร์ AI ใหม่โดยไม่จำเป็น |
| **Dealer ใหม่** | รับเฉพาะที่ลุง provision — ไม่เปิด onboarding ดีลเลอร์สาธารณะ |
| **Production** | ยังไม่ใช้ URL production สำหรับ pilot นี้ |

---

## 12. สิ่งที่ห้ามทำในรอบ v5.5A

- Deploy **production**
- เปิด **public signup**
- แก้ **Firestore/Storage rules**
- **Migration write** หรือ seed ข้อมูลจริงโดยไม่ผ่านแผน
- แตะ **secrets / .env / service account**
- เปลี่ยน **backend flags** (`dataBackend`, `imageBackend`, ฯลฯ)
- เพิ่ม **payment / subscription / lead system จริง**
- เพิ่ม **Gemini/API cost** โดยไม่จำเป็น
