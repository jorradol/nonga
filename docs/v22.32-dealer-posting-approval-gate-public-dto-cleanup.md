## 2) Owner-readable summary

| Question | Answer |
|----------|--------|
| What changed about dealer publish? | Dealer draft “publish” / submit now creates a listing with `listingStatus: pending_review` — **not** marketplace-public. |
| Require owner/admin approval before marketplace? | **Yes** for dealer-scoped listings. Admin `POST /api/admin/listings/:id/approve` sets `published`. |
| What can a dealer do now? | Create/edit drafts; submit for review (`pending_review`); hide own listings; view own inventory including pending. **Cannot** self-approve to `published`. |
| What can owner/admin review? | `GET /api/admin/listings/pending-review`; approve via `POST /api/admin/listings/:id/approve`. Admin import path unchanged (can still land published when admin-driven). |
| Can any dealer self-approve? | **No** — visibility unhide / publish blocked with 403 for non-admin on dealer-scoped cars. |
| Public listing fields shown? | Merchandising fields + images + masked plate + `showroomName` / `ownerName` + safe `dealerDisplayName`, `sellerDisplayName`, `dealerSlug`, `sellerType`. |
| Internal/private fields hidden? | `ownerId`, `dealerId`, phone, email, LINE, address, VIN, full plate, wholesale/internal, consent/moderation/duplicate internals, buyer PII. |
| ownerId / dealerId / sellerId? | Portal dealer create: `dealerId` from auth, `ownerId = owner-{dealerId}`. Lead `sellerId = listing.ownerId`. Thor imports keep existing Firebase `ownerId` + `dealerId: thor-auto` (no live migration). ACL still matches `dealerId`. |
| Future lead routing? | Unchanged: listing `ownerId` only; buyer cannot override; manual reveal; kill switch OFF blocks create. Pending listings reject lead create if somehow targeted. |
| What remains locked? | Lead capture ON, real leads, dealer send, public signup, production, live controlled dealer posting preview (next packet). |

### 3.2 Approval status / policy

| Actor / path | Resulting `listingStatus` |
|--------------|---------------------------|
| Dealer draft submit (`publishDraft`) | `pending_review` |
| Dealer import commit (non-admin) | New rows → `pending_review` |
| Dealer visibility unhide | **403** (cannot self-approve) |
| Admin approve route | `published` |
| Admin import (existing) | Still may `published` (or Thor force-hidden env) |
| Import upsert of **existing** row | **Preserves** existing `listingStatus` (Thor marketplace 13 safe) |
| Member (non-dealer) publish | Unchanged consent path → `published` when ready |

### 3.3 Public DTO redaction / mapping

- Deletes: `ownerId`, `dealerId` (plus prior phone/VIN/plate/internal lists).
- Adds when available: `dealerDisplayName`, `sellerDisplayName`, `dealerSlug`, `sellerType`.
- `toPublicDealerSlug`: maps Thor aliases → `thor-auto`; strips `dealer-`/`owner-` prefixes; **omits** opaque Firebase-style uids.

### 3.4 ownerId / dealerId convention (compatibility)

| Path | `dealerId` | `ownerId` | Lead `sellerId` |
|------|------------|-----------|-----------------|
| Dealer portal create/submit | Auth dealer id | `owner-{dealerId}` | = `ownerId` |
| Staging Thor imports (live) | `thor-auto` | Firebase uid (unchanged) | = that uid |
| Queue ACL | Match `dealerId` **or** `ownerId` (or admin) | — | — |

**No live Thor migration** in this step. Future dealer-created listings after approval bind leads via canonical `owner-{dealerId}`.
