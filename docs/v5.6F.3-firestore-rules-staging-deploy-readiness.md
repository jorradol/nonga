## B) Deploy command (ใช้**หลัง** review — รอบ v5.6F.3 ยังไม่รัน)

**Staging project เท่านั้น:** `nonga-ce93c`

```bash
# ตรวจ project ก่อน (ต้องเป็น staging)
firebase use nonga-ce93c

# Deploy เฉพาะ Firestore rules — ห้าม deploy แบบไม่ระบุ scope
npx -y firebase-tools@latest deploy --only firestore:rules --project nonga-ce93c
```

**ห้ามในรอบ rules-only:**

- `firebase deploy` แบบไม่มี `--only` / ไม่มี `--project`
- `deploy --only hosting` (ไม่จำเป็น — rules ไม่เปลี่ยน SPA bundle)
- `deploy` Cloud Run (ไม่จำเป็น — backend ยัง `memory`)
- Deploy rules ไป production project

**ไฟล์ที่ Firebase ใช้:** `firebase.json` → `"firestore": { "rules": "firestore.rules" }`

## D) Rollback plan (rules deploy)

| สถานการณ์ | การตอบสนอง |
|-----------|-------------|
| Regression บน listing/chat/users | Revert `firestore.rules` ใน git ไป commit ก่อน lead block → deploy rules ใหม่ staging |

**ยังไม่เปิด firestore backend ในรอบ rules-only** — rollback env ไม่จำเป็นถ้าไม่ได้แตะ Cloud Run

## E) ข้อห้ามก่อนเปิด `NONGA_LEAD_DATA_BACKEND=firestore`

ต้องทำครบ **หลัง** rules deploy + manual smoke C1–C3 ผ่าน:

| ห้าม / ต้องรอ | เหตุผล |
|---------------|--------|
| เปิด `NONGA_LEAD_DATA_BACKEND=firestore` ก่อน rules live | Client อาจ sync/อ่าน collection ผิดช่วง |
| เปิด payment / success fee | นอก scope MVP |
| Full contact reveal UI | MVP `canRevealContact: false` |
| Admin settlement | ยังไม่เปิด |
| Public signup (`VITE_NONGA_PUBLIC_SIGNUP_ENABLED`) | ยังปิด staging |
| Gemini / smart sales AI parse | compile-time + runtime ยัง OFF |
| Migration write ข้อมูล lead เก่า | ยังไม่มี batch |
| Deploy production rules | staging ก่อนเสมอ |

**ลำดับที่ถูก (หลัง v5.6F.3 approve):**

1. Deploy rules staging (`§B`)
2. Manual smoke (`§C`)
3. (รอบแยก) Cloud Run `NONGA_LEAD_DATA_BACKEND=firestore` + persistence smoke ตาม [v5.6F.1 §D](./v5.6F.1-firestore-lead-persistence-readiness.md)

## F) Risks ที่เหลือ

| Risk | ระดับ | หมายเหตุ |
|------|--------|----------|
| Rules deploy กระทบ collection อื่น | ต่ำ | v544f emulator ครอบคลุม; ยังรันก่อน deploy จริง |
| Staging มี rules เก่าบน Console ไม่ตรง repo | กลาง | เปรียบเทียบ Console กับ `firestore.rules` หลัง deploy |

| Admin อ่าน `buyerLeads` ผ่าน client SDK | ต่ำ | deny all by design — ใช้ API/Admin SDK |
| Production deploy ผิด project | สูง | บังคับ `--project nonga-ce93c` |
