# v7.3 — Natural Lead Preview + No Queue Count Display

Round goal: ใช้ conversational memory จาก v7.2 ช่วยเตรียม **lead preview แบบธรรมชาติ**
(ลูกค้าเห็นว่าน้องเอจำโจทย์ได้) โดยลูกค้ายังต้อง **กรอกเบอร์เอง** มี **preview + final
confirmation** ก่อนส่งเสมอ ไม่ส่งอัตโนมัติ และ **ไม่แสดงจำนวนคิวฝั่ง buyer** อีกต่อไป

Status: local-safe / staging-safe เท่านั้น — ไม่ deploy production/staging, ไม่เปิด
signup/AI จริง, ไม่ส่ง lead เอง, ไม่แตะ data model/security/privacy/dealer isolation

## ขอบเขตที่ลุงเด่นอนุมัติ (default ที่เสนอ)

1. กันคิวเฉพาะ **buyer-facing** (`ChatCarCard` + success reply) — ไม่แตะ seller panel/หลังบ้าน
2. การ์ด buyer: เลิกแสดง + เลิก fetch interest label — คง API/policy ไว้ให้ seller ใช้
3. memory v7.2 ใช้ **enrich preview context (display) เท่านั้น** — ห้ามแก้ payload จริง, ห้ามเป็น consent

## flow lead preview ปัจจุบัน (ของเดิมที่ใช้ต่อ — ปลอดภัยอยู่แล้ว)

1. เก็บฟิลด์ในแชท → `buyerLeadCaptureFlow.ts` (`collecting` → `ready_for_modal`)
2. preview (ข้อความ) → `buildBuyerLeadReadySummaryReply` (`buyerLeadCaptureCopy.ts`)
3. preview (modal) + final confirmation → `buildBuyerLeadModalPreview` (`buyerLeadPreview.ts`)
   แสดงใน `BuyerLeadConsentModal.tsx` — เบอร์โทรว่างเสมอ ลูกค้าพิมพ์เอง + ปุ่มยืนยัน
4. ส่งจริง → `submitBuyerLeadFromModal` (`buyerLeadCaptureHandler.ts`): บังคับ phone valid +
   `consentConfirmed=true` + signed-in → `createBuyerLeadFromChat` (ไม่ auto-send)

## เส้นแบ่ง memory ≠ consent ≠ payload (ยึดเคร่งครัด)

- memory ใช้แค่ **แสดง** ใน preview (`memoryHighlights`) — ไม่เคยถูกใส่ลง `draftToCreateInput`
- payload ที่ส่งจริง = draft fields + เบอร์ที่ลูกค้ากรอกเอง + `consentConfirmed` เท่านั้น
- การส่ง lead ยังต้องผ่าน modal + เบอร์เอง + กดยืนยัน → memory ไม่มีทางกลายเป็น consent/auto-send

## ความเสี่ยง / ผลกระทบ

- PDPA/privacy: ดีขึ้น (ตัดการโชว์จำนวนคิว/ผู้สนใจฝั่ง buyer; memory ไม่มี PII และเป็นของ session ลูกค้าเอง)
- lead revenue: ไม่กระทบ — คิวยังคำนวณ/จัดลำดับหลังบ้านเหมือนเดิม
- dealer isolation: ไม่แตะ seller routes/panel
- หมายเหตุ: แตะ `buyerLeadQueuePolicy.ts` เฉพาะ **ข้อความ buyer-facing** (ไม่ใช่ลอจิกคิว/รายได้)
