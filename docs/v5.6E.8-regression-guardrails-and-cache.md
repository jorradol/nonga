# v5.6E.8 — Regression Guardrails & Hosting Cache Fix

## Purpose

After v5.6E.5–E.7 (lead queue + layout + image display), staging showed occasional **stale `index.html`** after deploy (browser kept old hashed asset references → unstyled or broken UI). This release adds **hosting cache headers** and a **pre-deploy regression checklist** plus automated guards — no new product features.

## A) Firebase Hosting cache headers

| Path | Cache-Control | Why |
|------|---------------|-----|
| `/assets/**` | `public, max-age=31536000, immutable` | Vite emits fingerprinted JS/CSS; safe to cache long-term |
| `/index.html` | `no-cache` | Shell must revalidate after each deploy so it points at latest `/assets/*` |
| `/` | `no-cache` | **v5.6E.8a** — Firebase treats `/` separately from `/index.html`; without this, `GET /` kept default `max-age=3600` after E.8 deploy |

### v5.6E.8a — SPA deep-link routes (report only, not added yet)

Client routes such as `/chat`, `/my-listings`, `/marketplace` are served via the `** → /index.html` rewrite but **do not** match `/` or `/index.html` header rules. They may still receive Hosting’s default shell cache (~1h) until a follow-up adds either:

- explicit `no-cache` per high-traffic path (e.g. `/chat`, `/my-listings`, `/marketplace`), or
- a catch-all `source: "**"` `no-cache` **after** `/assets/**` so fingerprinted assets keep the more-specific immutable rule.

Do **not** apply `no-cache` on `/assets/**`. `/api/**` and `/storage/listings/**` use Cloud Run rewrites; avoid broad `**` headers until we confirm they do not alter API responses.

Static files are served from `dist/` (`public` in `firebase.json`). API and `/storage/listings/**` still use Cloud Run rewrites (unchanged).

## B) Pre-deploy regression checklist

Run on staging after deploy (hard refresh once: Ctrl+Shift+R or clear site data).

### Marketplace

- [ ] Card shows cover image or clear placeholder (not empty box)
- [ ] Card details and favorite still visible
- [ ] No lead queue UI on marketplace cards
- [ ] Buyer CTA in chat only — not on marketplace grid

### My Listings

- [ ] Cover image on each card (`ListingCoverImage`)
- [ ] Actions still present: แก้ไข, ซ่อน/แสดง, ดูในตลาด, ลบ
- [ ] Lead queue section **below** main row when leads exist
- [ ] No lead → **no** queue box/loading
- [ ] Queue does not hide or overlap image/actions

### Dealer — ประกาศที่ยังไม่ลงขาย (`/dealer/drafts`)

- [ ] Thumbnail on left of each draft card
- [ ] Edit opens gallery section; images still editable
- [ ] Publish guard labels unchanged (missing image, etc.)

### Dealer — รถที่ลงขายแล้ว (inventory)

- [ ] Thumbnail on left of each listing card

### Chat — ChatCarCard

- [ ] Image gallery visible
- [ ] “ให้ผู้ขายติดต่อกลับ” above expand button; does not cover gallery
- [ ] In-chat expand/collapse still works

### Buyer lead flow (staging)

- [ ] Natural Thai text parses (v5.6E.2)
- [ ] Phone only in consent modal (v5.6D.1)
- [ ] Queue position message after submit

### Seller queue

- [ ] Masked fields only — no full phone

### Cache / bundle

- [ ] Hard refresh → Network shows new `index-*.js` / `index-*.css` from latest deploy
- [ ] `/index.html` response has `Cache-Control: no-cache` (or revalidates)
- [ ] `GET /` (root) has `Cache-Control: no-cache` (v5.6E.8a)
- [ ] `/assets/*` responses allow long cache
