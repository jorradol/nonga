### 2.2 Image source / access (redacted)

| Pattern | Count (image slots) | Browser `<img>` hotlink |
|---------|---------------------|-------------------------|
| Google Drive `/file/d/.../view` share links | **39** | ❌ **not img-safe** |
| Google Drive `uc?export=view` | **0** in API | ✅ img-safe format |
| Firebase Storage | **0** | n/a |
| Local `/storage/listings/` | **0** | n/a |

**Conclusion:** Root cause = **Google Drive share page URLs** stored in `images[]` — browser cannot render as image src directly.

### 2.3 UI mapping

| Component | Field used | Issue |
|-----------|------------|-------|
| `ChatSidebarNewCarsSlider` | `resolveChatListingImageUrls` → `images[0]` | Raw Drive share URL passed to `<img>` |
| `buildSidebarNewCarsQueue` | `car.images` via chat inventory mapper | Same |
| Marketplace cards | `getListingPrimaryImage` | Same class of issue |

**Conclusion:** Field mapping ถูกต้อง (`images[0]`) — ปัญหาอยู่ที่ **URL format ไม่เหมาะกับ hotlink**

### 2.4 Fallback

## 3. Root Cause

```
Firestore images[] stores Google Drive share links (/file/d/ID/view)
    → GET /api/cars returns images[] unchanged (correct for storage)
    → Frontend passes share URL to <img src>
    → Browser cannot load Drive HTML page as image
    → Sidebar preview appears blank/broken
```

| Category | Classification |
|----------|----------------|
| Primary | **Image source/access** — Drive share link not display-normalized |
| Secondary | **UX** — sidebar lacked image error fallback |
| Not root cause | Data missing, wrong field name, API count, privacy leak |
