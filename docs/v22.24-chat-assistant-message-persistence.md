## 3) Reproduction (code-path)

1. Live session: orchestrator returns rich AI text + `carCards` → `finalizeStreamedReply` → `addMessage("ai", …)` → UI shows answer+cards.
2. `appendChatMessage` writes to Firestore; user messages (no nested undefined) succeed.
3. AI messages with `carCards` often include `undefined` optional fields (`color`, `fuelType`, …) → Firestore rejects write → catch falls back to **localStorage only**.
4. On reopen: `loadChatMessages` preferred Firestore docs when any existed → returned **user-only** set → assistant replies vanished.

**Affected:** both assistant text and car cards (same message document).

## 4) Fix

| Module | Change |
|--------|--------|
| `chatHistoryService.ts` | `stripUndefinedDeep` on Firestore message payload; `mergeChatMessagesById` so local-only AI replies rehydrate with Firestore users |
| `marketplaceChatSearch.ts` | omit undefined optional card fields at source |
| `buyerScoredMarketplaceSearch.ts` | omit undefined `fitReason` |
