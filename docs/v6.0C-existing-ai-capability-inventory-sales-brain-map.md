## 2. AI-as-Orchestrator Strategy (ใช้ของเดิม)

### หลักการ

| หลัก | รายละเอียด |
|------|------------|
| **AI เป็น orchestrator/adapter ไม่ใช่แหล่งข้อมูลหลัก** | AI อ่าน intent → เลือก tool/capability → สรุปผลลัพธ์ |
| **Facts ต้องมาจากระบบ** | listing facts, scoring, guards — ไม่ให้ AI สร้างเอง |
| **AI สรุป / ถามกลับ / เรียบเรียง** | ภาษาคน + Thai tone — ตัวเลข/รถมาจาก capability |
| **ข้อมูลไม่พอ → ถามเพิ่ม ไม่เดา** | ClarificationEngine เรียก parser ที่ได้ partial fields |
| **AI ปิด → fallback flow เดิม** | `chatSearchOrchestrator` + templates 100% |

### Sales Brain call flow (conceptual)

```
[User message]
      │
      ▼
[Intent router] ── (future AI layer or current orchestrator)
      │
      ├──► buyerSearchIntentParser ──► buyerScoredMarketplaceSearch
      ├──► chatBuyerFactsQa ──► buildChatCarFacts
      ├──► buyerLeadTextParser ──► BuyerLeadConsentModal (submit path)
      ├──► sellIntentParser + chatPrecheckLayer ──► publishMemberListingFromChat
      ├──► sellerShareCopy / thaiSalesCopyVariation
      ├──► columnMapping + prepareSmartInventoryImport (dealer/admin)
      └──► chatHelpOnboardingTemplates / chatMockFallback
      │
      ▼
[Output guards] ── facts-only, no hallucination, consent/privacy
      │
      ▼
[Reply to user] ── skipGemini:true paths unchanged today
```

### ไม่สร้าง AI chat แยก

- **ห้าม** parallel chat stack ที่ bypass orchestrator/lead/reveal routes
- **ให้** Sales Brain layer เป็น thin adapter บน `tryOrchestrateChatReply` + future mock/real provider (v6.0B)

## 10. Deterministic Fallback Chain

เมื่อ AI off / kill switch / provider blocked / guard fail:

```
1. chatSearchOrchestrator.tryOrchestrateChatReply (skipGemini: true)
2. Role templates (CAP-15)
3. chatMockFallback.buildMockChatReply
4. Static error copy
```

**v6.0C:** chain นี้ **มีอยู่แล้ว** — Sales Brain ต้อง delegate กลับมาที่ chain นี้ ไม่สร้าง fallback แยก
