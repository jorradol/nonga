## 1) Memory store ปัจจุบัน (v5.6I.4 audit)

### สิ่งที่ **ไม่ persist** (derive ทุกครั้ง)

| ข้อมูล | ที่มา | หายเมื่อ restart? |
|--------|-------|-------------------|
| Admin revenue preview rows | `deriveAdminRevenuePreviewRowsFromListings()` จาก inventory `pending_sale` | ไม่หาย (inventory อยู่ file/Firestore ตาม backend อื่น) แต่ **ไม่มี settlement record ถาวร** |
| Seller revenue statement rows | `buildSellerRevenuePreviewApiPayload()` — overlay + derive | เหมือนด้านบน |
| Success fee draft (closed_won) | `createSuccessFeeRecordDraft()` — **return null เมื่อ flag off** | ไม่ถูกสร้างใน runtime |

**ไฟล์หลัก:** `src/services/leads/adminRevenuePreview.ts`, `src/services/leads/revenuePreviewBackend.ts`

### สิ่งที่ persist **in-memory เท่านั้น** (หายเมื่อ Cloud Run restart)

| ข้อมูล | Store | ไฟล์ |
|--------|-------|------|
| Settlement adjustment state (overlay ต่อ listing) | `Map<listingId, SettlementAdjustmentState>` | `src/server/repositories/settlementAdjustmentRepository.ts` |
| Settlement adjustment audit entries | `SettlementAdjustmentAuditEntry[]` array | เดียวกัน |
| Success fee records (future) | `Map` in-memory repo (ยังไม่ wire routes) | `src/server/repositories/successFeeRecordRepository.ts` |

**Singleton:** `createSettlementAdjustmentRepository()` → `InMemorySettlementAdjustmentRepository` (default)

**API ที่เขียน memory:**

- `POST /api/admin/revenue/adjustments` → `adjustmentRepo.upsertState()` + `appendAudit()`
- `GET /api/admin/revenue/preview` / `GET /api/my/revenue/preview` → อ่าน overlay จาก repo แล้ว merge กับ derived rows

**ไฟล์ routes:** `src/server/revenuePreviewRoutes.ts`

### Feature flags ปัจจุบัน (ค่า default)

| Env | Default | ผล |
|-----|---------|-----|
| `NONGA_SUCCESS_FEE_RECORD_ENABLED` | **off** | ไม่ auto-create success fee บน closed_won |
| `NONGA_SETTLEMENT_DATA_BACKEND` | **memory** | adjustment repo = in-memory |
| `NONGA_SETTLEMENT_FIRESTORE_WRITES_ENABLED` | **off** | Firestore repo throw บน write |

## 5) Migration / Rollback plan

### Phase A — Staging enable (หลัง review)

1. Deploy `firestore.rules` พร้อม deny blocks + emulator tests
2. Set `NONGA_SETTLEMENT_DATA_BACKEND=firestore` (reads only ก่อน)
3. ยัง **ไม่** เปิด writes จนกว่า backfill script ผ่าน review

### Phase B — Backfill จาก `pending_sale`

1. `listAll()` inventory `saleStatus === pending_sale`
2. สำหรับแต่ละ listing:
   - ถ้ามี memory adjustment state → map เป็น `settlementAdjustments` + audit logs
   - ถ้าไม่มี → สร้าง `successFeeRecords` จาก `deriveAdminRevenuePreviewRowsFromListings` (estimated fee)
   - `leadId` จาก deal outcome ถ้ามี; ไม่ copy phone
3. Idempotent: doc id = `listingId` หรือ `preview-pending-{listingId}`

### Phase C — Cutover writes

1. `NONGA_SETTLEMENT_FIRESTORE_WRITES_ENABLED=true`
2. `NONGA_SUCCESS_FEE_RECORD_ENABLED=true` (เมื่อพร้อม closed_won auto-create)
3. Monitor audit consistency: ทุก adjustment ต้องมี audit log + before/after

### Rollback → memory-only

1. Set `NONGA_SETTLEMENT_DATA_BACKEND=memory`
2. Set `NONGA_SETTLEMENT_FIRESTORE_WRITES_ENABLED=false`
3. Restart Cloud Run — overlay เริ่มว่าง; preview กลับ derive-only
4. Firestore data คงอยู่ (read-only archive) จนกว่าจะ backfill กลับหรือ re-enable

### Multi-instance Cloud Run risk

| ความเสี่ยง | Memory (ปัจจุบัน) | Firestore (อนาคต) |
|-----------|-------------------|-------------------|
| Lost writes on restart | ✓ สูง | ต่ำ |
| Split-brain ระหว่าง instances | ✓ สูง — แต่ละ instance มี Map คนละชุด | ต่ำ — single source |
| Concurrent admin adjustments | last-write-wins ใน memory | ใช้ transaction + `updatedAt` check |

**Mitigation ก่อน durable:** จำกัด staging เป็น 1 instance หรือยอมรับว่า adjustment หายหลัง restart

### Audit consistency check

```text
สำหรับแต่ละ listingId:
  latest adjustment doc.remainingAmount === last audit.after.remainingAmount
  audit chain monotonic createdAt
  ไม่มี buyer PII ใน JSON export
```

### Flag kill-switch

```text
NONGA_SETTLEMENT_FIRESTORE_WRITES_ENABLED=false  → หยุด write ทันที
NONGA_SETTLEMENT_DATA_BACKEND=memory           → กลับ overlay in-process
NONGA_SUCCESS_FEE_RECORD_ENABLED=false         → หยุด auto-create closed_won
```
