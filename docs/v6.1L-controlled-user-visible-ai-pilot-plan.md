## 5. Multi-layer Guardrail Design

Controlled user-visible pilot ต้องผ่าน **ทุก layer** ก่อนแสดง AI response ให้ tester — ถ้า layer ใด fail → **fallback legacy ทันที**

```
┌─────────────────────────────────────────────────────────────┐
│ L1  environment !== "production"  → production always off   │
├─────────────────────────────────────────────────────────────┤
│ L2  NONGA_AI_EMERGENCY_KILL_SWITCH !== true                 │
├─────────────────────────────────────────────────────────────┤
│ L3  NONGA_AI_USER_VISIBLE_ENABLED === true (staging only)   │
├─────────────────────────────────────────────────────────────┤
│ L4  SALES_BRAIN_V60R_USER_VISIBLE_BLOCKED === false         │
│     (lift only in approved v6.1L.1 code slice)              │
├─────────────────────────────────────────────────────────────┤
│ L5  NONGA_AI_PROVIDER=gemini + shadow prerequisites         │
│     (mode, ai-first, budgets present)                       │
├─────────────────────────────────────────────────────────────┤
│ L6  Allowlist gate — Firebase UID ∈ allowlist               │
│     (guest / anonymous → always legacy)                     │
├─────────────────────────────────────────────────────────────┤
│ L7  Budget caps respected — daily/monthly limits            │
├─────────────────────────────────────────────────────────────┤
│ L8  No payment/lead/reveal/outcome side effects from AI path│
└─────────────────────────────────────────────────────────────┘
         │ any layer fails
         ▼
   legacy user-visible response (exact orchestrator text)
```

### Layer interaction rules

| Rule | Detail |
|------|--------|
| Kill switch precedence | L2 blocks ก่อน provider network — validated CP-02 v6.1K.5 |
| Allowlist default-deny | ไม่อยู่ใน allowlist = legacy 100% แม้ L3-L4 เปิด |
| Guest always legacy | ไม่มี Firebase UID → ไม่ผ่าน L6 |
| Shadow sink unchanged | Admin CP-02 sink path ยังแยกจาก user-visible path |
| No public endpoint | ไม่มี public route สำหรับเปิด user-visible โดยตรง |

## 6. Allowlist / Tester-only Gate Design

### Proposed env (v6.1L.1 implementation — not set in v6.1L)

```
NONGA_AI_USER_VISIBLE_ALLOWLIST_UIDS=<uid1>,<uid2>,<uid3>
```

| Property | Design |
|----------|--------|
| **Scope** | staging Cloud Run env only |
| **Format** | comma-separated Firebase Auth UIDs — **no phone numbers, no emails in env** |
| **Default** | absent or empty → **no user sees AI** (legacy only) |
| **Who adds testers** | ops/admin via controlled env update — documented in execution record |
| **Max testers** | recommend **≤ 5** UIDs for first pilot |
| **Guest users** | never in allowlist — always legacy |
| **Dealer/public at large** | not in allowlist → legacy |

### Server-side evaluation (proposed v6.1L.1)

```typescript
// Pseudocode — NOT implemented in v6.1L planning slice
function isUserVisibleAiAllowedForUid(uid: string | undefined, env: Env): boolean {
  if (!uid) return false;
  const allowlist = parseCommaSeparatedUids(env.NONGA_AI_USER_VISIBLE_ALLOWLIST_UIDS);
  if (allowlist.length === 0) return false;
  return allowlist.includes(uid.trim());
}
```

### Client bundle rules (proposed)

| Rule | Detail |
|------|--------|
| No hardcoded tester UIDs in client | allowlist server-only |
| No `userVisible=true` in client env | flags from server runtime only |
| `wireShadowChatPath` | ยัง legacy for non-allowlisted; future slice may add server-mediated path only |
| Debug flags in browser | flags-only summary — no provider output to console for public |

### Tester onboarding (future execution only)

| Step | Action |
|------|--------|
| 1 | สร้าง Firebase Auth test account บน staging — synthetic email pattern เท่านั้น |
| 2 | บันทึก UID ใน execution record — **ไม่บันทึก password/secret** |
| 3 | เพิ่ม UID ใน `NONGA_AI_USER_VISIBLE_ALLOWLIST_UIDS` พร้อม env update record |
| 4 | ยืนยัน tester เห็น AI เฉพาะเมื่อผ่าน §7 pre-pilot checklist |
| 5 | ถอด UID จาก allowlist เมื่อจบ pilot — rollback §10 |
