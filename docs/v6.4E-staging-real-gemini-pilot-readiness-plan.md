## 4. Staging Real Provider Gate

Real Gemini เปิดได้ **เฉพาะ staging** และ **เฉพาะเมื่อครบทุกข้อ**:

| # | Gate | Requirement | v6.4E |
|---|------|-------------|-------|
| G-01 | Environment | `environment === "staging"` | plan only |
| G-02 | Provider status | `providerStatus === "STAGING_REAL"` | plan only — default **OFF** |
| G-03 | Superadmin approval | `stagingApprovalGranted === true` | future readiness only |
| G-04 | Allowlist | approved tester UIDs configured (masked in audit) | future readiness only |
| G-05 | Daily cap | `dailyRequestCap !== null` | **unset blocks real** |
| G-06 | Per-surface cap | `perSurfaceCaps[surfaceId] !== null` for pilot surfaces | **unset blocks real** |
| G-07 | Per-user/session cap | `perUserSessionCap !== null` | **unset blocks real** |
| G-08 | Kill switch | `killSwitch.active === false` | default off |
| G-09 | Output guard | `AI_OUTPUT_GUARD_POLICY` active, `onFail: deterministic` | ✅ defined v6.4B |
| G-10 | Deterministic fallback | active on guard fail / cap / error | ✅ defined |
| G-11 | Prompt/data boundary | allowed fields only | ✅ defined v6.4B |
| G-12 | Audit logging | redacted fields only | plan defined §9 |
| G-13 | Production forbidden | `isProductionRealProviderForbidden("production") === true` | ✅ static guard |

### Static guard reference

```typescript
isStagingRealProviderAllowed({
  environment: "staging",
  stagingApprovalGranted: true,
  allowlistConfigured: true,
  capsConfigured: true,
  killSwitchActive: false,
}) // → true only when ALL true
```

**Cap unset rule:** ถ้า `dailyRequestCap === null` หรือ `perUserSessionCap === null` หรือ pilot surface cap unset → **`capsConfigured: false`** → real provider **blocked**

**Default:** `DEFAULT_AI_PROVIDER_STATUS = "OFF"` — ไม่เปลี่ยนใน v6.4E

## 10. Rollback / Kill Switch

| Trigger | Action |
|---------|--------|
| Kill switch ON | **Immediate OFF** — `resolveEffectiveProviderStatus` → `DISABLED` |
| Cap exceeded | Deterministic fallback |
| Guard fail | Deterministic fallback |
| Provider error | Deterministic fallback |
| Suspicious output | Deterministic fallback + flag issue |
| Production environment | **Hard block** — real provider never allowed |

Kill switch authority: **superadmin only** (`triggerKillSwitchReadiness`)  
Admin: view status/readiness only — **cannot trigger kill switch**

Fallback chain (same as v6.4D):

1. Detect trigger (cap / guard / error / kill switch)
2. Skip real provider call
3. Return deterministic copy via buyer-friendly / golden seller helpers
4. Record redacted audit with `fallbackReason`
