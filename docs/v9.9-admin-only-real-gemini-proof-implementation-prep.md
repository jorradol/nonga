# v9.9 Admin-Only Real Gemini Proof Implementation Prep

> **IMPLEMENTATION PREP ONLY / ADMIN-ONLY MANUAL PROOF BOUNDARY / FAIL-CLOSED BY DEFAULT**
> v9.9 รอบนี้เป็นการเตรียม implementation path สำหรับ future real Gemini proof แบบ admin-only/manual-proof เท่านั้น โดยยังไม่เปิด buyer-facing AI และยังไม่เปิด production/public route/deploy

---

## 1. Scope of v9.9

- เพิ่ม guard state สำหรับเส้นทาง future real provider proof แบบแคบที่สุด
- คง default/normal path ให้ disabled และ deterministic เป็น source of truth
- คุมเงื่อนไขก่อน real provider call ให้ fail-closed ทุกชั้น
- เพิ่ม deterministic fallback เมื่อ provider ไม่พร้อมหรือ fail
- เพิ่ม test v9.9 เพื่อยืนยัน safety boundaries

## 2. Explicit Non-GO Confirmation

v9.9 ยังเป็น:

- NOT GO for production
- NOT GO for deploy
- NOT GO for buyer-facing AI
- NOT GO for user-visible AI
- NOT GO for public route
- NOT GO for real lead sending
- NOT GO for default runtime/provider activation

## 3. Guard Model Introduced in v9.9

real provider call จะเกิดได้ในอนาคตก็ต่อเมื่อผ่านครบทุก guard เท่านั้น:

- default OFF baseline (`AI_RUNTIME_PROOF_ENABLED` ต้องไม่เปิดเองใน normal path)
- kill switch wins all flags (`AI_RUNTIME_PROOF_KILL_SWITCH` ชนะทุกกรณี)
- admin-only boundary required
- owner approval flag required (`AI_RUNTIME_PROOF_OWNER_APPROVED_MODE`)
- manual proof mode required (`AI_RUNTIME_PROOF_MANUAL_PROOF_MODE`)
- env-secret only (`GEMINI_API_KEY` from environment only, placeholder ใช้ไม่ได้)
- quota guard + cost guard ready
- real-provider quota cap ready
- logging redaction guard ready
- dry-run gate passed before real provider call eligibility
- explicit activation flag required for manual proof (`AI_RUNTIME_PROOF_REAL_PROVIDER_ACTIVATION`)

ถ้าไม่ผ่านข้อใดข้อหนึ่ง:

- `realProviderCallAllowed` ต้องเป็น false
- `effectiveProviderEnabled` ต้องไม่เปิดใน default/normal path
- deterministic fallback ต้องพร้อมเสมอ

## 4. Dry-Run and Manual-Proof Relationship

- dry-run gate ยังคงเป็น safety prerequisite
- manual/admin-only proof path เป็น future implementation path แบบคุมเข้ม
- normal path ยังไม่เรียก real provider และยังไม่เปิด network/provider call
- test ปกติไม่ต้องใช้ secret จริง และต้องไม่ยิง Gemini จริง

## 5. Logging Redaction and Secret Safety

logging redaction ต้องปกป้อง:

- raw prompt
- phone
- VIN
- bearer token
- token-like value
- secret-like assignment

และต้องยืนยันว่า:

- no real API key/secret in repo
- no normal test depends on real secret
- no network/provider call in normal tests

## 6. Buyer/Public Isolation and Deterministic Truth

- buyer/public path ไม่มีทางเข้าถึง admin runtime-proof guard path
- ไม่เพิ่ม public route ใหม่
- ไม่เปลี่ยน buyer/public orchestrator flow
- deterministic flow remains source of truth
- real lead sending ไม่เกี่ยวข้องและยังปิดอยู่

- no network/provider call in normal test
