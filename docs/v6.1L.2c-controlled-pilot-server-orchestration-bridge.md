## Architecture (เลือกแบบนี้และทำไม)

| ทางเลือก | เหตุผล |
|----------|--------|
| **Authenticated POST `/api/ai/chat-user-visible-orchestrate`** | `NONGA_AI_*` อยู่บน Cloud Run เท่านั้น — server อ่าน env + allowlist gate; client ส่ง Bearer token เท่านั้น |
| **ไม่ส่ง `firebaseUid` จาก client** | UID มาจาก `getServerAuthContext` / verified token เท่านั้น — client-supplied UID ไม่ถูกเชื่อ |
| **Browser `wireShadowChatPath` คง flags-only** | ไม่ import pilot resolver ใน Vite bundle — ไม่ทำลาย browser-safe guard |
| **Client bridge ปรับ `orchestrated.text` หลัง local orchestrator** | คง car cards / draft UI จาก client; server ปรับ user-visible text เมื่อ auth สำเร็จ |

### Flow

1. Guest → client `tryOrchestrateChatReply` only (legacy 100%)
2. Signed-in → client orchestrate แล้วเรียก bridge (Bearer)
3. Server → auth → inventory → `tryOrchestrateChatReplyCore` → `wireShadowChatPathWithPilot` → redacted JSON
4. Bridge fail / 401 → client ใช้ legacy text เดิม

## Route

- `POST /api/ai/chat-user-visible-orchestrate`
- Auth: Firebase Bearer (required) — 401 ถ้าไม่มี token
- Body: `{ userMessage, attachedImageCount? }` — **ห้าม** `firebaseUid`
- อยู่ใต้ `registerAiEndpointGuards` (rate limit)
- Production environment → legacy only (no pilot)
