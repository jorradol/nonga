## 5) Root cause

Duplicate cleanup copied durable Firebase Storage URLs from newer duplicate listing ids (`car-import-1783565788477-p*`) onto canonical ids (`car-import-1783556891631-p*`). Object paths still contain the **prior** listing id.

- Marketplace/detail: `isValidListingImageUrl` accepts any non-stock HTTPS URL → image shows.
- Chat: `resolveChatListingImageUrls` had an **extra** Firebase path filter requiring the URL to contain the **current** listing id → all 3 Thor cards dropped every image → empty gallery (“ยังไม่มีรูปในระบบ”).

Not caused by low image count on MAZDA (2 images is enough). Not a content-type / query-param rejection. All three Thor chat cards were affected, not only MAZDA.

## 6) Fix

| Surface | Before | After |
|---------|--------|-------|
| Chat image source | `collectListingImageCandidates` + `isValidListingImageUrl` **plus** Firebase listing-id path guard | Same candidate order + `isValidListingImageUrl` only (aligned with marketplace) |
| Cover fallback | ignored unless already in `images[]` | `coverImage` / legacy fields via shared collectors |
| Placeholder | chat never shows Unsplash | unchanged (still no Unsplash in chat) |
| Chat `<img>` | no `referrerPolicy` | `referrerPolicy="no-referrer"` (match marketplace) |
| Public DTO | address fields not in contact redact list | `address` / `ownerAddress` redacted |
