## A) Persistence path audit (เมื่อเปิด `NONGA_LEAD_DATA_BACKEND=firestore`)

ทุก HTTP path ใช้ `createBuyerLeadRepository()` → `FirestoreBuyerLeadRepository` (Admin SDK บน Cloud Run). **ไม่มี** client SDK อ่าน `buyerLeads` โดยตรงในปัจจุบัน

| # | คำถาม | คำตอบ |
|---|--------|--------|
| 1 | **Create buyer lead** เขียนที่ไหน | `POST /api/buyer-leads` → `createConsentedBuyerLead` → `repository.createBuyerLead(lead)` → collection **`buyerLeads`**, doc id = `lead.id` (`blead-…`) |
| 2 | **queuePosition** คำนวณจากอะไร | `assignQueuePositionOnCreate` → `listBuyerLeadsByListingId(listingId)` จาก Firestore query `listingId == …` → `computeNextQueuePosition` (active lifecycle + max position + 1) |
| 3 | **Seller queue GET** อ่านจากไหน | `GET /api/seller/listings/:listingId/buyer-lead-queue` → `getSellerMaskedQueueForListing` → `listBuyerLeadsByListingId` → **`toSellerMaskedQueue`** (mask ก่อนส่ง JSON) |
| 4 | **skip / reveal / outcome** อัปเดต doc ไหน | `getBuyerLeadById` + `updateBuyerLead` บน **`buyerLeads/{leadId}`**; skip ตั้ง `queueLifecycle=withdrawn`, `buyerQueueFeedback`; reveal ตั้ง `contactRevealStatus`, `contactRevealedAt` |
| 5 | **Contact logs** เขียนที่ไหน | `appendContactLog` → **`leadContactLogs/{logId}`** (consent, reveal, outcome, skip) |
| 6 | **contactPhone** เก็บที่ไหน | ฟิลด์ในเอกสาร **`buyerLeads`** เท่านั้น (ไม่มีใน `buyerPurchaseProfiles`) |
| 7 | **API redaction** | ดูตารางด้านล่าง |

### API response redaction (ไม่เปลี่ยนเมื่อ backend = firestore)

| Route | ผู้เรียก | สิ่งที่ส่งกลับ |
|-------|---------|----------------|
| `POST /api/buyer-leads` | Buyer (auth) | `data: toPublicBuyerLead(lead, **buyer_self**)` — buyer เห็นเบอร์ตัวเอง; ไม่ส่ง lead คนอื่น |
| `GET /api/buyer-leads/:id` | Buyer self / seller / admin | `toPublicBuyerLead` ตาม `resolveBuyerLeadViewerRole`: **buyer_self** & **admin** = เบอร์จริง; **listing_seller** = mask; **public** = 403 |
| `GET …/interest-queue-stats` | Public | `{ interestCount }` เท่านั้น — `publicQueuePayloadHasNoOtherBuyerPii` guard |
| `GET …/buyer-lead-queue` | Listing owner / admin | `SellerMaskedQueueEntry[]` — `maskBuyerContact(revealContact: false)`, `canRevealContact: false` (MVP) |
| `POST …/skip` | Seller | `{ leadId, buyerQueueFeedback, nextRevealableLeadId }` — **ไม่มี** `contactPhone` |
| `POST …/reveal` | Seller | `{ leadId }` เท่านั้น — **ไม่คืนเบอร์ใน body** (UI ยังไม่เปิด reveal เต็ม) |
| `POST …/outcome` | Seller | `{ leadId, nextRevealableLeadId }` — ไม่มี PII |

## C) Firestore security rules — **draft only** (ยังไม่ deploy)

**ปัจจุบัน:** `firestore.rules` ไม่มี match สำหรับ lead collections → fallback `match /{document=**} { allow read, write: if false; }` → client **อ่าน/เขียนไม่ได้** (ปลอดภัยระหว่างรอ draft)

### หลักการ (8 ข้อ)

1. Public client **ห้าม** `get/list` `buyerLeads`  
2. Buyer **ห้าม**อ่านเบอร์/แถวของ buyer คนอื่น (ใช้ API + `toPublicBuyerLead` เท่านั้น)  
3. Seller **ห้าม**อ่าน `contactPhone` จาก Firestore client — คิว masked ผ่าน Cloud Run เท่านั้น  
4. Seller queue **เฉพาะ** `/api/seller/listings/.../buyer-lead-queue`  
5. Admin ผ่าน admin API / Admin SDK — ไม่เปิด collection กว้างให้ role admin ใน rules โดยไม่จำกัด field  
6. `leadContactLogs` — **deny all** client read/write  
7. `buyerPurchaseProfiles` — owner read/write จำกัด field **หรือ** deny client แล้วใช้ server API เท่านั้น (แนะนำ deny client ในเฟสแรก)  
8. **ห้าม** `allow read, write: if true`

### Rules implementation (v5.6F.2 — ใน repo, ยังไม่ deploy)

Merged into `firestore.rules.draft` and `firestore.rules`. Details: [v5.6F.2](./v5.6F.2-firestore-lead-rules.md).
