## 1. Vision & ขอบเขต v6.0G

### เป้าหมาย

เตรียม **shadow mode** สำหรับ Sales Brain integration โดย:

1. รับ chat message input แบบเดียวกับที่ legacy flow ใช้
2. เรียก **Sales Brain adapter (mock provider เท่านั้น)** คู่ขนาน
3. **compare** legacy route label vs Sales Brain intent
4. ส่งออก **`shadowDebugResult` / `shadowEvaluation`** สำหรับ test/log/debug
5. **`userVisibleResponse` ต้องมาจาก legacy flow เดิม** — shadow ห้ามแตะ

| ทำ (รอบนี้) | ไม่ทำ (รอบนี้) |

| Offline test script | fetch network |
| Legacy vs Sales Brain compare design | เปลี่ยน user-visible chat response |
| PII-safe shadow logs | เปิด AI First จริง |
| Production default off | real AI provider |
| | settlement/payment write |
| | แก้ buyer lead / reveal / outcome |
| | เปิด public signup |

## 2. Shadow Mode คืออะไร

### หลักการ

```
User message
     │
     ├─► Legacy flow (useChat + chatSearchOrchestrator) ──► userVisibleResponse  ◄── ผู้ใช้เห็นแค่นี้
     │
     └─► Shadow path (v6.0G — parallel, optional)
              │
              ▼
         Sales Brain adapter (mock only)
              │
              ▼
         shadowDebugResult / shadowEvaluation  ◄── test/log/debug เท่านั้น
```

| หลักการ | รายละเอียด |
|---------|------------|
| **Shadow = คิดคู่ขนาน** | วิเคราะห์ intent/capability โดยไม่ส่งผลให้ผู้ใช้ |
| **User-visible ไม่เปลี่ยน** | `userVisibleResponse === input.legacyUserVisibleResponse` เสมอ |
| **Mock provider only** | `createSalesBrainAdapter({ provider: "mock" })` — ไม่เรียก real |
| **Disabled by default** | `SALES_BRAIN_SHADOW_MODE_DEFAULT_ENABLED = false` |
| **Production off** | แม้ flag เปิด  production บังคับ off |

## 3. Architecture (not wired)

### Module: `src/services/ai/salesBrainShadowMode.ts`

| Function | บทบาท |
|----------|--------|
| `resolveSalesBrainShadowModeEnabled()` | ตัดสินเปิด shadow หรือไม่ (production = off) |
| `inferLegacyRouteLabel()` | label สำหรับ legacy route (deterministic, ไม่ invoke orchestrator) |
| `compareLegacyVsSalesBrainRoute()` | เปรียบ legacy label vs Sales Brain intent |
| `evaluateSalesBrainShadowMode()` | entry point — คืน shadow evaluation + userVisibleResponse ไม่เปลี่ยน |

### Not wired guarantee

- **`useChat.ts`** — ไม่ import `salesBrainShadowMode`
- **`chatSearchOrchestrator.ts`** — ไม่ import `salesBrainShadowMode`
- ไม่มี runtime path เรียก shadow ใน v6.0G

## 4. Shadow Input / Output Contract

### Input (`SalesBrainShadowInput`)

| Field | Type | รายละเอียด |
|-------|------|------------|
| `userMessage` | string | ข้อความผู้ใช้ |
| `userRole` | role | buyer / seller / dealer / admin / superadmin |
| `flowContext` | object? | session/listing/image context |
| `listingContext` | object? | listing facts from system only |
| `legacyUserVisibleResponse` | string | **คำตอบจาก legacy flow — shadow ห้ามแก้** |
| `shadowModeEnabled` | boolean? | default `false` |
| `environment` | `"production"` \| `"staging"` \| `"local"` | production บังคับ off |
| `aiMode` | mode? | shadow ใช้ mock high สำหรับ compare |
| `aiFirstEnabled` | boolean? | optional — undefined = mock routes at high for compare; legacy AI First still off |
| `emergencyKillSwitch` | boolean? | จาก v6.0B design |

### Output (`SalesBrainShadowEvaluation`)

| Field | Type | รายละเอียด |
|-------|------|------------|
| `shadowModeActive` | boolean | shadow ทำงานหรือถูก skip |
| `skippedReason` | string? | e.g. `shadow_mode_disabled`, `production_shadow_disabled` |
| `userVisibleResponse` | string | **ต้องเท่ากับ input.legacyUserVisibleResponse เสมอ** |
| `shadowDebugResult` | object? | มีเมื่อ shadow active |

### `shadowDebugResult`

| Field | รายละเอียด |
|-------|------------|
| `salesBrainIntent` | intent จาก adapter mock |
| `legacyRouteLabel` | label จาก `inferLegacyRouteLabel` |
| `routesAlign` | legacy vs Sales Brain สอดคล้องหรือไม่ |
| `provider` | **`mock` only** |
| `routedVia` | mock / fallback |
| `selectedCapabilities` | CAP IDs |
| `safetyDecision` | allow / no_go / askFollowUp |
| `paramsHash` | hash ไม่มี raw PII |
| `comparisonNotes` | redacted notes |

## 5. Legacy vs Sales Brain Comparison

### Legacy route labels (deterministic)

| Label | Typical user message | Expected Sales Brain intent |
|-------|---------------------|----------------------------|
| `legacy.tryOrchestrateChatReply.buyer_search` | งบ 4 แสน มีรถอะไรน่าเล่น | `buyer.search` |
| `legacy.tryOrchestrateChatReply.buyer_finance_negotiate` | คันนี้ผ่อนได้ไหม | `buyer.finance_negotiate` |
| `legacy.tryOrchestrateChatReply.seller_image_draft` | ลงขายจากรูป | `seller.image_draft` |
| `legacy.tryOrchestrateChatReply.seller_marketing_copy` | เขียนโพสต์ขาย | `seller.marketing_copy` |
| `legacy.tryOrchestrateChatReply.dealer_import` | ไฟล์รถ เอาเข้า | `dealer.import` |
| `legacy.tryOrchestrateChatReply.dealer_suggested_reply` | ตอบลูกค้า | `dealer.suggested_reply` |
| `legacy.tryOrchestrateChatReply.admin_ai_mode` | ดูสถานะ AI mode | `admin.ai_control_readonly` |
| `legacy.tryOrchestrateChatReply.admin_revenue_readonly` | รายได้เดือนนี้ | `admin.revenue_readonly` |
| `legacy.tryOrchestrateChatReply.fallback` | อื่นๆ / fallback | fallback / unknown / blocked |

### askFollowUp / no listing

เมื่อ buyer ถาม finance โดยไม่มี listing context → Sales Brain คืน `askFollowUp` — legacy ยังใช้ template/orchestrator — shadow บันทึก `routesAlign` และ `comparisonNotes` โดยไม่เปลี่ยน user-visible response

## 6. Flag Design (future — disabled by default)

> **v6.0G ยังไม่ wire flag ลง runtime หรือ Cloud Run**

| Flag (future) | Default | ความหมาย |
|---------------|---------|----------|
| `NONGA_AI_SALES_BRAIN_SHADOW_MODE` | `false` | เปิด shadow evaluation คู่ขนาน |
| `NONGA_AI_MODE` | `off` (prod) | shadow ไม่แทน AI mode จริง |
| `NONGA_AI_FIRST_ENABLED` | `false` | ยังไม่เปิด AI First จริง |
| `NONGA_AI_PROVIDER` | `mock` | shadow อนุญาต mock only |

### Safe defaults

| Environment | Shadow | User-visible |
|-------------|--------|--------------|
| **production** | **off (hard)** | legacy only |
| **staging** | off (future: opt-in flag) | legacy only |
| **local** | off (future: dev opt-in) | legacy only |

## 7. Safety & PII Rules

| Rule | รายละเอียด |
|------|------------|
| **No raw PII in shadow logs** | phone/email redacted via `redactPiiForSalesBrainLog` |
| **paramsHash only** | ไม่ log raw message ใน production shadow sink |
| **No contact reveal** | shadow ไม่ expose phone/contact |
| **No hallucination path** | listingContext ไม่พอ → askFollowUp ใน Sales Brain branch only |
| **User-visible unchanged** | shadow output แยกจาก visible response |

## 8. No-Go Zones in Shadow

Shadow evaluation ใช้ adapter mock ที่ inherit no-go จาก v6.0D/E/F:

| Zone | Shadow behavior |
|------|-----------------|
| revenue write | `blocked.no_go`, fallback |
| settlement write | `blocked.no_go` |
| payment | `blocked.no_go` |
| invoice | `blocked.no_go` |
| contact reveal without consent | `blocked.no_go` |
| submit lead without consent | `blocked.no_go` |
