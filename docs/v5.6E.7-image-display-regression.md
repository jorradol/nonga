# v5.6E.7 — Image Display Regression Audit & Restore

## Root causes

1. **Dealer drafts / dealer inventory list cards** never rendered a cover `<img>` — only text and actions. Images were only visible inside the edit panel (`DealerDraftImageSection`). This looked like “รูปหาย” on ประกาศที่ยังไม่ลงขาย.

2. **Listing image helpers** only read `images[]`. Legacy rows with `coverImage`, `imageUrl`, `imageUrls`, or `gallery` were ignored after normalize, so some marketplace/draft records could end up with an empty gallery until placeholder.

3. **Chat search** used `url.includes(car.id)` on encoded Firebase URLs; replaced with `listingImageUrlReferencesListing` (decode-aware). Collects from all image fields via `collectListingImageCandidates`.

4. **Broken remote URLs** showed a blank box. `ListingCoverImage` falls back to the intentional placeholder on `onError`.

Marketplace API data on staging already contained valid Firebase URLs; missing thumbnails on draft lists and strict field merging were the main fix targets.

## Changes

- `src/utils/listingImages.ts` — `collectListingImageCandidates`, `mergeListingRecordImages`, `listingImageUrlReferencesListing`
- `src/utils/marketplaceCarMapper.ts` — merge all image fields before sanitize
- `src/components/listings/ListingCoverImage.tsx` — shared cover + fallback
- `MarketplaceView`, `MyListingsView`, `DealerDraftsPage`, `DealerInventoryPage` — use `ListingCoverImage`
- `marketplaceChatSearch.ts` — shared image collection + listing id check

Lead queue remains additive; no API/rules/env changes.
