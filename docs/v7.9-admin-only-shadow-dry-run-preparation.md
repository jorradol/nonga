## 4. Gate B Readiness Checklist (Secret / Budget / Kill switch readiness)

checklist ความพร้อม **ก่อน** ขอผ่าน Gate B — แต่ละข้อ `[ ]` = ยังไม่ผ่าน, เป็น preparation เท่านั้น (ยังไม่ทำจริงในรอบนี้):

### 4.1 Secret wiring plan
- [ ] **secret wiring plan** — Gemini API key ผ่าน Secret Manager เท่านั้น (ไม่อยู่ใน frontend / repo / env ที่ commit)
- [ ] **no real secret in repo** — repo / docs / scripts ห้ามมีค่า secret / API key จริง (static validation บังคับ)
- [ ] **secret access boundary** — เฉพาะ runtime service account ฝั่ง server เท่านั้นที่อ่าน secret ได้, frontend / buyer / public อ่านไม่ได้

- [ ] **rollback if secret wiring fails** — ถ้า wiring secret ล้มเหลว ⇒ ระบบ fallback เป็น deterministic (fail-closed) โดยไม่ crash flow, และถอน wiring ได้โดยไม่กระทบ staging runtime `92d0dac`

## 6. Budget / Quota Cap Readiness

checklist ความพร้อมด้านงบ/โควต้า **ก่อน** activation (preparation — ยังไม่ตั้งค่าจริง, ยังไม่เปิดใช้งานจริง):

## 7. Kill Switch Drill Readiness

checklist ความพร้อมการซ้อม kill switch **ก่อน** activation (preparation — ยังไม่รัน drill จริง):

- [ ] **what switch stops AI** — ระบุชัดว่า flag ใดตัด AI กลับ deterministic (เช่น `NONGA_AI_EMERGENCY_KILL_SWITCH`)
- [ ] **how to verify switch** — ขั้นตอนยืนยันว่าเมื่อ switch = on ระบบกลับเป็น deterministic 100% (ไม่มี AI path เหลือ)
- [ ] **what evidence must be captured** — เก็บหลักฐาน sanitized (timestamp, scenario id, ผล before/after, reason code) ว่าตัดสำเร็จ
- [ ] **fallback after switch off** — เมื่อ kill switch ทำงาน ⇒ ทุก flow กลับเป็น deterministic, ไม่มี user-visible / buyer-facing AI หลงเหลือ

## 8. Fallback Deterministic Proof

checklist พิสูจน์ว่าทุก failure path fallback เป็น deterministic (fail-closed) — เป็น preparation, ยังไม่รันจริง:

- [ ] **AI fail** — เมื่อ AI error / ไม่ตอบ ⇒ fallback deterministic
- [ ] **timeout** — เมื่อเกิน timeout cap ⇒ fallback deterministic
- [ ] **blocked output** — เมื่อ output ถูก policy block ⇒ fallback deterministic
- [ ] **unsafe output** — เมื่อ output ไม่ปลอดภัย (PII / ทะเบียน / VIN / ราคาภายใน) ⇒ block + fallback deterministic
- [ ] **hallucination risk** — เมื่อ AI เสี่ยงแต่งข้อมูลรถที่ไม่มีใน inventory ⇒ fallback deterministic, inventory จริงเป็น source of truth
- [ ] **policy uncertainty** — เมื่อไม่แน่ใจว่า output ผ่าน policy ⇒ fail-closed กลับ deterministic

## 14. Stop Condition / Rollback Preparation

- **Stop condition (รอบอนาคตเมื่อซ้อม shadow):** ถ้าพบ buyer เห็น AI output, PII หลุด, prompt injection สำเร็จ, cost/quota เกิน cap, หรือ fallback ไม่ทำงาน ⇒ **สั่ง kill switch ทันที** (`NONGA_AI_EMERGENCY_KILL_SWITCH=true`) ตัดกลับ deterministic
- **Rollback (รอบ v7.9 นี้):** v7.9 เป็น docs-only ไม่มี runtime change / ไม่มี deploy ⇒ **ยังไม่มีอะไรต้อง rollback**; ถ้าต้องถอนเอกสารทำได้ด้วย git revert ระดับ docs โดยไม่กระทบ runtime / staging
- **Rollback preparation (เมื่อ wiring secret/shadow ในอนาคต):** ปิด flag ⇒ ระบบกลับเป็น deterministic 100%; staging runtime `92d0dac` ไม่ถูกแตะจาก shadow path; ถอน secret wiring ได้โดยไม่กระทบ flow
- หลัง stop: review root cause แบบ sanitized ก่อนพิจารณาเปิดใหม่ — ต้องผ่าน owner sign-off อีกครั้ง
