## 4. Archive / Hide / Deactivate Strategy

Per v6.2B.7 preferred strategy — **rollbackable first, no hard delete**:

| Priority | Strategy | Mechanism | Rollback |
|----------|----------|-----------|----------|
| 1 | **hide** | `listingStatus=hidden` | restore `published` from backup |
| 2 | **archive flag** | metadata flag `archived=true` or equivalent | clear flag from backup |
| 3 | **deactivate** | exclude from marketplace query without delete | re-enable from backup |
| 4 | **hard delete** | ❌ **not in initial cleanup** | separate approval later |

### Execution principles

- Apply to **candidate cohort count 17** only — exclude any future real pilot batch
- **No mutation** of buyerLead / reveal / outcome / payment / settlement records
- Report records (`listingReports`) **remain** — archive/hide does not delete reports
- Batch size: all **17** candidates in one controlled batch (or phased sub-batches with same rollback)
- Log **masked execution summary** in ops channel — redacted counts only in git execution record

### What cleanup changes (future execute)

| Field | Change | Reversible |
|-------|--------|------------|
| `listingStatus` | `published` → `hidden` | ✅ yes |
| Marketplace visibility | excluded from public search | ✅ yes |
| Chat/AI grounding | excluded from pilot inventory | ✅ yes |
| Lead/reveal/outcome data | **unchanged** | — |
| Hard delete document | ❌ **forbidden** in initial cleanup | — |
