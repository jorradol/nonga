## 6. PII Guard

### 6.1 PII Categories — Hard Block in AI Path

| Category | Examples | Guard |
|----------|----------|-------|
| เบอร์โทร | `08x-xxx-xxxx`, `+66` | ไม่ส่งไป provider; ไม่แสดงใน reply |
| ชื่อเจ้าของรถ | ชื่อ-นามสกุล seller | mask → "เจ้าของรถ" หรือ omit |
| LINE ID | `@line`, LINE QR | ไม่แสดง |
| ที่อยู่ | บ้านเลขที่, ซอย, แขวง | แสดงแค่จังหวัด |
| เลขทะเบียนเต็ม | `กข 1234 กรุงเทพ` | mask → จังหวัด only ถ้าจำเป็น |
| เอกสาร / ใบเล่ม / บัตรประชาชน | ภาพ/ข้อความ | block + reject import |
| ป้ายทะเบียนในรูป | readable plate in photo | blur before publish |

### 6.2 PII Scan Before Import (Future v6.2B)

| Step | Action |
|------|--------|
| P-01 | Scan description text for phone/LINE/address patterns |
| P-02 | Scan image metadata; flag documents/plates |

| P-04 | Reject listing if PII cannot be sanitized |

### 6.3 PII in Logs & Provider Payloads

| Rule | Detail |
|------|--------|

## 7. Stale Listing Guard

### 7.1 Stale Conditions

| Condition | AI behavior | Listing action |
|-----------|-------------|----------------|
| รถขายแล้ว (sold) | ไม่แนะนำ; บอกว่าขายแล้ว | **delist** จาก pilot search |
| รถจองแล้ว (reserved) | บอกสถานะจอง; ไม่ overpromise | mark reserved; optional delist |
| ราคาเปลี่ยน | ตอบจากราคาล่าสุดเท่านั้น | sync price before reply |
| รูปไม่ตรง | ไม่ฟันธงสภาพจากรูปเก่า | update or delist |
| ข้อมูลเลขไมล์/ปี/รุ่นไม่ครบ | บอก **"ข้อมูลประกาศยังไม่พอ"** | fix or delist |
| Listing ไม่ update > N วัน | flag stale | manual review |

### 7.2 Delist / Disable Procedures

| Trigger | Procedure |
|---------|-----------|
| Seller ขายแล้ว | ops เปลี่ยน status → `sold` → auto exclude from AI search |
| Seller ถอน consent | remove from pilot batch immediately |
| Price mismatch reported | freeze listing → verify → update or delist |
| PII leak detected | **immediate delist** + incident record |
| Stale > threshold | weekly review → delist or refresh |

### 7.3 Sync Requirements (Future Runtime)

| Field | Sync frequency |
|-------|----------------|
| status (available/reserved/sold) | real-time or ≤ 1 hour |
| price | real-time or ≤ 1 hour |
| photos | on change |
| mileage/year/model | on change |

## 9. AI Grounding Rules

### 9.1 Core Principles

| # | Rule |
|---|------|
| AG-01 | **น้องเอต้องตอบจากข้อมูลประกาศจริงก่อน** — listing fields + carCards ใน session |
| AG-02 | **ห้ามแต่งข้อมูลนอกประกาศ** — no hallucinated specs, price, mileage |
| AG-03 | ถ้าข้อมูลไม่พอ → ตอบว่า **"ข้อมูลประกาศยังไม่พอ"** และถาม/แนะนำให้ตรวจประกาศ |
| AG-04 | **ห้าม overpromise** — ไม่การันตีสภาพ, ราคา, การอนุมัติไฟแนนซ์ |
| AG-05 | **ห้ามฟันธงสภาพรถ** — ไม่บอกว่า "สภาพดีมาก" ถ้าไม่มีข้อมูลรองรับ |
| AG-06 | ต้องบอกว่าเป็น **คำแนะนำเบื้องต้นจากข้อมูลประกาศ** |
| AG-07 | ไฟแนนซ์/ผ่อน → การประเมินเบื้องต้น ต้องตรวจสอบกับไฟแนนซ์จริง |
| AG-08 | Compare/refine → ใช้ recent carCards ใน session เท่านั้น (v6.1L.2g/i) |

### 9.2 Forbidden AI Behaviors

| Behavior | Example | Action |
|----------|---------|--------|
| Invent car not in inventory | "มี Civic RS 2024 คันนี้..." (ไม่มีใน batch) | block |
| Guess mileage | "น่าจะวิ่ง ~80,000 km" | block → ข้อมูลไม่พอ |
| Guarantee condition | "สภาพสมบูรณ์แบบ 100%" | block |
| Guarantee deal | "ดีลสุดคุ้ม คุ้มค่าเงินทุกบาทแน่นอน" | block (v6.1L lesson) |
| Credit/legal advice | "ติดบูโรก็ผ่อนได้" | block |
| Contact reveal | ให้เบอร์/LINE seller | block (§6) |

### 9.3 Grounding Source Priority

1. Listing fields จาก real stock record (future)
2. carCards ใน session ปัจจุบัน
3. ถ้าไม่มี → safe copy / ข้อมูลไม่พอ — **ไม่เดา**
