# v5.6E — Seller Masked Lead Queue / Seller Lead Inbox MVP

**Status:** Staging MVP (in-memory leads)  
**Scope:** Seller sees masked buyer interest queue per listing; skip before contact reveal; buyer feedback copy.  
**Not in scope:** Full CRM inbox, payment/success fee, admin settlement, full contact reveal UI, Firestore persistence.

## Overview

After v5.6D buyer interest queue and v5.6D.1 phone-in-modal UX, sellers need a minimal UI to review queued buyers **without** seeing full phone numbers. v5.6E adds:

1. **Seller masked queue UI** on **My Listings** (per listing card).
2. **Skip queue** API before reveal, with required reason and polite buyer feedback.
3. **Privacy guardrails** — masked list always hides full mobile; skip never reveals contact.

## Staging limitations

- Buyer leads and queue state remain **in-memory** (`buyerLeadRepository`).
- **Restart / redeploy / multi-instance** can reset or split queue data.
- This is **not** a durable seller CRM; admin audit relies on contact logs in memory for now.

## Seller UI

**Location:** `MyListingsView` → `SellerMaskedLeadQueuePanel` under each owned listing.

**Shows (when `interestCount > 0` or queue rows exist):**

- Interest count (from public stats + queue API).
- Queue rows sorted by `queuePosition`.
- Masked buyer summary: display name, purchase method, budget/offer labels, preferred contact window, `buyerSummary`.
- Current turn: “ถึงคิวของคุณ”; others: “รอผลคิวก่อนหน้า”.
- Actions on current turn only:
  - **ข้ามคิวนี้** — opens reason form, calls skip API.
  - **เปิดข้อมูลติดต่อ** — disabled (coming soon / not enabled in this MVP).

**Errors:** 401/403/404 from API show polite inline messages; page does not crash.

## APIs

| Method | Path | Auth | Purpose |
|--------|------|------|---------|
| GET | `/api/seller/listings/:listingId/buyer-lead-queue` | Firebase auth; listing `ownerId` | Masked queue rows |
| GET | `/api/listings/:listingId/interest-queue-stats` | Public | `interestCount` only |
| POST | `/api/seller/buyer-leads/:leadId/skip` | Auth; lead `sellerId` or admin | Skip before reveal |

**Skip body:** `{ reason: SellerSkipReason, note?: string }` — `note` required when `reason` is `other`.

## Skip reasons

| Value | Label (TH) |
|-------|------------|
| `offer_below_expectation` | ราคาเสนอไม่ถึงเกณฑ์ |
| `purchase_method_mismatch` | วิธีซื้อไม่ตรงที่ต้องการ |
| `insufficient_info` | ข้อมูลยังไม่พอ |
| `suspected_inaccurate` | สงสัยข้อมูลไม่ถูกต้อง |
| `other` | อื่น ๆ (requires short polite note) |

## Skip behavior

- Only the **current** queue head (`getNextRevealableLead`) with `contactRevealStatus === locked`.
- Sets `queueLifecycle: withdrawn`, `status: not_proceeded`, stores `sellerSkipReason`, optional `sellerSkipNote`, `buyerQueueFeedback`.
- Appends contact log `queue_skipped_before_reveal` with `autoBuyerPenalty: false`.
- Does **not** set `contactRevealedAt` or reveal phone.
- Next active lead becomes seller’s turn.

## Buyer feedback copy

Template (all reasons):

> ผู้ขายยังไม่ได้เลือกติดต่อกลับในรอบนี้ เนื่องจาก:  
> [reason-specific line]  
> น้องเอแนะนำให้ปรับข้อมูลหรือเลือกคันที่เหมาะกับงบ/วิธีซื้อของคุณมากขึ้น เพื่อเพิ่มโอกาสให้ผู้ขายติดต่อกลับในครั้งถัดไปครับ

Reason-specific lines — see `buildBuyerSkipFeedbackMessage()` in `sellerSkipQueuePolicy.ts`.

## Privacy / auth

- Seller queue: listing owner only (403 for others).
- Skip/reveal/outcome: lead `sellerId` or admin only.
- Masked queue rows: `contactMasked: true`, `canRevealContact: false` in v5.6E list API mapping.
- Public stats: `interestCount` only — no buyer PII.

## Explicitly not opened

- Payment / success fee collection
- Admin settlement workflows
- Full contact reveal UI for sellers
- Firestore rules / migration writes
- Durable Firestore lead persistence (future phase)
