# Nong A v5.0 Step 2L Chat History Production Storage

Step 2L introduces a central chat history service and a production Firestore schema while keeping local/mock mode compatible with the existing dealer-scoped localStorage keys.

## Current Storage Before Step 2L

Local/mock mode used:

- Sessions: `nong-a-chat-sessions:{storageScopeKey}`
- Messages: `nong-a-chat-messages:{storageScopeKey}`
- Preferences: `nong-a-chat-prefs:{storageScopeKey}`

The `storageScopeKey` is generated by `getChatStorageScope()`:

- Dealer: `dealer:{dealerId}:{uid}`
- Member/consumer: `user:{uid}`

The old Firestore-ready path used `chats/{chatId}` with `userId == storageScopeKey`. That was scoped enough for local/demo separation but did not expose `uid`, `dealerId`, and `scope` as first-class production fields.

## What Changed

New service:

- `src/services/chat/chatHistoryService.ts`

Main APIs:

- `loadChatSessions(scope)`
- `loadChatMessages(scope, sessionId)`
- `createChatSession(scope, title)`
- `appendChatMessage(scope, sessionId, message)`
- `updateChatSessionMetadata(scope, sessionId, patch)`
- `updateChatMessageText(scope, sessionId, messageId, text)`
- `deleteChatSession(scope, sessionId)`

The Zustand chat store now delegates persistence to this service, so selecting a session validates scope and loads that session's messages before switching `activeSessionId`.

## Production Firestore Schema

`chatSessions/{sessionId}`:

- `sessionId`
- `uid`
- `dealerId`
- `scope: "user" | "dealer"`
- `storageScopeKey`
- `userId` for backward compatibility with the old scoped key
- `title`
- `createdAt`
- `updatedAt`
- `lastMessagePreview`
- `savedDraftId`
- `status: "active" | "archived"`

`chatSessions/{sessionId}/messages/{messageId}`:

- `messageId`
- `sender`
- `text`
- `attachments`
- `draftFields`
- `savedDraftId`
- `createdAt`

The service has read-only compatibility for the old `chats/{chatId}` collection if no `chatSessions` exist yet.

## Attachment Metadata

Messages persist attachment metadata only, not binary files.

Persisted metadata can include:

- `id`
- `kind`
- `name`
- `mimeType`
- `size`
- `width`
- `height`
- `imageUrl`
- `thumbnailUrl`
- `storagePath`
- `dealerId`
- `listingId`
- `draftId`
- `fileName`
- `originalFileName`

Transient browser-only fields such as `previewUrl` and `previewDataUrl` are stripped before persistence. This prevents stale blob URLs from being stored after a browser reload.

## Session Switching

When selecting a row in the left chat history:

1. The store confirms the session belongs to the current `uid/dealerId` scope.
2. The service loads messages for that `sessionId`.
3. The store sets `activeSessionId`.
4. The message pane renders `messages[activeSessionId]`.
5. `ChatContainer` scrolls to the latest message when `activeSessionId` changes.

This prevents dealer A from opening dealer B's session even if a stale or guessed `sessionId` is available in the UI.

## Rules Alignment

`firestore.rules.draft` now includes:

- `match /chatSessions/{sessionId}`
- `match /chatSessions/{sessionId}/messages/{messageId}`
- read-only legacy `match /chats/{chatId}` for migration/export

Rules require:

- Member/user chat: `uid == request.auth.uid`
- Dealer chat: active `dealerMembers/{uid_dealerId}`
- Admin/superadmin: active server profile role

Rules are still drafts and have not been deployed.

## Tests

Run:

```bash

```

Coverage:

- Dealer-scoped session creation.
- User/assistant message append.
- Scoped session loading.
- Session switching updates `activeSessionId` and messages.
- Dealer A cannot load dealer B messages.
- Attachment metadata persists without transient preview URLs.
- `savedDraftId` persists on message and session.
- Local/mock mode remains backed by scoped localStorage.
