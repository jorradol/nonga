## 18. NONGA_AI_SHADOW_MODE_ENABLED=true Review

### Current state

`NONGA_AI_SHADOW_MODE_ENABLED=true` remains on staging after v6.5Q.EXEC (out of scope for alignment).

### Why shadow mode may be acceptable for isolated synthetic invocation

| Factor | Assessment |
|--------|--------------|
| User-visible path | **OFF** — shadow cannot surface to users |
| Admin shadow real provider | **OFF** — no admin real provider path |
| Chat shadow real provider | **OFF** |
| Gate B harness | **Isolated** — not wired to App/user/chat/live |
| Invocation surface | Dedicated synthetic harness only |

**Conclusion:** Shadow mode **acceptable for Gate B** **if and only if** Gate B runs via **isolated harness** with **no user-visible route**, switches UV-01/UV-02 remain `false`, and pre-flight re-verifies flags before exec.

### Why shadow mode would NOT be acceptable

| Condition | Result |
|-----------|--------|
| User-visible flag becomes `true` | **NO-GO** |
| Admin shadow real provider `true` | **NO-GO** |
| Gate B wired to user chat/live runtime | **NO-GO** |
| Harness not isolated from App routes | **NO-GO** |

**Owner must ack RW-01 isolation plan before Gate B.EXEC.**
