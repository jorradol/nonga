## Current problem (ก่อน v5.6I.9)

`POST /api/admin/revenue/adjustments` เคย:

1. เรียก `applySettlementAdjustment()` (pure)
2. `adjustmentRepo.upsertState(next)` 
3. `adjustmentRepo.appendAudit(...)` แยกกัน

**ความเสี่ยง:**

| ปัญหา | ผล |
|--------|-----|
| upsert สำเร็จ แต่ appendAudit ล้ม | state เปลี่ยนโดยไม่มี audit |
| ไม่มี requestId | network retry / double-click สร้าง audit ซ้ำ |
| audit id = `Date.now()` + random | replay ไม่ idempotent |

---

## Transaction invariant

ทุก adjustment 1 ครั้งต้อง:

1. Validate input + audit invariant **ก่อน** write
2. เขียน **state + audit พร้อมกัน** (atomic)
3. ถ้า audit invariant fail → **ไม่เขียน state**
4. Duplicate `requestId` + fingerprint เดิม → คืนผลเดิม ไม่ append audit ซ้ำ

## Idempotency model

### Fields

| Field | ที่มา | หมายเหตุ |
|-------|-------|----------|
| `requestId` | Frontend (`useRef` ตอนเปิด modal) หรือ server `srv-{ts}-{rand}` | ห้ามมี PII |
| Composite key | `{listingId}\|{updatedBy}\|{requestId}` | ใน memory / Firestore cache |
| `payloadFingerprint` | JSON normalized ของ action/amount/reason/note | ไม่มี PII fields |
| `auditId` | `adj-audit-{listingId}-{requestId}` | deterministic |
| `outcome` | `processed` \| `duplicate` | ใน API response |

### Rules

| กรณี | ผล |
|------|-----|
| Same requestId + same listing + same actor + same fingerprint | **200** — `outcome: duplicate` |
| Same requestId + different fingerprint | **409** conflict |
| Missing requestId | Server generate `srv-...` — backward compatible แต่ **กัน retry ข้าม request ไม่สมบูรณ์** |
| requestId มี phone/email/PII | **400** reject |

**Key format:** UUID/random จาก client (`generateServerSettlementRequestId` ใน modal) — ไม่ใส่ buyer data

---

## Duplicate / conflict handling

- **Duplicate:** คืน `adjustment` + `audit` เดิม + `idempotency.outcome: "duplicate"`
- **Conflict:** `SettlementAdjustmentIdempotencyConflictError` → HTTP 409
- **Audit invariant:** `SettlementAdjustmentAuditInvariantError` → HTTP 400

## Firestore transaction plan

Module: `settlementAdjustmentRepositoryFirestore.ts`

- `applyAdjustmentWithAudit()` ใช้ `db.runTransaction()` — state + audit ใน transaction เดียว

- **ยัง gated:** `assertWritesAllowed()` — ไม่เขียน Firestore จนเปิด flag
