## 5) Root cause of `pilot_path_inactive`

### 5.1 Immediate blocking gate

In `src/services/ai/salesBrainUserVisibleRealProvider.ts`:

- `maybeApplyUserVisibleRealProvider()` checks:
  - `if (!input.bridgeResult.payload.pilotPathActive) -> realProviderGateReason = "pilot_path_inactive"`
- this happens after eligibility passes
- provider call is not attempted when this condition is false

### 5.2 Where `pilotPathActive` comes from

`pilotPathActive` is produced by orchestration bridge path:

1. `/api/ai/chat-user-visible-orchestrate` -> `handleChatUserVisibleOrchestratePost()`
2. `orchestrateUserVisibleChatForTrustedAuth()`
3. `runUserVisibleOrchestrationBridge()`
4. `wireShadowChatPathWithPilot()`
5. `resolveUserVisibleChatResponse()`

If orchestration does not produce a pilot-active text, payload is built with `pilotPathActive=false`.

### 5.3 Why pilot became inactive in v13.15B flow

Expected fail-closed path, not bug:

- `runUserVisibleOrchestrationBridge()` returns inactive when:
  - `tryOrchestrateChatReplyCore(...)` returns `null`, and
  - message is not follow-up path that can trigger `runPilotFollowUpBridgeWhenNoOrchestrator()`
- in that branch it returns:
  - `orchestrated: null`
  - payload from `buildRedactedPayload(null, "", false, true)` -> `pilotPathActive=false`

Therefore `pilot_path_inactive` can occur even when owner-only + AI-first + user-visible gates are all enabled, because pilot-path activation is a separate gate tied to orchestration/session context outcome.

## 6) Required pilot activation conditions

To avoid `pilot_path_inactive`, the bridge must produce `pilotPathActive=true`.
Key required conditions:

1. **Orchestrated reply must exist** (`orchestrated != null`)  
   - message must map to supported deterministic orchestrator paths (search/follow-up/intents)

2. **Pilot path resolution must stay active**  
   - `resolveUserVisibleChatResponse()` must not fall back to legacy due to gate fallback
   - `buildPilotUserVisibleText()` must return an active pilot result

3. **Session context availability for follow-up flows**  
   - follow-up paths rely on `pilotSessionContext.recentCarCards` or prior in-chat card context
   - without context cards, non-follow-up prompt may leave pilot inactive

4. **User-visible gate still must pass**  
   - owner-only, allowlist, user-visible requested, AI-first, provider/mode/budget prerequisites
