## 2) Baseline from v14.0A retest

v14.0A retest showed runtime/gate signals were captured (`HTTP 200`, `providerNetwork=true`, `pilotPathActive=true`) but owner quality scoring remained HOLD because answer text evidence was still not reliably captured in a stable documented field.

## 3) Root cause confirmed

### Backend/endpoint findings

Endpoint `/api/ai/chat-user-visible-orchestrate` already returned `userVisibleText`, but no dedicated stable evidence field existed for owner one-run evidence capture and no explicit missing-answer flag/reason existed.

### Frontend/evidence findings

Owner helper originally read only `nested.userVisibleText` and inferred missing from that single key.  
This could fail when:

1. response shape evolves,
2. answer exists in an alternate sanitized field,
3. response wrapper shape differs.

Result: diagnostics could appear while answer text remained uncaptured in evidence workflow.

## 4) v14.0B patch summary

### Backend

In `salesBrainServerUserVisibleOrchestrationBridge` response data now includes:

- `sanitizedUserVisibleText` (normalized + length-capped)
- `missingUserVisibleText` (boolean)
- `missingUserVisibleTextReason` (when missing)
- `evidenceCapturedAt` (ISO timestamp)

Sanitization rules:

- trim + whitespace normalization
- max length cap
- no token/header/secret exposure

### Frontend

Introduced stable evidence parser utility in `ownerOneRunEvidence.ts`:

- maps backend -> evidence block with deterministic keys
- supports fallback answer key chain:
  - `sanitizedUserVisibleText`
  - `userVisibleText`
  - `assistantText`
  - `answerText`
  - `finalText`
  - `content`
  - `message`
- emits:
  - `answerFieldSource`
  - `answerCharCount`
  - `userVisibleTextMissing`
  - `userVisibleTextMissingReason`

Owner panel now consumes parser output and renders sanitized answer evidence reliably.

## 5) Backend -> frontend -> evidence flow

1. backend computes final user-visible text path and returns response payload
2. backend emits `sanitizedUserVisibleText` + missing flags + `evidenceCapturedAt`
3. frontend helper parses payload using stable mapping utility
4. evidence block shows:
   - sanitized answer text (or missing warning)
   - provider/gate/fallback flags
   - card counts and runtime diagnostics
   - timestamp and session lock evidence
