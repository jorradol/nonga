### 3.4 Auth requirements

- **Create lead:** Firebase auth via `getServerAuthContext` — unauthenticated → **401** (preserved; verified live).
- **Seller queue / reveal / skip / outcome:** authenticated listing owner, dealer scope, or admin.
- **Public signup:** disabled — login copy tells buyers pilot accounts are invite-only.

### 3.5 Consent requirements

- Consent version: **`v5.6C-1`** (`BUYER_LEAD_CONSENT_VERSION`).
- Server rejects create unless `consentConfirmed === true` and version matches.
- Submit is from the **modal** (not from typing “ยืนยัน” alone in chat for the final POST).
- Forbidden sensitive docs in free text (ID card, registration book, salary slip, bank account, finance contract, etc.) are blocked.

## 4) Owner-readable lead flow summary

### What the buyer would see

1. In chat, find a car card → tap **「ให้ผู้ขายติดต่อกลับ」** (or type a contact-back intent after selecting a car).
2. น้องเอ asks for: nickname, purchase method, budget/offer, convenient contact time (phone **not** in chat).
3. When complete, buyer taps **「ตรวจสอบและส่งข้อมูลให้ผู้ขาย」** → modal **「ตรวจสอบก่อนส่งข้อมูลให้ผู้ขาย」**.
4. Buyer enters phone, reads consent, taps **「ยืนยันส่งข้อมูลให้ผู้ขาย」** (must be logged in).
5. Success copy (no queue number shown to buyer): data sent for seller review; phone still masked to seller until they reveal; น้องเอ is not a party to the sale.

### Consent wording (exact — for owner review)

**Modal primary:**

> น้องเอจะส่งข้อมูลนี้ให้ผู้ขายรถคันนี้เพื่อให้ติดต่อกลับเรื่องการซื้อขายเท่านั้น น้องเอไม่ใช่คู่สัญญาและไม่ตัดสินใจแทนผู้ซื้อหรือผู้ขาย กรุณาตรวจสอบรถ เอกสาร และเงื่อนไขจริงก่อนตกลงซื้อขาย

**Modal contact:**

> ข้อมูลติดต่อจะใช้เฉพาะเพื่อส่งต่อให้ผู้ขายตามที่คุณยินยอมในรายการนี้

**Chat consent prompt (supporting):**

> ถ้าคุณยืนยัน น้องเอจะส่งข้อมูลติดต่อและความสนใจของคุณให้ผู้ขายรถคันนี้ เพื่อให้ผู้ขายติดต่อกลับเรื่องการซื้อขายรถคันนี้เท่านั้น

### What happens after submission (if an authenticated user completes the flow)

1. Server validates consent + fields → creates lead with **locked** phone.
2. Assigns queue position for that listing (buyer-facing success text does **not** show the number).
3. Appends contact log `consent_recorded`.
4. Seller can later open masked queue on their listing; full phone only after **Reveal**.
5. No automatic message is sent to the dealer outside the in-app queue.

### Where stored / owner review before dealer action

- Stored in lead repository (staging default: **memory**).
- Seller/admin can review **masked** queue before reveal.
- Owner/admin can use seller/admin auth paths; there is no separate “owner must approve every lead before it enters seller queue” gate today — create goes to the listing’s interest queue immediately after consent.

### What remains locked in this step

- Public signup
- Public launch
- Production deploy
- Automatic dealer notification
- This review’s real lead creation / dealer send
- Durable Firestore lead backend (env not set)
