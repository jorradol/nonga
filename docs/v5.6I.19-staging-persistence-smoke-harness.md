### S4–S6 detail (adjustment + idempotency)

```http
POST /api/admin/revenue/adjustments
Authorization: Bearer <admin-token>
Content-Type: application/json

{
  "listingId": "<test-listing-id>",
  "adjustmentType": "partial_payment",
  "amount": 1000,
  "reason": "staging smoke test",
  "requestId": "<uuid-from-modal-pattern>"
}
```

| Step | Action | Expected |
|------|--------|----------|
| 1 | POST ครั้งแรก | 200, `outcome: processed` |
| 2 | POST ซ้ำ requestId + body เดิม | 200, `outcome: duplicate`, audit count ไม่เพิ่ม |
| 3 | POST requestId เดิม amount/reason ต่าง | **409** conflict fingerprint |
| 4 | Firestore Console (Admin SDK) | idempotency + adjustment + audit — **1 ชุด** ไม่ซ้ำ |

### S7 seller scope detail

- Login เป็น seller A → `GET /api/my/revenue/preview` ต้องมีเฉพาะ listing ที่ `ownerId === seller A`
- ต้อง **ไม่** เห็น admin note, audit trail, หรือยอดของ seller B
- ถ้ามี `refreshSignal` หลัง cancel pending sale — ยอดต้อง sync (v5.6I.3b)
