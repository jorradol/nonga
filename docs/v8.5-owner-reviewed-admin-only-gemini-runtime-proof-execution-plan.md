## 4. Runtime-Proof Phases (Plan Only)

> ทุก phase ด้านล่างเป็นแผนสำหรับ review และ evidence readiness เท่านั้น
> ห้ามตีความว่าเป็นการอนุญาต execute runtime จริง

### Phase 0: Preflight Verification

- **objective:** ยืนยัน baseline ความปลอดภัยและขอบเขตก่อนพิจารณา runtime proof ใดๆ
- **exact action allowed:** ตรวจเอกสาร, checklist, และ static validation script เฉพาะใน repo เท่านั้น
- **forbidden action:** ห้าม deploy, ห้าม runtime invoke, ห้ามแก้ production config, ห้ามเปิด Gemini จริง
- **evidence to collect:** baseline checklist, validation output, และเอกสารยืนยัน non-activation boundary
- **pass criteria:** baseline safety checks ผ่านครบ และไม่มี activation signal
- **fail/block condition:** checklist ไม่ครบ, ข้อมูล baseline ขัดแย้ง, หรือพบความเสี่ยงด้านขอบเขต
- **rollback/stop condition:** หยุดทันทีเมื่อ baseline mismatch และคงสถานะ HOLD
- **owner sign-off gate:** owner รับรองว่า preflight พร้อมเฉพาะในระดับ docs/static เท่านั้น

### Phase 1: Secret Readiness Check (No Secret in Repo)

- **objective:** ยืนยันความพร้อมแนวทาง secret handling โดยไม่เปิดเผยค่า secret จริง
- **exact action allowed:** ตรวจ naming convention, env key mapping แบบ placeholder, และ redacted checklist เท่านั้น
- **forbidden action:** ห้ามใส่ค่า secret/API key จริง, ห้าม commit credential, ห้ามเปิดการเชื่อมต่อ provider จริง
- **evidence to collect:** redacted secret-readiness checklist, policy mapping เอกสาร, และ scan report ว่าไม่พบ key จริง
- **pass criteria:** mapping ครบ, ไม่มี secret leak pattern, และ reviewer ยืนยันว่า repository ปลอด credential จริง
- **fail/block condition:** พบ secret pattern จริง, mapping ไม่ครบ, หรือ policy ไม่ชัดเจน
- **rollback/stop condition:** isolate artifact ที่มีความเสี่ยงทันทีและหยุด phase ถัดไปทั้งหมด
- **owner sign-off gate:** owner ลงนามรับรองว่าความพร้อมด้าน secret อยู่ในระดับ non-runtime only

### Phase 2: Admin-Only Route/Boundary Proof Plan

- **objective:** วางหลักฐานว่าการพิสูจน์ runtime ในอนาคตจำกัดเฉพาะ admin-only boundary เท่านั้น
- **exact action allowed:** ทบทวน route inventory, role matrix, deny-path checklist แบบ static
- **forbidden action:** ห้ามเปิด buyer-visible path, ห้าม expose AI output สู่ผู้ใช้จริง, ห้ามแก้ routing production
- **evidence to collect:** admin-only route matrix, deny-case evidence plan, และเอกสาร non-admin access rejection
- **pass criteria:** boundary definition ชัดเจน, role isolation audit ได้, และไม่มีเส้นทาง user-visible
- **fail/block condition:** พบ ambiguity ของสิทธิ์, route overlap กับ buyer path, หรือ guard definition ไม่ครบ
- **rollback/stop condition:** หาก boundary ไม่ชัดเจนให้หยุดและคง deterministic-only posture
- **owner sign-off gate:** owner อนุมัติ boundary matrix ก่อนพิจารณา phase runtime proof ใดๆ ต่อ

### Phase 3: Kill Switch Proof Plan

- **objective:** วางแนวทางพิสูจน์ว่า kill switch สามารถปิด admin-only shadow path ได้ทันทีเมื่อมีความเสี่ยง
- **exact action allowed:** จัดทำ runbook, trigger criteria, และ simulated drill plan ในเอกสารเท่านั้น
- **forbidden action:** ห้าม toggle runtime switch จริง, ห้ามยิง request provider จริง, ห้ามทำ incident trigger บน production
- **evidence to collect:** kill switch runbook draft, SLA expectation, และ simulated drill evidence template
- **pass criteria:** trigger condition ชัดเจน, stop path ชัดเจน, และ fallback deterministic route ระบุครบ
- **fail/block condition:** ไม่มี owner/operator ชัดเจน, SLA ไม่กำหนด, หรือ stop flow ไม่ deterministic
- **rollback/stop condition:** suspend runtime-proof progression หาก kill switch proof plan ยังไม่ครบ
- **owner sign-off gate:** owner ลงนามรับรอง kill switch drill plan ก่อนอนุญาตไปขั้นถัดไป

### Phase 4: Fallback Proof Plan

- **objective:** ยืนยันแผน fallback ที่คืนการตอบกลับไป deterministic flow ได้เสมอ
- **exact action allowed:** สร้าง fallback matrix และ failure class mapping แบบเอกสาร/static test เท่านั้น
- **forbidden action:** ห้ามเปิด runtime provider จริง, ห้ามเปลี่ยน source of truth จาก deterministic flow
- **evidence to collect:** fallback matrix, deterministic response mapping, และ failure scenario checklist
- **pass criteria:** ทุก scenario มี fallback deterministic ชัดเจนและไม่มี user-visible AI effect
- **fail/block condition:** fallback ครอบคลุมไม่ครบ, behavior ไม่ deterministic, หรือมี buyer-facing leakage
- **rollback/stop condition:** หาก fallback ambiguity เกิดขึ้น ให้หยุดและย้อนกลับสู่ deterministic-only state
- **owner sign-off gate:** owner อนุมัติ fallback matrix ก่อนอนุญาตไป phase guard เชิงปฏิบัติการ

### Phase 5: Logging/Redaction Proof Plan

- **objective:** ยืนยันว่า evidence logging ไม่หลุด PII/secrets และอยู่ภายใต้ redaction policy
- **exact action allowed:** ตรวจ schema log, redact rule, และ static sample review แบบไม่ใช้ข้อมูลจริง
- **forbidden action:** ห้ามเก็บข้อมูลส่วนบุคคลจริงแบบไม่ redact, ห้ามบันทึก token/secret จริง, ห้ามส่ง log ไป production sink
- **evidence to collect:** redaction checklist, static sample logs (sanitized), และ privacy review note
- **pass criteria:** redact ครบ field เสี่ยง, ไม่มี secret pattern, และมี privacy reviewer acknowledgment
- **fail/block condition:** พบ PII/secret unredacted, rule coverage ไม่ครบ, หรือ traceability ไม่เพียงพอ
- **rollback/stop condition:** stop ทันทีเมื่อพบ data exposure risk และคง non-activation state
- **owner sign-off gate:** owner และ reviewer ลงนามยืนยันว่า logging plan ปลอดภัยพอสำหรับขั้น review ถัดไป

### Phase 6: Quota/Budget Guard Proof Plan

- **objective:** วางแนวทางป้องกันงบประมาณและโควตาก่อนอนุญาต runtime proof จำกัดขอบเขต
- **exact action allowed:** จัดทำ guard threshold matrix, escalation path, และ budget stop policy แบบเอกสารเท่านั้น
- **forbidden action:** ห้ามเปิด traffic จริง, ห้าม consume quota จาก provider จริง, ห้ามตั้งค่า production billing change
- **evidence to collect:** quota/budget matrix, breach-handling checklist, และ owner-reviewed stop policy
- **pass criteria:** threshold ชัดเจน, breach response ชัดเจน, และมี deterministic stop path เมื่อเกิน guard
- **fail/block condition:** threshold ไม่ชัด, ไม่มี escalation owner, หรือ stop policy ไม่ enforce ได้
- **rollback/stop condition:** หาก guard ยังไม่พร้อมให้ HOLD ทันทีและไม่อนุญาต phase execution
- **owner sign-off gate:** owner ยืนยัน budget guard ครบก่อนเข้าสู่ขั้น evidence decision

### Phase 7: Owner Evidence Review Before Next Authorization

- **objective:** ให้ owner ตรวจหลักฐานรวมทุก phase ก่อนตัดสินใจอนุญาตขั้นถัดไป
- **exact action allowed:** ตรวจ evidence package, sign-off record, และ decision packet เท่านั้น
- **forbidden action:** ห้าม activate runtime จริงก่อน verdict, ห้าม bypass owner gate, ห้ามเปิด user-visible AI
- **evidence to collect:** consolidated evidence index, unresolved risk list, และ owner decision log
- **pass criteria:** evidence ครบ, risk อยู่ในเกณฑ์ยอมรับได้, และ owner มี decision ชัดเจน
- **fail/block condition:** evidence ขาด, risk ยังไม่ถูกปิด, หรือมีข้อสงสัยเรื่อง non-activation boundary
- **rollback/stop condition:** คง HOLD/NO-GO ทันทีเมื่อหลักฐานไม่พอหรือพบความเสี่ยงใหม่
- **owner sign-off gate:** owner ลงนาม verdict เป็น GO/HOLD/NO-GO อย่างเป็นทางการ
