# v5.6I.3b — Revenue Statement Refresh Reliability After Cancel Pending Sale

## ปัญหา (หลัง v5.6I.3a)

หลัง cancel pending sale สำเร็จ badge/listings อัปเดตแล้ว แต่ **ยอดค่าบริการใน MyRevenueStatementSection บางครั้งยังค้าง** จนกว่าจะ reload browser

## Root cause

1. **Stale in-flight fetch race** — request เก่าก่อน cancel อาจ complete หลัง request ใหม่ แล้วเขียนทับ payload เก่ากลับ
2. **ลำดับ refresh** — revenue signal ถูก bump ก่อน `fetchCars()` sync เสร็จ
3. **Counter refreshKey (+1)** — เปลี่ยนจริงแต่ไม่มี cache-bust / guard ชัดพอ

## วิธีแก้ (frontend only)

### MyListingsView

หลัง cancel success:

```text
await load()
await fetchCars()
setRevenueRefreshSignal(Date.now())
```

### MyRevenueStatementSection

- เปลี่ยน `refreshKey` → **`refreshSignal`** (timestamp nonce)
- `useEffect` มี cleanup `active = false` — ทิ้ง response ที่ stale
- ระหว่าง refetch แสดง **"กำลังอัปเดตยอดค่าบริการ…"** และซ่อนตารางเก่า
- เรียก `fetchMyRevenuePreview(scope, refreshSignal)`

### myRevenuePreviewApi

- เมื่อ `refreshSignal > 0` ใช้ `GET /api/my/revenue/preview?_rs=<signal>` (cache bust)

## ข้อห้าม

- ไม่เปลี่ยน backend cancel/relist policy
- ไม่เปิด payment / settlement write
