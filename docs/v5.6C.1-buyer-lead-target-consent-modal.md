# v5.6C.1 — Buyer Lead Target Selection + Consent Preview Modal

## Summary

- Car cards in chat expose **「ให้ผู้ขายติดต่อกลับ」** — sets explicit `listingId` + session capture state.
- Text intent **「ขอให้ผู้ขายติดต่อกลับ」** without a selected car prompts the user to pick a car first; no lead is created without `listingId`.
- When draft fields are complete, chat opens a **consent preview modal** (not text-only consent). Submit happens only from the modal with `consentConfirmed: true`.
- Phone in the modal is editable and is written into the lead payload before `POST /api/buyer-leads`.
- Guests must log in before submit (modal confirm triggers login modal).

**Buttons:** ยืนยันส่งข้อมูลให้ผู้ขาย · กลับไปแก้ไข · ยกเลิก

## ข้อจำกัด staging MVP

- **ต้องเลือกรถก่อน** — ปุ่มบนการ์ดหรือ target ชัดเจน; พิมพ์ intent อย่างเดียวไม่ auto-bind จาก “ดูรายละเอียดรถ”
- **Consent ผ่าน modal เท่านั้น** — ไม่ submit จากข้อความ “ยืนยันให้ส่งข้อมูล” ในแชท
- **Guest ต้อง login ก่อน POST** — กดยืนยันใน modal เปิด `ChatLoginModal` (gate ที่ 4 ใน `useChat`)
- **In-memory buyer leads** (v5.6C) — restart/redeploy หาย; multi-instance ไม่ share state
- **ยังไม่เปิด** seller inbox เต็ม, contact reveal UI เต็ม, payment/success fee
