## Exact staging enablement steps (ยังไม่รัน — อ้างอิงเท่านั้น)

> **ห้ามรัน** จนกว่าจะผ่าน [Approval criteria](#approval-criteria-ก่อนเปิด-staging-จริง) และได้รับอนุมัติจากลุง

### Phase A — Read-only Firestore backend (optional first slice)

**เป้าหมาย:** ตรวจว่า Cloud Run อ่าน Firestore ได้ โดยยังไม่เขียน

```text
# Cloud Run staging env ONLY — ตัวอย่าง ห้ามรันใน v5.6I.14
NONGA_SETTLEMENT_DATA_BACKEND=firestore
NONGA_SETTLEMENT_FIRESTORE_WRITES_ENABLED=false   # หรือ unset
NONGA_SUCCESS_FEE_RECORD_ENABLED=false            # หรือ unset
```

**Deploy:** Cloud Run env update **เท่านั้น** — ไม่ deploy rules ใหม่ / ไม่ production  
**คาดหวัง:** GET revenue preview ยังทำงาน; POST adjustment **throw** ก่อน write (`assertWritesAllowed`)

### Phase B — Adjustment Firestore writes (staging money path)

**เป้าหมาย:** POST adjustment เขียน 3 docs atomic (idempotency + state + audit)

```text
# Cloud Run staging env ONLY — ตัวอย่าง ห้ามรันใน v5.6I.14
NONGA_SETTLEMENT_DATA_BACKEND=firestore
NONGA_SETTLEMENT_FIRESTORE_WRITES_ENABLED=true
NONGA_SUCCESS_FEE_RECORD_ENABLED=false            # ยังไม่เปิด fee records
```

**Deploy:** Cloud Run env update + **restart/redeploy service** (ไม่ Hosting)  
**ห้าม:** backfill, migrate, payment, invoice, production

### Phase C — Success fee records (future — หลัง Phase B stable)

```text
NONGA_SUCCESS_FEE_RECORD_ENABLED=true
# + ทั้ง BACKEND=firestore และ WRITES=true
```

**ห้ามทำใน slice แรก** — รอ Phase B smoke + idempotency parallel test ผ่าน 24–72h

## Smoke test plan หลังเปิด (Phase B)

รันบน staging URL + admin token — **test listing เท่านั้น**

| # | ขั้นตอน | คาดหวัง |
|---|---------|---------|
| 1 | `GET /api/admin/revenue/preview` | 200, rows มี pending_sale |
| 2 | `POST /api/admin/revenue/adjustments` partial_payment + `requestId` | 200, `idempotency.outcome: processed` |
| 3 | `GET /api/admin/revenue/preview` ซ้ำ | paid/remaining ตรง adjustment |
| 4 | Firestore Console (Admin) | มี docs ใน `settlementAdjustments`, `settlementAuditLogs`, `settlementIdempotencyRecords` |
| 5 | `GET /api/my/revenue/preview` (seller scope) | 200, ไม่มี buyer PII / admin note |
| 6 | POST ซ้ำ requestId + payload เดิม | 200, `outcome: duplicate`, audit ไม่เพิ่ม |
| 7 | POST requestId เดิม payload ต่าง | 409 conflict |

**Fail-closed:** ถ้า transaction fail → admin ต้อง **ไม่** เห็น success; ตรวจ Cloud Run logs

## Parallel / idempotency replay smoke plan

**เป้าหมาย:** ยืนยัน durable idempotency ข้าม instance (v5.6I.13)

### Setup

- Staging Cloud Run **min instances ≥ 2** ชั่วคราว (หรือ force 2 concurrent requests)
- Test listing + fixed `requestId` (UUID จาก modal pattern)

### Test matrix

| Case | วิธี | คาดหวัง |
|------|------|---------|
| Concurrent duplicate | 2× POST พร้อมกัน body เดิม | audit **1 แถว**; idempotency doc **1 แถว**; 1× processed + 1× duplicate |
| Sequential replay | POST สำเร็จ → POST ซ้ำ | duplicate 200, audit count ไม่เพิ่ม |
| Conflict | POST สำเร็จ → POST requestId เดิม amount ต่าง | 409, audit count ไม่เพิ่ม |
| Restart replay | POST สำเร็จ → restart Cloud Run → POST ซ้ำ | duplicate 200 (durable record อยู่ใน Firestore) |

### Verification queries (Admin SDK / Console)

```text
settlementIdempotencyRecords/{docId}  → status=processed, auditLogId, settlementAdjustmentId
settlementAuditLogs/{auditLogId}      → 1 doc
settlementAdjustments/{stateId}       → paid/remaining ตรง
```

**PII check:** idempotency `responseSnapshot` ไม่มี phone/email/buyer fields

## Rollback plan

| ลำดับ | Action | ผล |
|-------|--------|-----|
| 1 | `NONGA_SETTLEMENT_FIRESTORE_WRITES_ENABLED=false` | หยุด writes ทันที (throw ก่อน transaction) |
| 2 | `NONGA_SETTLEMENT_DATA_BACKEND=memory` | runtime กลับ in-memory overlay |
| 3 | Redeploy / restart Cloud Run | apply env |
| 4 | **ไม่** ลบ Firestore docs อัตโนมัติ | docs ค้าง — memory runtime ไม่พึ่ง Firestore |
| 5 | Document incident + freeze adjustments ถ้าข้อมูลไม่สอดคล้อง | ops |

**ห้าม:** silent fallback memory เมื่อ backend=firestore (fail-closed)

## Data safety / PII safety checklist

| หัวข้อ | ตรวจ |
|--------|------|
| Settlement docs | ไม่มี buyer phone, email, contact, buyer name |
| Idempotency record | `assertNoBuyerPiiInIdempotencyRecord` + redacted `responseSnapshot` |
| Audit log | before/after numbers only — reason ไม่มีเบอร์โทร |
| API seller preview | ไม่ส่ง admin note / audit trail |
| Client direct Firestore | rules deny-all — ต้องผ่าน API เท่านั้น |
| requestId | ห้าม PII ใน key — client ส่งจาก `useRef` |
| Test data | ใช้ listing test — ไม่ใช้ข้อมูลลูกค้าจริง |

## Approval criteria ก่อนเปิด staging จริง

Staging enablement **อนุมัติได้** เมื่อครบ **ทุกข้อ**:

1. v5.6I.13 pushed + regression tests ผ่าน
2. v5.6I.14 runbook reviewed โดยลุง
3. Staging rules deny-all ยืนยันบน `nonga-ce93c` (ไม่ production)
4. Cloud Run staging credentials พร้อม (ไม่ leak)
5. Finance/admin sign-off สำหรับ staging money writes
6. Test listing + admin actor กำหนดแล้ว
7. Rollback owner + on-call ชัดเจน
8. Parallel idempotency smoke script/owner กำหนดแล้ว
9. **ยืนยัน:** ไม่ backfill, ไม่ payment, ไม่ invoice, ไม่ production ใน slice แรก

จนกว่าจะครบ → **Phase A/B ห้ามรัน**
