## 4. Preconditions ก่อนเปิด admin-only shadow จริง

สิ่งที่ต้องพร้อมครบก่อนจะ **ขอเปิด** admin-only shadow จริง (precondition gate):

1. **owner sign-off** — ลุงเด่นอนุมัติเป็นลายลักษณ์อักษร
2. **secret wiring plan** — Gemini API key ผ่าน Secret Manager เท่านั้น (ไม่อยู่ใน frontend / repo / env ที่ commit)
3. **budget cap / quota cap** — ตั้ง daily + monthly cap และ quota cap ก่อนเปิด
4. **kill switch verified** — `NONGA_AI_EMERGENCY_KILL_SWITCH` ตัดกลับ deterministic ได้จริง (ผ่าน drill)
5. **fallback deterministic verified** — ทุก failure path (fail/timeout/unsafe/hallucination/policy block/prompt injection) fallback deterministic
6. **admin-only boundary verified** — shadow UI เห็นเฉพาะ admin, buyer/public ไม่เห็น AI output เด็ดขาด (no buyer-facing exposure)
7. **logging / redaction verified** — log เฉพาะ sanitized scenario id / reason code / pass-fail, ไม่มี raw PII
8. **no PII/plate/VIN/phone/internal price in AI payload** — input ผ่าน sanitization, forbidden fields ไม่ถูกส่งเข้า prompt

ทุกข้อต้อง **verified = true** ก่อนจะขอเปิด shadow จริง — ถ้าข้อใดยัง not verified ⇒ ยังไม่พร้อมขอเปิด

## 6. Risk Matrix

ความเสี่ยงที่ยังเหลือ ก่อนเปิด admin-only shadow จริง (sanitized — ไม่มีค่าจริง/PII):

| # | Risk | ผลกระทบ | โอกาส (ก่อน mitigate) |
|---|---|---|---|
| R1 | **PDPA / privacy** — ข้อมูลส่วนบุคคลหลุดเข้า AI payload | สูง | ต่ำ–กลาง |
| R2 | **hallucination ภาษาไทย** — AI แต่งข้อมูลรถ / สเปก / ราคาที่ไม่มี source | สูง | กลาง |
| R3 | **prompt injection** — ผู้ใช้หลอกให้ AI แสดง PII / ทะเบียน / VIN / secret | สูง | กลาง |
| R4 | **accidental buyer-facing exposure** — AI output หลุดถึง buyer โดยไม่ตั้งใจ | สูง | ต่ำ |
| R5 | **cost / quota overrun** — shadow traffic ทำให้ cost / quota เกินงบ | กลาง | กลาง |
| R6 | **fallback failure** — เมื่อ AI fail แล้วไม่ fallback deterministic | สูง | ต่ำ |
| R7 | **lead consent bypass** — AI ข้าม consent / ส่ง lead เองโดยไม่มี user action | สูง | ต่ำ |
| R8 | **dealer / owner isolation risk** — AI เห็น/แสดงข้อมูล internal price / identity ข้าม isolation | สูง | ต่ำ |

## 7. Mitigation Plan สำหรับแต่ละความเสี่ยง

- **R1 (PDPA / privacy):** input sanitization บังคับ — forbidden input fields (phone, full license plate, VIN, full UID, secret, API key, internal price, wholesale price, raw owner/dealer private data, raw lead/contact data) ห้ามเข้า prompt; ส่งเฉพาะ public-safe / sanitized context; log เฉพาะ sanitized id
- **R2 (hallucination ภาษาไทย):** deterministic authority map — AI เป็นชั้นภาษา/น้ำเสียงบน deterministic เท่านั้น, ห้าม override inventory จริง; hallucination risk ⇒ fallback deterministic; เก็บตัวอย่าง shadow แบบ sanitized เพิ่มเพื่อประเมิน
- **R3 (prompt injection):** redaction + refusal policy (scenario S9); prompt injection ⇒ fallback deterministic; ห้ามแสดง PII / ทะเบียน / VIN / secret; เฝ้าผลใน shadow run
- **R4 (accidental buyer-facing exposure):** admin-only boundary verified ก่อนเปิด; shadow output ไม่มี write path ถึง buyer; ถ้าพบความเสี่ยง buyer จะเห็น ⇒ NO-GO ทันที
- **R5 (cost / quota overrun):** budget cap (daily + monthly) + quota cap ตั้งก่อนเปิด; kill switch ตัดเมื่อเกิน; เก็บ cost/quota baseline จาก shadow แบบจำกัด
- **R6 (fallback failure):** fallback deterministic เป็น fail-closed; ทุก failure path (fail/timeout/unsafe/hallucination/policy block/prompt injection) ⇒ deterministic; kill switch drill ต้อง pass ก่อนเปิด
- **R7 (lead consent bypass):** lead capture / phone capture / consent preview / final confirmation ยังเป็น deterministic authority; AI ไม่มีสิทธิ์ใน flow เหล่านี้; user กรอกเบอร์เอง + consent modal เท่านั้น
- **R8 (dealer / owner isolation risk):** ส่งเฉพาะ public-safe fields เข้า AI; ไม่มี identity / internal price / wholesale price; public DTO redaction คงอยู่; dealer isolation / owner isolation ไม่ถูกแตะ

## 8. Owner Approval Gates

ลำดับ gate ที่ต้องผ่านก่อนไปถึง user-visible AI (แต่ละ gate แยกอนุมัติ):

- **Gate C — admin-only dry-run approval:** อนุมัติให้รัน admin-only dry-run / shadow แบบจำกัด (ยังไม่ buyer-facing)
- **Gate D — shadow result review:** review ผล shadow (sanitized) — pass/fail, reason code, cost/quota baseline

## 10. Rollback / Stop Condition

เงื่อนไขหยุด (stop condition) ถ้ารอบอนาคตเปิด shadow แล้วมีปัญหา:

- **Stop condition:** ถ้าพบ buyer เห็น AI output, PII หลุด, prompt injection สำเร็จ, cost/quota เกิน cap, หรือ fallback ไม่ทำงาน ⇒ **สั่ง kill switch ทันที** (`NONGA_AI_EMERGENCY_KILL_SWITCH=true`) ตัดกลับ deterministic
- **Rollback (รอบ v7.8 นี้):** v7.8 เป็น docs-only ไม่มี runtime change / ไม่มี deploy ⇒ **ยังไม่มีอะไรต้อง rollback**; ถ้าต้องถอนเอกสารทำได้ด้วย git revert ระดับ docs โดยไม่กระทบ runtime / staging
- **Rollback (รอบอนาคตเมื่อเปิด shadow):** ปิด flag ⇒ ระบบกลับมาเป็น deterministic 100%; staging runtime `92d0dac` ไม่ถูกแตะจาก shadow path
- หลัง stop: review root cause แบบ sanitized ก่อนพิจารณาเปิดใหม่ — ต้องผ่าน owner sign-off อีกครั้ง
