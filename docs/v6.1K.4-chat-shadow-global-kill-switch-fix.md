## 1. Problem (v6.1K.3 Gap)

เมื่อตั้ง global Cloud Run `NONGA_AI_EMERGENCY_KILL_SWITCH=true`:

| Field | v6.1K.3 (before fix) | Expected |
|-------|----------------------|----------|
| CP-02 `providerNetwork` | `true` | `false` |
| CP-02 gate | `real_provider_call_ok` | `emergency_kill_switch` |

**Root cause:** CP-02 evaluation ใช้ `stagingStyleShadowEnv()` ที่ hardcode `NONGA_AI_EMERGENCY_KILL_SWITCH=false`; handler gate ตรวจเฉพาะ `evaluation.runtimeFlags.shadowEvaluationAllowed` จาก scenario env ไม่ได้อ่าน global kill switch จาก `process.env` / Cloud Run

---

## 2. Fix Summary

เพิ่ม `isGlobalChatShadowEmergencyKillSwitchActive(readEnv)` ใน `salesBrainChatShadowRealProvider.ts` และเรียกใน `resolveChatShadowSinkHandlerContext` **หลัง** chat real provider flag check และ **ก่อน** `invokeChatShadowRealProvider`

เมื่อ global kill active:

| Field | Value |
|-------|-------|
| `providerNetwork` | `false` |
| `realProviderGateReason` | `emergency_kill_switch` |
| `realProviderFallbackReason` | `emergency_kill_switch` |
| Gemini invocation | **none** |
| `sinkOnly` / `userVisibleOff` / `readOnly` | `true` |

Diagnostics เพิ่ม `globalEmergencyKillSwitchActive` ใน `ChatShadowSinkDiag` (redacted log only)

## 3. Gate Order (CP-02)

1. `production_environment` — if scenario env is production
2. `scenario_not_allowed_for_real_provider` — CP-01, CP-03..CP-05
3. `chat_shadow_real_provider_flag_off` — `NONGA_AI_CHAT_SHADOW_REAL_PROVIDER_ENABLED` off
4. **`emergency_kill_switch`** — **global** `NONGA_AI_EMERGENCY_KILL_SWITCH=true` (**v6.1K.4**)
5. `shadow_evaluation_not_allowed` — scenario-local guards (e.g. CP-03 kill in scenario env)
6. `real_provider_call_ok` — injected/offline provider only in tests; live Gemini on staging after deploy + flag on
