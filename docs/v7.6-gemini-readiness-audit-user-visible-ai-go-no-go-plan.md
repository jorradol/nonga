## 6. Deterministic Authority Boundaries

จุดที่ deterministic flow ต้องเป็น authority และ AI **ห้ามแทนที่**:

| Flow | Authority (deterministic) | AI บทบาทที่อนุญาต (อนาคต) |
|---|---|---|
| search intent | `buyerSearchIntentParser` + `useSearch` + inventory จริง | wording เท่านั้น ไม่เปลี่ยนผล |
| lead capture | `buyerLeadCaptureFlow.ts` state machine (no Gemini) | ไม่มี — deterministic ล้วน |
| lead escape | `buyerLeadFlowEscape.ts` (v7.5.2 search escape) | ไม่มี — deterministic ล้วน |
| preview | `conversationalLeadMemory.buildLeadPreviewContextFromMemory` (display-only) | wording เท่านั้น |
| final confirmation | consent modal + `draftToCreateInput(...)` | ไม่มี |
| payment safety | finance routing / no-guarantee guard | wording ปลอดภัยเท่านั้น |
| no-results path | deterministic safe nudge | wording เท่านั้น |

หลักการ: **AI เป็นชั้น "ภาษา/น้ำเสียง" บนผลลัพธ์ deterministic เท่านั้น — ไม่ใช่ผู้ตัดสินใจ flow และไม่ใช่ source of truth**

- `createdLeadId` เกิดได้เฉพาะหลัง user confirmation ผ่าน deterministic path (`draftToCreateInput` ต้องมี `consentConfirmed`)
- ฟังก์ชัน lead flow ทั้งหมด comment กำกับว่า "deterministic, no Gemini"

## 8. PII / PDPA / Privacy Guardrails

- **Forbidden prompt fields** (`AI_CONTROL_FORBIDDEN_PROMPT_FIELDS`): `licensePlate`, `phone`, `line`, `fullUid`, `wholesaleInternalPrice`, `secretEnvValues`, `rawImageUrl`, `privateAdminNotes`, `rawPromptDumpWithPii`
- **Allowed prompt fields** (public-safe): `brand`, `model`, `year`, `bodyType`, `fuelType`, `price`, `mileage`, `sanitizedPublicDescription`, `normalizedPublicFeatures`
- **Log redaction:** `redactPiiForAiLog` / `redactPiiForSalesBrainLog` ลบเบอร์โทร/อีเมล; error/output sample ลบ API key (`AIza...`) และ `Bearer` token ก่อน log
- **Interest memory PDPA guard:** `conversationalLeadMemoryHasNoContactOrConsent` — memory ห้ามมี contactPhone/phone/displayName/name/consent/plate/queue/interestCount
- **Frontend secret guard:** `assertNoFrontendApiKeyLeak` บล็อก `GEMINI_API_KEY` / `AIzaSy...` ใน frontend source
- AI **ห้ามเปิดเผย PII / ทะเบียนเต็ม / VIN** ทุกกรณี

## 9. Lead Flow Guardrails

- phone ต้องให้ลูกค้ากรอกเอง — AI/memory ห้ามเดาหรือเติม (`updateBuyerLeadDraftPhone` รับจาก user เท่านั้น)
- preview ก่อนส่ง lead (display-only summary จาก interest memory)
- final confirmation ก่อนส่ง lead (consent modal)
- consent ห้ามสร้างเอง — `consentConfirmed` + `BUYER_LEAD_CONSENT_VERSION` มาจาก user action
- `createdLeadId` ต้องเกิดหลัง user confirmation เท่านั้น
- AI **ห้ามส่ง lead / สร้าง consent / เดา phone / สร้าง createdLeadId**
- lead escape (v7.5.2): เมื่อ buyer พิมพ์ search intent ใหม่ระหว่าง lead capture ⇒ pause draft, ไม่ถาม lead prompt ซ้ำ, ไม่ส่ง lead

## 10. Dealer / Owner Isolation Guardrails

- prompt ที่ส่งให้ AI ใช้เฉพาะ public-safe listing fields — ไม่มี dealer/owner identity, ไม่มี internal price
- `wholesaleInternalPrice` / `privateAdminNotes` เป็น forbidden prompt fields
- buyer queue: buyer เห็นเฉพาะ row ของตัวเอง (`filterBuyerVisibleQueueFields`), `publicQueuePayloadHasNoOtherBuyerPii` กัน PII ผู้สนใจรายอื่น
- v7.6 **ไม่แตะ** dealer isolation / owner isolation / data model
- AI ห้ามเปิดเผย dealer/owner identity

## 11. Inventory-Grounding Rules

- AI **ห้ามเป็น source of truth แทน inventory จริง**
- คำตอบต้อง ground จาก listing context ที่ระบบส่งให้เท่านั้น ("จากข้อมูลในประกาศนี้")
- ถ้า listing ไม่มีข้อมูล ⇒ ต้องบอก "ยังไม่มีข้อมูลนี้ในระบบ" ห้ามเดา
- ข้อมูลที่ AI **ห้ามแต่งเอง**: ราคา / รุ่น / ปี / เลขไมล์ / สภาพรถ / ไฟแนนซ์ / โปรโมชั่น / availability / dealer-owner identity / ทะเบียนเต็ม / VIN / PII
- ความรู้ทั่วไปของรุ่นรถใส่ได้เฉพาะพร้อม disclaimer ว่า "ไม่ใช่การยืนยันสภาพของรถคันนี้โดยตรง"
- EV: ห้ามเดา kWh / ระยะวิ่ง / ค่าชาร์จ / ประกันแบต ถ้า listing ไม่มี (`hasUnsourcedEvSpeculation` guard)

## 12. Thai Tone / Naturalness Policy

- ตอบภาษาไทยเป็นหลัก สุภาพ อบอุ่น (persona "น้องเอ")
- เรียก "คุณลูกค้า" หรือไม่เรียกขาน — **ห้ามเดา** ลุง/ป้า/เฮีย/เจ๊/พี่/น้อง (`hasGuessedCustomerAddressTerm`)
- ห้ามใช้คำ brand voice ต้องห้าม (เช่น "ปังปุริเย่")
- ชื่อยี่ห้อ/รุ่น/เทคนิคเป็นภาษาอังกฤษได้ (allowlist) แต่ห้ามตอบเป็นอังกฤษล้วน (`hasExcessiveNonThaiContent`)
- คำตอบต้องเป็นประโยคไทยสมบูรณ์ จบด้วย ครับ/ค่ะ (`looksLikeIncompleteSentence` guard)

## 13. Safety / Finance / Legal Disclaimer Policy

- ไฟแนนซ์: ห้ามคำการันตี เช่น "อนุมัติแน่นอน" / "ผ่อนได้แน่นอน" / "ผ่านชัวร์" / "การันตี" — ใช้ "ประเมินเบื้องต้น" / "ขึ้นอยู่กับเงื่อนไขไฟแนนซ์" / "ทีมงานช่วยประสาน"
- output guard: `assertNoFinanceGuaranteeLanguage` ⇒ fail ⇒ fallback deterministic
- ห้ามอ้างเครดิตบูโร / blacklist เป็นเงื่อนไข (credit risk label patterns)
- ห้ามใช้ภาษาค่าคอมมิชชั่นกับ buyer
- ต้องไม่ทำให้ผู้ใช้เข้าใจผิดว่าเป็นการรับประกันสภาพรถหรือการอนุมัติไฟแนนซ์

## 14. Failure / Fallback Behavior

fallback plan ถ้า Gemini fail / timeout / blocked / ตอบผิด / hallucination:

1. output safety evaluation (empty, json leak, finance guarantee, meta leak, EV speculation, address term, brand voice, non-thai, pipe echo, too short, incomplete sentence)
2. ถ้า unsafe และอยู่ใน retry set ⇒ retry 1 ครั้งพร้อม repair note
3. ถ้ายัง unsafe / error / timeout ⇒ **fallback deterministic (mock/legacy)** + log redacted diagnostics
4. kill switch / production / flag off ⇒ ไม่เรียก Gemini เลย ใช้ deterministic
5. ทุก fallback ต้อง **ไม่กระทบ** lead flow / consent / phone

หลักการ: **fail-closed** — เมื่อไม่แน่ใจให้ตกกลับ deterministic เสมอ

## 15. Logging and Evidence Policy Without PII

- log เป็น redacted diagnostics เท่านั้น: gateReason, scenario, outputLength, finishReason, token counts, unsafeReason, sliceId
- ห้าม log: เบอร์โทร, ชื่อ, raw UID, raw prompt, API key, ทะเบียน, VIN
- error log ผ่าน `redactUserVisibleRealProviderError` (ลบ key/Bearer/PII)
- masked UID เท่านั้นในเอกสาร evidence (เช่นรูปแบบ `Xxxx...xx`)
- evidence ต้องเก็บแบบ sanitized ตาม pattern รอบก่อน (v6.8D.2, v7.5.2B)

## 16. Staged Rollout Proposal

แต่ละ phase มี rollback + kill switch:

| Phase | ชื่อ | ขอบเขต | trigger เปิด | rollback / kill switch |
|---|---|---|---|---|
| **Phase 0** | doc-only readiness | เอกสาร + static validation (รอบนี้) | — | revert doc (ไม่มี runtime) |
| **Phase 1** | admin-only shadow | shadow real Gemini เฉพาะ admin, ไม่ user-visible | owner approve + secret wired | `EMERGENCY_KILL_SWITCH=true` / flag off |
| **Phase 2** | allowlisted internal visible | user-visible เฉพาะ UID ภายในใน allowlist (staging) | Phase 1 ผ่าน + go/no-go | flag off + ลบ allowlist |
| **Phase 3** | limited dealer/buyer test | allowlist ขยายเป็น pilot ดีลเลอร์/ผู้ซื้อจำนวนจำกัด | Phase 2 ผ่าน + owner approve | flag off + kill switch |
| **Phase 4** | broader staging pilot | ขยาย staging pilot กว้างขึ้น (ยังไม่ production) | Phase 3 ผ่าน + cost review | flag off + kill switch |

- ทุก phase: production ยังบังคับ off จนกว่าจะมี production go/no-go แยกต่างหาก
- ทุก phase: budget caps ต้องตั้งก่อนเปิด

## 18. Rollback / Kill Switch Checklist

ลำดับ rollback (เร็วสุด → ลึกสุด):

1. `NONGA_AI_EMERGENCY_KILL_SWITCH=true` ⇒ ปิด AI ทั้งหมดทันที (offFlags)
2. `NONGA_AI_USER_VISIBLE_REAL_PROVIDER_ENABLED=false` ⇒ ปิด real Gemini บน user-visible
3. `NONGA_AI_USER_VISIBLE_ENABLED=false` ⇒ ปิด user-visible path (กลับ legacy)
4. ลบ `NONGA_AI_USER_VISIBLE_ALLOWLIST_UIDS` ⇒ deny ทั้งหมด
5. `NONGA_AI_PROVIDER=none` / `NONGA_AI_MODE=off` ⇒ ตัด provider
6. redeploy revision ก่อนหน้า (image-only) ถ้าจำเป็น

- ทุก rollback **ไม่กระทบ** lead data / consent / phone
- production ไม่ต้อง rollback เพราะ production ไม่ถูกเปิด
- ต้องบันทึก revision timeline แบบ sanitized

## 19. Known Blockers / Open Risks

- **B1:** ยังไม่มี owner sign-off สำหรับเปิด Gemini จริง — **blocker**
- **B2:** secret wiring (Gemini API key ผ่าน Secret Manager) ยังไม่ยืนยันสำหรับ rollout จริงรอบนี้
- **B3:** budget caps ยังไม่ตั้งค่าจริงใน staging runtime
- **B4:** output safety guards ส่วนใหญ่ทดสอบแบบ offline — ยังต้อง staging smoke จริง (Phase 1+) ก่อนวางใจ
- **B5:** cost monitoring / quota dashboard สำหรับ user-visible ยังไม่มี real-traffic baseline
- **O1 (open risk):** hallucination เชิงคุณภาพในภาษาไทยยังต้องเก็บตัวอย่างจริงเพิ่ม
- **O2 (open risk):** prompt injection จาก user message — มี redaction แต่ต้องเฝ้าใน pilot
- v7.6 **ไม่ปิด** blocker เหล่านี้ — เป็นเพียงการ record เพื่อ go/no-go รอบถัดไป
