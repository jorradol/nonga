## 3) Root cause — duplicate creation

`processSmartInventoryImport` always minted new IDs (`car-import-{timestamp}-p{n}`) and called `createListing` / `bulkAddMarketplaceCars` only. Duplicate detection was **advisory** (`possible_duplicate` warnings) and never upserted. Re-import therefore prepended new rows for the same Thor cars.

## 4) Root cause — latest images not showing

1. New duplicate listings got **new** listing IDs, so image downloads (if any) were stored under the new id — not linked to the original 3 Thor rows.
2. When remote download/upload failed (or resolved to Unsplash placeholder), `resolveStoredImagesForListing` wrote `LISTING_PLACEHOLDER_IMAGE`.
3. Frontend `isValidListingImageUrl` / gallery helpers **reject Unsplash legacy placeholders as “real” listing images** for display purposes in some paths, and ephemeral `/storage/listings/{newId}/...` 404 on Cloud Run when file-backend paths leak through.
4. There was **no** blank-safe merge: failed image resolution could leave only placeholders on the new duplicate, while originals kept old (possibly 404) `/storage/listings/...` URLs.

Net: duplicates appeared without usable marketplace images; originals were not updated with durable Firebase URLs.

## 5) Upsert / dedup key and confidence rule

Implemented in `src/server/listingImportIdentity.ts`, wired in `inventoryImportCommit.ts`.

| Precedence | Key | Confidence | Action |
|------------|-----|------------|--------|
| 1 | dealer scope + full plate (+ province when both present) | high (exact, unique) | update existing |
| 2 | dealer scope + VIN exact | high (exact, unique) | update existing |
| 3 | dealer scope + brand/model/year/color/mileage/price fingerprint | high only if **unique** | update existing |
| — | multiple exact hits OR soft brand/model/year overlap without unique key | **ambiguous** | NEED REVIEW — do **not** create |
| — | no match | none | create new |

Rules:

- Masked plate alone (`*`, short tokens) is **not** a sole key.
- Never guess (“มั่วคัน”).
- Opaque `importKey` hash stored on listing; redacted from public DTO.
- Merge: only overwrite fields that are explicitly present/valid; blank/null does not erase good data.
- Images: on failed download/upload, preserve existing working URLs + warning; on success, rewrite onto the **stable** listing id (Firebase Storage when backend is `firebase-storage`).
