## 7. Confirmation: lead capture search escape ทำงานจริงบน UI

**ยืนยัน** — บน staging UI จริง เมื่อผู้ใช้อยู่ใน lead capture flow แล้วพิมพ์ "ช่วยหารถที่ราคาถูกกว่า 400,000 มานำเสนอเพิ่มให้ด้วยครับ" ระบบ detect เป็น search intent ใหม่ พัก lead draft เดิม และกลับไปค้นหารถต่อ **โดยไม่ถาม lead prompt ซ้ำ** — ตรงกับพฤติกรรมที่ออกแบบใน v7.5.2 และยืนยันว่าปัญหา loop เดิมถูกแก้แล้วใน UX จริง

---

## 8. Confirmation: ไม่ส่ง lead / ไม่สร้าง consent / phone / createdLeadId เอง

**ยืนยัน** — ระหว่าง escape ไป search intent ใหม่:
- **ไม่ส่ง lead** เองโดยอัตโนมัติ
- **ไม่สร้าง consent** จาก search intent หรือ memory
- **ไม่เก็บ/เดา/เติม phone** ของลูกค้า
- **ไม่สร้าง createdLeadId**

การส่ง lead จริงยังต้องผ่าน preview + กรอกเบอร์เอง + final confirmation ตาม flow เดิม (ไม่ถูกแก้ใน v7.5.2)

---

## 9. Confirmation: no buyer-facing queue count ยังไม่หลุด

**ยืนยัน** — ตลอด flow ที่ลุงเด่นทดลอง (รวมข้อความ escape) **ไม่มีการแสดงตัวเลขลำดับคิว / queue count ให้ฝั่งผู้ซื้อเห็น** สอดคล้องกับนโยบาย no buyer-facing queue count ตั้งแต่ v7.3

---

## 10. Confirmation: Gemini / user-visible AI / public signup / real lead sending ยังปิด

**ยืนยัน — ปิดทั้งหมด:**
- **Gemini จริง:** ปิด
- **user-visible AI จริง:** ปิด (flow เป็น deterministic ทั้งหมด)
- **public signup:** ปิด (staging build บังคับ `VITE_NONGA_PUBLIC_SIGNUP_ENABLED=false`)

manual smoke รอบนี้ไม่ได้เปิด feature ต้องห้ามใด ๆ และไม่มีการใช้ข้อมูลลูกค้าจริง/เบอร์จริงในการทดสอบ
