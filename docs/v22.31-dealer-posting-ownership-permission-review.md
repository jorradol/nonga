## 4) Listing ownership binding

### 4.1 Stored identity fields

| Field | Role |
|-------|------|
| `dealerId` | Tent / dealer partition (inventory scope, ACL, image paths) |
| `ownerId` | Listing owner key; **copied to lead `sellerId`** at create |
| `ownerName` / `ownerPhone` / `showroomName` | Contact / showroom metadata (phone redacted on public DTO) |

There is no separate listing `sellerId`; leads use `ownerId` as `sellerId`.

### 4.2 How dealer create binds identity

| Step | Behavior |
|------|----------|
| Draft create | Server sets `dealerId: ctx.dealerId` (not client-chosen) |
| Draft publish | `dealerId` from draft; `ownerId: owner-${normalizeDealerId(draft.dealerId)}` |
| Repository create/update | Forces / preserves `dealerId` + `ownerId` (patch cannot rebind) |
| Dealer import commit | `ownerId: owner-${ctx.dealerId}`, `dealerId: ctx.dealerId` |

Client cannot override owner/dealer on dealer routes. Updates keep `existing.dealerId` / `existing.ownerId`.

### 4.3 Thor Auto binding (live staging)

| Observation | Value |
|-------------|-------|
| Count | **3** |
| `dealerId` | **`thor-auto`** (all three) |
| `ownerId` | Shared Firebase-style uid across the three (import-era binding; not the `owner-thor-auto` portal convention) |
| Lead recipient if capture were ON | That listing’s `ownerId` |
| Queue manage ACL | Dealer with `dealerId: thor-auto` **or** matching `ownerId` (or admin) |

Canonical **portal publish** uses `owner-{dealerId}`. **Staging Thor imports** used a Firebase uid as `ownerId` while keeping `dealerId: thor-auto`. Both are consistent *within* their path; ACL still works via `dealerId`. Owner should treat the dual convention as a **review item** before any controlled dealer posting test that mixes import + portal publish.

### 4.4 Override / missing binding

| Case | Behavior |
|------|----------|
| Buyer overrides recipient | **Impossible** — no API field; server derives from listing |
| Empty `ownerId` | Lead create **400** — seller not found |
| Wrong but non-empty `ownerId` | Lead would route to that id — correctness depends on publish/import |
| Unbound listing published? | Dealer publish path always writes `ownerId`; empty owner cannot accept leads |
| Lead/contact UI while kill switch OFF | Chat CTA may still appear; modal submit disabled; server create **403** |

## 5) Dealer permissions and isolation

### 5.1 Create / edit / view

| Actor | Own listings | Other dealer’s listings |
|-------|--------------|-------------------------|
| Dealer (active + `dealerId`) | Create / edit / view / publish within scope | **Blocked** (`carBelongsToDealer` / `draftBelongsToDealer` → 403/404) |
| Member | Own member listings (hidden-by-default path) | No dealer portal |
| Admin / superadmin | All (admin bypass); dealer APIs need explicit dealer scope when acting as tent | Yes |
| Guest | None | None |

Inventory dashboard and `GET /api/dealer/inventory` are filtered to `ctx.dealerId` only.

### 5.2 Image storage isolation

Path pattern: `{listing-images\|draft-images}/{dealerId}/{listingId}/{fileName}`  
Uploads pass authenticated `dealerId` and ownership checks before write.

### 5.3 Public vs private fields

**Public marketplace DTO** (`toPublicMarketplaceCarDto`):

| Shown (examples) | Hidden / stripped |
|------------------|-------------------|
| Brand, model, year, price, mileage, fuel, condition, images | `ownerPhone`, emails, LINE, contact phones |
| Title, sanitized description | `vin`, full `licensePlate` / `licensePlateFull` / plate / registration |
| `licensePlateMasked` (when available) | Wholesale / internal price fields |
| `ownerName`, `showroomName` | Seller consent / moderation / duplicate internals |
| **`ownerId`, `dealerId`** (partition ids) | Buyer contact fields if present on record |

Live staging sample confirmed: no VIN, no full plate, no owner phone; `ownerId` + `dealerId` present; masked plate may be present.

**Policy reminder (v22.18):** seller-provided vehicle images may display under publish-rights + listing-use consent; no manual blur/crop required. System-controlled text/DTO must still not expose full plate / VIN / phone / address.

## 7) Owner-readable posting flow preview

**TEST / OWNER APPROVAL ONLY — design preview, not a live post.**

```text
1. Dealer logs in (invite/pilot account; public signup OFF)
2. Opens Dealer Portal or Sell wizard (RequireDealer)
3. Creates draft → server binds dealerId from auth
4. Fills required car fields (publish guard):
   - brand, model, year, price, mileage
   - publishable vehicle images (+ image-set / vehicle-image checks)
5. Image consent policy: seller-provided photos may show as submitted
   when publish rights + listing-use consent apply (no mandatory blur/crop)
6. Dealer publishes draft → marketplace car with:
   - dealerId = authenticated dealer
   - ownerId = owner-{dealerId}   [portal path]
   - listingStatus = published    [no separate owner approval gate today]
7. Public surfaces show car fields + images; hide phone/VIN/full plate
8. Future lead (only if kill switch later ON):
   - buyer picks listing → sellerId = listing.ownerId
   - contact locked until seller/admin manual reveal
   - no auto dealer notification
9. While kill switch OFF: create blocked (403 auth / 401 unauth); UI submit disabled
```
