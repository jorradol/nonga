## 4. Gate B Evidence Checklist (Secret / Access Readiness)

หลักฐานที่ต้องมีครบก่อนพิจารณา Gate B:

- [ ] **secret wiring readiness** — มีแผน wiring ที่ชัดเจน (concept only) โดยไม่เปิด secret จริง
- [ ] **no real secret in repo** — ยืนยันว่าไม่มี secret/API key จริงใน repo, docs, script, commit message
- [ ] **secret storage อยู่่นอก repo** — ระบุที่เก็บเป็น Secret Manager/secure vault เท่านั้น
- [ ] **access boundary proof** — จำกัดสิทธิ์อ่าน secret เฉพาะ runtime/service account ที่อนุญาต
- [ ] **verification method (ไม่เปิดเผย secret)** — มีวิธีพิสูจน์ว่า wiring สำเร็จโดยไม่ print ค่า secret
- [ ] **failure/rollback condition** — ถ้า wiring ล้มเหลว ต้อง fail-closed และ rollback สู่ deterministic ได้ทันที

## 5. Gate C Evidence Checklist (Admin-only Shadow Readiness)

หลักฐานที่ต้องมีครบก่อนพิจารณา Gate C:

- [ ] **admin-only dry-run readiness** — ขั้นตอน dry-run ชัดเจน พร้อม role/สิทธิ์ reviewer
- [ ] **admin-only boundary proof** — พิสูจน์ว่า shadow output อยู่หลัง admin auth เท่านั้น
- [ ] **no buyer-facing exposure proof** — ไม่มี path ไป buyer/public ทั้ง route, API, render
- [ ] **deterministic remains source of truth** — AI เป็น layer เสริมภาษา ไม่ override deterministic authority
- [ ] **shadow output visible only to admin/reviewer** — ผู้เห็นผล shadow ต้องถูกจำกัดกลุ่มอย่างชัดเจน

## 6. Budget / Quota Evidence Checklist

หลักฐานด้านต้นทุน/โควต้าที่ต้องเห็นก่อน activation ในอนาคต:

- [ ] **daily cap** — เพดานรายวันพร้อมหลักฐานการตั้งค่า
- [ ] **per-run cap** — เพดานต่อรัน/ต่อคำขอพร้อมหลักฐาน
- [ ] **timeout cap** — เพดานเวลาและ behavior เมื่อ timeout
- [ ] **emergency stop** — กลไกหยุดฉุกเฉินที่ตัด AI path กลับ deterministic
- [ ] **cost/quota baseline** — baseline ค่าใช้จ่าย/โควต้าที่ใช้เทียบผิดปกติ
- [ ] **owner-approved spending limit** — ต้องมีวงเงินที่ owner อนุมัติไว้ก่อน activation

## 7. Kill Switch Evidence Checklist

หลักฐาน kill switch ที่ลุงเด่นต้องเห็น:

- [ ] **switch name/config concept** — ระบุชื่อสวิตช์เชิงแนวคิด (ไม่ใส่ค่า secret จริง)
- [ ] **verification steps** — ขั้นตอนทดสอบเปิด/ปิด switch และผลที่คาดหวัง
- [ ] **expected evidence** — หลักฐานที่ต้องเก็บ (timestamp, scenario, before/after behavior แบบ sanitized)
- [ ] **stop condition if switch fails** — ถ้าสั่ง switch แล้วไม่ตัด AI path ต้องหยุดทันทีและขึ้น NO-GO

## 15. Stop / Rollback Conditions (สำหรับรอบอนาคต)

- **Stop condition:** ถ้าพบ buyer/public เห็น shadow output, พบ PII leakage, พบ policy bypass, budget เกิน cap, หรือ kill switch ใช้งานไม่ได้ ให้หยุดทันที
- **Rollback condition:** ปิด AI path ทั้งหมดกลับ deterministic, ยืนยัน no buyer-facing exposure, เก็บ incident evidence แบบ sanitized ก่อนพิจารณาใหม่
- **Re-open condition:** เปิดใหม่ได้ต่อเมื่อ root cause ถูกแก้ครบและ owner ลงนามอนุมัติรอบใหม่
