# v5.6H.1 — Cancel Pending Sale / Relist Safety

**สถานะ:** Implementation ready for review — **ยังไม่ commit/deploy**  
**อ้างอิง:** [v5.6H](./v5.6H-deal-outcome-pending-sale-flow.md)

## ใช้เมื่อไหร่

- กด outcome “ปิดการขายได้” ผิด
- ดีลล่ม / ผู้ซื้อถอนตัว แต่ยังไม่ปิดการขายจริง
- ต้องการให้รถกลับเข้าตลาดโดยไม่ลบประกาศ

## สิ่งที่ทำในรอบนี้

| รายการ | พฤติกรรม |
|--------|----------|
| API | `POST /api/my/listings/:id/cancel-pending-sale` (owner/admin ผ่าน `canManageListingWithScope`) |
| Policy | เฉพาะ `saleStatus === pending_sale` |
| หลังยกเลิก | `saleStatus → sale_cancelled`, `saleCancelledAt` (+ optional `saleCancelReason`) |
| Publish | `listingStatus → published` ถ้า publish guard ผ่าน; ไม่ผ่าน → คง `hidden` + HTTP 422 |
| Audit | **เก็บ** `pendingSaleAt` (ไม่ลบ) |
| Marketplace | รถกลับเข้า `getPublishedMarketplaceCars` / chat search เมื่อ published |
| My Listings | ปุ่ม “ยกเลิกดีล / กลับไปขายต่อ” + confirm |

## สิ่งที่ยังไม่ทำ

| รายการ | หมายเหตุ |
|--------|---------|
| Payment / settlement | ❌ |
| Revive buyer queue อัตโนมัติ | ❌ คิวที่ superseded ยังไม่กลับ |
| Push notification ผู้ซื้อ | ❌ มีแค่ foundation copy ใน `listingSaleCopy.ts` |
| ลบ / แก้ lead `closed_won` | ❌ เก็บ audit |
| เปิดเบอร์คิวใหม่ | ❌ |

## Queue / lead

- Lead ที่ `closed_won` **ไม่ถูกลบ**
- ไม่ revive `queueLifecycle: superseded` ในรอบนี้
- งานถัดไป: แจ้งผู้ซื้อรายอื่น + revive queue ตามนโยบายแยก
