หลัก PDPA/lead เดิมครบ ต่อยอดจาก v7.1 (ไม่ทำให้ flow แข็งอีก)

user-visible AI จริง, ไม่ส่ง lead เอง, ไม่แตะ data model/security/privacy/lead revenue/

## ขอบเขตที่ได้รับอนุมัติจากลุงเด่น

- Phase A: core module + tests (ไม่แตะ flow)
- Phase B: wiring แบบ **record-only** ใน `useChat.ts` (จำเฉย ๆ ไม่เปลี่ยนพฤติกรรมตอบ/ส่ง)
- ที่เก็บ: **in-memory Map ต่อ session** (เหมือน `buyerLeadCaptureFlow`)
- ไม่รวม: feed memory เข้า search (เปลี่ยนพฤติกรรม search) → กันไว้ขออนุมัติแยกใน v7.3

## การแยกชั้นข้อมูล (แยกชัดเจน)

| ชั้น | ที่อยู่ | ส่ง lead? |
|---|---|---|
| **interest memory** (v7.2) | `conversationalLeadMemory.ts` | ไม่ — ความสนใจเท่านั้น |
| **personal contact data** | `buyerLeadCaptureFlow.ts` (contactPhone/displayName) | ต้องลูกค้ากรอกเอง |
| **consent / confirmation** | `buyerLeadValidation.ts` (consentConfirmed) | ต้องยืนยันเอง |
| **submitted lead** | `buyerLeadApi` / queue | หลัง consent เท่านั้น |

interest memory **ไม่เก็บ** เบอร์/ชื่อ/consent/ทะเบียน/จำนวนคิว เด็ดขาด — มี guard
`conversationalLeadMemoryHasNoContactOrConsent()` ตรวจ
